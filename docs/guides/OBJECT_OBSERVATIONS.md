## 身份与时间

园区沿用物理站点 `site_id`。公司使用已登记法人ID；产品由厂商、确切型号、版本确定；统计由发布者、系列、地区、定义确定；报价由卖方、完整配置、市场、币种及计价条件确定。未能唯一匹配的资料保留在线索层，不能靠同名或同城并入对象。

每条观测分别保存有效时间 `effective_at`、来源披露时间 `source.published_at`、首次有记录接收时间 `source.first_received_at`、实际审核时间 `reviewed_at`、正式写入时间 `recorded_at`。未知留空，年/月精度保留，不拿下载日期代替信息日期。当前值只在有效时间可确定先后时选择；未知、预测及未来值单列，同口径冲突并列。原生区间不取中点；修订/撤回保留旧版本和明确替代链。

## 本地操作

运行数据放在现有资料根，不将原件或SQLite提交到Git。

1. 针对归档JSON/XLSX制定选择器计划：原件SHA、唯一对象、字段JSON Pointer、口径和已知时间。运行 `python3 manage.py object-extract --plan PLAN.json --data DATA_ROOT --output CANDIDATES.json`。提取使用Python标准库，无模型调用，不产生采用。
2. 对JSON、XLSX或已定位的原生HTML/PDF页运行 `python3 manage.py object-review prepare --input CANDIDATES.json --data DATA_ROOT --output PROPOSAL.json`。入口重核真实原件、定位、相关上下文及首次接收记录，冻结审核版本。
3. 实际审核者检查主体、值、表头/脚注、单位、工况、时间和冲突，填写现行C3记录；允许公开的字段同时明确 `public_fields_reviewed=true`。普通新增批次不重复要求所有者确认；替代旧结论和放宽受限分发仍遵守01。
4. `python3 manage.py object-review apply --input PROPOSAL.json --data DATA_ROOT` 在锁内复验原件和冻结版本、CAS追加 `data/object_observations.json`。完全相同的提案重放不重复计数、不刷新接收/写入时间。
5. 通过严格校验、registry、治理与相应测试后按原单一发布队列部署，核正式镜像内数据与公网实际返回。

没有模型需求也可完成上述步骤；它们不会自动把目标标为delivered、关闭问题或验证模型参数。

## 网页与API的同一公开范围

`GET /api/observations?limit=50&offset=0` 返回经审核的公开研究投影，支持 `object`、`type`、`company` 筛选。每页最多100条，`next_offset` 为后续页；`type` 可为 company/product/statistic/quote。首页同样消费 `public_records`，仅限制摘要数量，不另设内容权限。

公开范围包括唯一对象、数值/区间、单位、性质、条件、信息/披露/核实时间、来源链接、冲突和修订。原件引文、上下文SHA、接收审计、审核委托及本机路径不直接序列化；私有记录也不计入公开总数。原始账本路径不匿名开放。付费会员不是现有内部 `member`，本批没有支付或会员权益服务，不能以付费名义取得后台权限。

## 首批真实采用范围

Spark归档实际核验13份原件，采用81条：68条产品规格、3条公司与产品关系、10条EIA工业电价统计，共18个对象。提取模型调用0，语义审核为本会话实际具名审核；全年/月累计均价不当作数据中心报价，厂商额定规格不当作园区实测。

7条继续保留待核：Delta 33kW BBU六项既有映射值没有在所选归档原生正文找到；Vertiv Li7一项能量字段的原标签与解释不一致。真实报价采用0。没有因此增加全文阅读数或已验证模型输入数；171项未接通来源和17个未验证模型输入不被本批改状态关闭。实际部署状态以本批交接及私有运行回执为准。


归档HTML若将规格内联保存在iframe[srcdoc]，可用`html:srcdoc:N`（从1开始，仅计带srcdoc的iframe）定位相关片段。标准库解析属性转义及内层文本，不执行JavaScript、不访问外部iframe；大小/定位/空白内容拒绝。原始HTML字节SHA和选定文本上下文SHA同时冻结，逐条引文须存在于所选片段。普通正文及PDF继续用原页定位；这不是全文阅读完成，也不授予模型支持。表格列、额定条件、脚注及公开资格仍须具名审核。


## 原生表格字段接入

原生XLSX逐条采用：xlsx:sheet:N:cell:C2:context:A1:E3精确定位，冻结表名、原始单元格/类型、日期系统、合并表头与脚注上下文；不执行公式/宏、不访问外链，选中公式缓存或错误值拒绝。提取保留原始值，数字等值复验不改单位或拆分组合型号；具名C3、来源身份、首次接收、CAS、无写重放和公开字段清单保持。此能力不证明三份HBM汇总已核实或采用。

`object-extract` 的 XLSX 计划使用 `fields[].locator`（JSON 仍使用 `pointer`）。例如 `xlsx:sheet:1:cell:C2:context:A1:E3`：工作表按原件次序从1开始，C2为值，A1:E3为本次审核矩形。范围须包含字段、相关表头/单位和脚注；合并表头不得被切断。最多4096格，归档字节20MB、解压总量50MB，超限选择更小资料或保留线索。日期序列号不自动解释为披露/观测时间。固定提取只生成候选，范围、预测假设、来源发行者与唯一对象仍逐条审核；缺少真实出处的二手表不靠文件名补造来源。

## 有导入台账的归档资料

归档资料的对象优先接入（2026-10-12）：公司、产品、统计和报价的逐条观测可使用真实catalog导入来源，不强制先有HTTPS网页或特定采集sidecar。审核入口重新核原件SHA、documents身份及sources实际记录；首次接收取真实导入时间，冻结来源记录ID、路径摘要和接收时间。路径/个人资料留在运行库，Git只留摘要。网页URL未知保持null，不补造链接；公开仍需具名审核明确允许字段分发，购买原件不自动公开。原件/导入记录变化须重新审核，缺项、估算、未知时间不阻挡明确对象的初始信息。入库不等待全文阅读或模型用途；这不自动完成新园区创建、全文阅读、模型验证或受限分发授权。

原生表格操作流程保持；不必重新下载或给已有文件伪造网页来源。首页/API仍共用公开字段，归档记录source.url为null，首页点击打开同一公开观测的口径和时间。原件路径、导入记录和引文不进入公开投影。CI完整JSON比较允许真实归档来源形状的纯追加；首次程序/规则更改全套验收。

## 园区普通信息快速登记（现行，2026-10-12）

使用 `python3 manage.py source-statements --data <原件运行目录> --input <私有JSONL或JSON数组> --receipt <私有回执.json>`。每条包含version=1、唯一site_id、fields、source.sha256；published_at/effective_at未知可空，basis为来源陈述说明。首次对象加identity（沿物理身份结构，不能把同城其他园区混入）。known字段含规划/投运/设施功率、角色与可选水电指标。单条失败保存held_statements供后补，不阻断其他条目；重放不改首次登记时间。

不要求C3、全文阅读、研究目标、网页URL或专用采集凭证；原件来自实际接收目录，字段值不做真假判断。结果registered_in_checkout只是已登记到该源码副本，仍需单一发布队列和网站实际回执才能计上线。公开状态为基础登记待查，verified_date不伪造；当前展示按01的时间顺序，旧版本保留。`object-review`用于主动做研究核验，不能再次作为普通园区登记的前置门槛。
