# 四队采集员工任务包

版本：2026-10-11 · 负责人可直接分发本目录。现行研究规则以 [06 采集规范](../../../framework/06_acquisition.md) 为准；本任务包规定员工交付，不授予正式研究采用权限。

## 要做成什么

持续把公开资料和已有 Spark 资料变成**有原件、有定位、带时间、可追加的逐条信息**。先识别对象，再提取信息；不知道研究模型用途，也可以交付。缺地址、缺指标、没有全文阅读结果都不阻止交付已找到的内容。对象不确定则交线索，不猜一个园区写进去。

四队是四个岗位，先放在一个 `fetchdata` 仓库、四个目录。下载、哈希、打包、运行台账共用，来源适配和定时任务独立。不要每人复制一套内核，也不要把四队任务重新做成四个网站。当前仓库仍待建设、四队未接通；本任务包和离线验包工具不代表接收服务已上线。

## 给谁哪份文件

所有人先读 [共同交付规范](delivery-contract.md)，再读自己的任务书。

| 员工 | 任务书 | 回答的问题 | 第一批范围（工作目标，不能编数凑量） |
|---|---|---|---|
| A | [fetchstat：统计、费率和规则](fetchstat-statistics.md) | 某地区某时期的电价、工资、税费等外部条件是多少？ | 2 个来源、5 条序列，每条最近 12 个已发布期间 |
| B | [fetchfilings：公司披露](fetchfilings-company-disclosures.md) | 哪个法律主体披露了什么经营、资产、债务及项目信息？ | 4 家公司，每家最新年度及最新季度，提取可定位条目 |
| C | [fetchreports：研究资料](fetchreports-research-publications.md) | 研究/标准给了什么测量、估算、方法和假设？ | 3 家机构、5 份资料，至少 10 条有定位的信息 |
| D | [fetchquotes：报价](fetchquotes-market-prices.md) | 某配置、地区、时点的公开报价和限制是什么？ | 2 个供应商、2 个地区，至少 10 个有效报价样本 |

人数不足时先 A/B，再 C/D；四人齐备可以同步做。B 兼任首周公共内核及接口负责人，A/C/D 提适配需求；这项职责可由负责人转给更适合的工程师，但必须只指定一人。所有员工只改自己的队目录，共用内核通过接口负责人合并。

## 第一天直接开始

1. 把本任务包复制到新建 `fetchdata` 仓库；源码目录按 [开发与验收](implementation-and-acceptance.md)。每人建 `codex/<team>-bootstrap` 分支或本组织统一的分支名。
2. 接口负责人交来源登记、下载/本地复用、哈希、包构建和台账最小实现；其余员工先登记任务书里的首批来源，手工核对 3 份真实资料和 3 条信息作为基准。
3. 优先查询 Spark **只读清单**是否已有所需原件；由有权限的运行端就地读取、复用。没有访问权时先做公开新源，不复制几百 GB 到个人电脑，不改旧库、不重新下载相同字节。
4. 用 [样例生成器](examples/make_sample.py) 运行四种合成交付包及 [离线验包工具](../../../scripts/validate_collector_handoff.py)，然后按同一格式生成本队真实小包。样例不能混入正式资料。

负责人提供对象索引、只读存量清单和私有交付位置；尚未提供时，员工仍可交对象待匹配线索及本地验包结果。真实上传与研究端回执必须在地址和身份确认后联调，不编造接收 URL 或凭据。

## 节奏与验收

- **第 1 天：** 来源登记、3 份人工基准、共同包格式、最小可运行命令。
- **第 2–3 天：** 首批真实包；负责人抽查各队 10 条（不足 10 条全查），修正定位、口径和时间问题，进行一次研究端接收联调。
- **第 4–5 天：** 完成表中首批范围；验证重放、来源修订、单项失败隔离；安装一个队一个的周期任务，提供实际运行记录。未接通接收端时交待联调清单，不能报上线。
- **第二周：** 只扩展已跑通的适配器；统计实际接收、审核采用、读者页面回执。下一批优先依据缺失/陈旧/冲突与来源可得性，研究目标可作为优先级，但不是入库前提。

以上是建议的首周工作节奏，遇到无披露、需要授权或不可访问，交明确缺口和替代来源，不能降低真实性标准赶数量。指标按 [开发与验收](implementation-and-acceptance.md) 计算；不能用下载 GB、网页数或“程序跑过”当成功。

## 每人交还六件东西

1. 源码 PR、准确提交 SHA、依赖锁定和启动说明；不交只有截图的工具。
2. 来源登记表和适配器，包含唯一负责队、执行机、抓取周期。
3. 原件包：原生 HTML/PDF/JSON/CSV/XLSX 等，含 manifest 和 SHA256SUMS。
4. 逐条候选 `observations.jsonl`：对象、值/区间、口径、时间、原文定位；疑似冲突/身份不明保留。
5. `run-report.json`、`errors.jsonl`、测试结果、真实小包验收报告。
6. 接收回执和后续采用/上线回执（若已取得）；没有就标待联调，不能用员工自测替代。

本目录可以作为一套文件发给员工；不要把私有资料、账号或真实运行凭据放进任务包。推荐负责人按员工分发“README + delivery-contract + implementation-and-acceptance + 本队任务书 + examples + validator”。
