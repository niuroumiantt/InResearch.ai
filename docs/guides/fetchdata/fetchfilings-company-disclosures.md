# B 员工任务书：fetchfilings 公司正式披露

先读 [共同交付规范](delivery-contract.md) 和 [开发与验收](implementation-and-acceptance.md)。首周兼任公共内核和包格式接口负责人；其余队提交适配器，不各自复制下载/哈希内核。

## 目的与对象

持续收集公司的正式年度/季度披露、附件、债务文件、资产寿命、ESG 与项目公告。主身份是法律主体（CIK/注册号/LEI 优先），报告期及文件版本是观测维度。只在披露明确点名时关联唯一园区，不能把全球合计分摊到园区。

## 第一批对象和来源

Microsoft、Alphabet、Meta、Oracle：从各公司官方 IR 入口或 [SEC 开发入口](https://www.sec.gov/developer) 查正确法律名称及 CIK，登记经核对的值，不靠名称猜 CIK。每家取最新已发布年度 10-K 及最新季度 10-Q；如果最新期是年度，保留最近季度但不当新年度。

使用 [data.sec.gov](https://data.sec.gov/) 的 submissions / companyfacts 与 EDGAR 原文件；submissions 是发现清单，companyfacts 便于表格定位，正式文件及附注保留。按 SEC 当前自动访问规则提供真实身份 User-Agent 和限速；默认每主机最多 1 请求/秒，遇 429 退避，不把机构上限当目标吞吐。不要伪造身份或绕过限制。

## 要提取什么

| 指标/关系 | 保存范围与区别 |
|---|---|
| finance.capex / finance.asset_additions | 现金支付、固定资产增加、融资租赁增加分别保存；报表期间、币种、集团/分部，不能只写 capex 一个数 |
| finance.debt_terms | 借款法律主体、债权人、期限、利率/浮动基准、抵押/担保、金额、有效日期；unknown 不推算 |
| asset.useful_life | 资产类别、区间年限、会计估计变更适用期；不能把建筑寿命当服务器寿命 |
| company.site_role | 土地/资产业主、开发商、运营商、施工方、承租方、最终用户、股权投资人/担保人，按原文分别记 |
| site.planned_capacity / site.operating_capacity | 仅明确园区和容量口径时提取；规划/投运、IT/设施/接入、分期不能混 |
| sustainability.pue / wue / energy / water | 可选：公司/园区范围、年度、分母、取水/耗水、绝对量/强度；缺失不阻塞财报交付 |

第一批每份文档先提取 3–5 条实际存在且定位准确的信息；没有披露的交缺口，不为凑数写估计。XBRL 用 concept + context + unit + period + accession 定位；同一 concept 可能有不同维度和重述，不按 tag 名去重。

## 操作流程

1. 建主体登记、发现文件清单，记录 accession、form、报告期、披露日期、附件关系及原 URL。
2. 复用 Spark 已有同字节原件；没有则取得原生 HTML/XBRL/PDF/JSON。HTML 附表影响结论时保留必要附件，不只存摘要。
3. 提取报表行及必要附注；逐条交候选，既有对象 ID 不明则 unresolved。数据发布单位是百万时保留比例，不丢表头。
4. 每工作日查新披露，周回查最近 90 天修订/补充件，年度报告更新时核对既有口径；10-K/A、10-Q/A 和重述单独版本，旧数据不删。

## 本队验收

交 4 家主体身份表、8 份目标文档的实际取得/缺口清单、候选包和 10 条人工核对。回归至少覆盖财政年度非自然年、单位缩放、集团不等于园区、租赁与现金 capex 分开、修订件保存五种情形。每条出错说明是否同适配器其它记录也受影响。

不可把公司披露自动标为所有项目都已核实；公司报表可以先积累到公司对象，不等待找到园区或模型问题。公共入口于 2026-10-11 核查，具体公司最新报告由员工实际确认。
