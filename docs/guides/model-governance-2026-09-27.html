数据中心经济模型
五层两级、四柱六队

骨架大于案例：变量分五层，输出分两级，四根柱子承载数据与规则，六支抓取队按来源机制补给。
五层输入变量：构成、运行、价格、时间、主体。五层正交，一个案例 = 五层各取一个值。
两级输出：成本级（TCO，capex + opex）与回报级（收入、分账、杠杆后回报）。
四柱承载物：目录、序列、规则、视图。数据与规则分开，页面只是视图。
六队抓取分队按来源机制划分，从五层目标清单领任务，统一交付到供应中心。

本文件是 inresearch.ai 项目此后建模、找数据与分工的指导。它把 2026-09-27 之前形成的爆炸图、成本结构（TCO）、主体账本与价格库放进一个统一结构，说明每样东西属于哪一层、住在哪根柱子里、由哪支队伍更新。公司名、案例和具体数字都会变，本页描述的结构不随它们变。

阅读顺序：第 2 页五层两级（模型骨架），第 3 页四柱（数据与规则的家），第 4 页六队（抓取分工与日历），第 5 页闭环与原则（怎么运转、先做什么）。

二 · 四柱：数据与规则的家

目录、序列、规则、视图各司其职；数据不写在页面里，页面不存值

目录柱 Catalog

装什么：部件目录（46 个部件：状态、上游、公司、挂接序列）；每 MW 工程量表（待建）；站点、冷却、设备类型预设表。

文件：framework/bom.json，datacenter_tco_model.json 的 sites / coolings / it_classes。

规则：一个部件一个 id；工程量以 1 MW IT 为基准；预设只作起点并注明来源；非物理量不进目录。

承载：第 1 层。

序列柱 Series

装什么：全部带时点的数字：价格、费率、工资、租金、造价指数、PUE/WUE 实测、集群功率实测、交期、折旧年限、债务票息。

文件：data/prices.json（512 条）。

规则：series_id + as_of 唯一；grade 分监管 / 公司 / 研究 / 媒体 / 估算，估算必带 assumptions；一个序列只装一种口径的实测点；预测值与案例不入序列。

承载：第 2、3、4、5 层的数据。

规则柱 Rules

装什么：因子树（部件 → 因子 → 模型输入的聚合规则）；模型口径（公式、单位、每个输入的证据状态与抓取目标）；参考实现的恒等式断言；五层目标清单（待建）。

文件：framework/tco_factors.json，data/datacenter_tco_model.json，docs/research/datacenter-tco/model.py。

规则：规则只定义结构与归属，不保存数值；改引擎先过断言再改前端。

承载：层与层之间的聚合，五层到两级的公式。

视图柱 Views

装什么：爆炸图页（构成层目录视图）；tco.html（成本级）；economics.html（回报级）；价格库页；供应中心 supply.html（任务与交付）。

规则：视图读柱不写柱；每个改动相对基准显示变化；每个输入显示证据状态、最新时点与下次更新（到期列待加）。

承载：展示与操作，不承载事实。

绿底 = 已承载；黄底 = 部分承载；虚框 = 该柱不承载该层（不是缺陷）。红字为待补项。旧规定"非物理维度不进 3D"只约束爆炸图页面，不约束序列柱与规则柱。

为什么是六个，不是五个

  • 一份 10-K 同时喂运行、时间、主体三层；按层分队会让同一来源被抓三次。
  • 六类来源的抓取机制、失败模式、执行机各不相同：API 表格、EDGAR、注册下载的 PDF、JS 页面、RSS、厂商页。
  • 符合 06 号采集规范："存在独立运行与维护边界才新建 repo，不按模块机械建仓库"。
  • 中国来源（信通院、运营商集采、招投标平台）机制又不同，将来可从 fetchstat 与 fetchreports 分出中文分队，现在不建。

六队共同遵守的三条

  • 需求只来自一张表：五层目标清单（因子树扩展）写明每层要哪些序列、来自哪类披露、下次更新日期；各队从这张表领任务，不自定抓什么。
  • 交付只走一个入口：按 fetchspec 包格式（manifest、SHA256SUMS、原件）交到供应中心；数字进序列柱，文本与规格进材料档案再提取。
  • 公司是实例，不是单位：任务写"披露类型 × 出版方类别 × 日历"，当前公司列在"实例"栏，可替换。

四 · 闭环与原则：怎么运转、先做什么

页面报到期 → 生成任务 → 六队抓取 → 入柱 → 模型改值 → 页面重算

六条原则

  1. 骨架大于案例。公司案例只作对标与校准，不直接覆盖因子值。
  2. 披露类型是抓取单位。公司是实例，随时可换。
  3. 一序列一口径。预测值与案例不进序列，估算必带假设链。
  4. 数量 × 价格 × 时间。capex 与 opex 都是物理量乘单价再排到年上；物理量来自目录与运行层，价格来自序列柱。
  5. 敏感度 × 不确定性定优先级。龙卷风图排在前的先抓；低敏感度的允许留作假设。
  6. 引擎先过断言再改页面。改值前 model.py 恒等式必须通过。

三种时间行为决定节奏

类型例子节奏
结构性慢变量折旧年限、造价构成、人效、维护比例年，按出版日历
市场定价变量电价、需量费、租金、GPU 小时价、票息、地价月或事件
代际变量每 MW GPU 密度、每 kW IT 造价、更新比例每代产品发布

"一次性"与"持续更新"不用人判断：目标清单里构成层的序列一年也不到期一次，价格层的每月到期。

近期任务（按顺序）

  1. 五层目标清单：扩展因子树，补披露类型、当前实例、发布日历、目标序列、目标输入、执行机。
  2. 每 MW 工程量表骨架：列部件与用量单位，数值留待抓取；四个造价类目写明部件清单。
