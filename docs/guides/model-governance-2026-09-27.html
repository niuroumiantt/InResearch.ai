数据中心经济模型
三级、四段、五层、六队

三级输出：成本级、收入级、回报级。回报 = 收入 − 成本，再按主体分账。
四段流程：采集 → 事实 → 规则 → 视图。每段只从上一段取，不能跳。
五层变量：构成、运行、价格、时间、主体。五层正交，案例 = 五层各取一值。
六队采集分队按来源机制划分，从五层目标清单领任务，统一交付。

骨架大于案例。公司名、案例和数字都会变，本页描述的结构不随它们变。五层说一个变量是什么，四段说它此刻在哪，三级说它最后算成什么，六队说谁去取。

阅读顺序：第 2 页三级（算成什么），第 3 页四段（数据走哪条路、五层住在哪），第 4 页六队（谁去取、什么时候取），第 5 页闭环与原则。

二 · 四段：数据走哪条路，五层住在哪

采集 → 事实 → 规则 → 视图；事实按"怎么变"分参照与观测

① 采集

六队从外部取材料，按 fetchspec 包格式（manifest、SHA256SUMS、原件）交到供应中心验收。唯一与外界接触的段。

规则：任务只来自五层目标清单；写"披露类型 × 出版方类别 × 日历"，公司只是实例。

② 事实

参照数据（按版本改）：部件目录、每 MW 工程量、站点/冷却/设备预设。文件 bom.json、模型的预设表。

观测数据（按时点追加）：价格、费率、实测效率、交期、票息。文件 prices.json，512 条。

规则：series_id + as_of 唯一；一序列一口径；估算必带假设；预测与案例不入库。

③ 规则

事实怎么变成答案：因子树（部件 → 因子 → 输入）、模型口径（公式、单位、证据状态、抓取目标）、参考实现的恒等式断言、五层目标清单（待建）。

规则：只定义结构与归属，不保存数值；改引擎先过断言。输出三级。

④ 视图

答案怎么被看到：爆炸图页、价格库页、tco.html、economics.html、供应中心页。

规则：只读不写；每处改动相对基准显示变化；每个输入显示证据状态、最新时点与下次更新；报出的到期与缺口回到①。

五层是内容轴（一个变量是什么），四段是流程轴（它此刻在哪）。两轴正交，任何一条数据同时有一个层和一个段；五层目标清单就是这张表的行。绿底 = 已承载；黄底 = 部分；虚框 = 该段不承载该层。红字为待补项。

为什么是六个，不是五个

  • 一份 10-K 同时喂运行、时间、主体三层；按层分队会让同一来源被抓三次。
  • 六类来源的抓取机制、失败模式、执行机各不相同：API 表格、EDGAR、注册下载的 PDF、JS 页面、RSS、厂商页。
  • 符合 06 号采集规范："存在独立运行与维护边界才新建 repo，不按模块机械建仓库"。
  • 中国来源（信通院、运营商集采、招投标平台）机制又不同，将来可从 fetchstat 与 fetchreports 分出中文分队，现在不建。

六队共同遵守的三条

  • 需求只来自一张表：五层目标清单（因子树扩展）写明每层要哪些序列、来自哪类披露、下次更新日期；各队从这张表领任务，不自定抓什么。
  • 交付只走一个入口：按 fetchspec 包格式交到供应中心；数字进观测数据，规格进参照数据，文本进材料档案再提取。
  • 公司是实例，不是单位：任务写"披露类型 × 出版方类别 × 日历"，当前公司列在"实例"栏，可替换。

四 · 闭环与原则：怎么运转、先做什么

视图报到期 → 生成任务 → 六队采集 → 入事实 → 规则改值 → 视图重算

六条原则

  1. 骨架大于案例。公司案例只作对标与校准，不直接覆盖因子值。
  2. 披露类型是采集单位。公司是实例，随时可换。
  3. 一序列一口径。预测值与案例不进观测数据，估算必带假设链。
  4. 数量 × 价格 × 时间。成本与收入都是物理量乘单价再排到年上；物理量来自参照数据与运行层，价格来自观测数据。
  5. 敏感度 × 不确定性定优先级。龙卷风图排在前的先抓；低敏感度的允许留作假设。
  6. 引擎先过断言再改视图。改值前 model.py 恒等式必须通过。

三种时间行为决定节奏

类型例子节奏
结构性慢变量折旧年限、造价构成、人效、维护比例年，按出版日历
市场定价变量电价、需量费、租金、GPU 小时价、票息、地价月或事件
代际变量每 MW GPU 密度、每 kW IT 造价、更新比例每代产品发布

"一次性"与"持续更新"不用人判断：参照数据一年也不到期一次，观测数据里价格层的每月到期。
