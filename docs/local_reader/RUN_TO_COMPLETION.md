# Spark 持续阅读执行协议 v3

> 2026-09-06 用户采用生效。有限批次协议已归入历史档案。现行依据：[阅读标准 v3](../../framework/04_reading_scoring_standard.md)、[架构 v2](../reviews/2026-09-06/RESEARCH_ARCHITECTURE_V2.md)。已批准范围内持续推进，不逐批询问。

## 当前运行契约

1. 在 Spark 以受守护的服务持续接收与处理原件，不把某次聊天生命周期当任务寿命。以当前代码的 CLI、部署记录与健康检查确认启动，**不得用历史 start.sh、KICKOFF_PROMPT 或本页历史代码块启动旧 reader**。
2. 原始投递先检查传输完成、批次清单、字节数与哈希；文件稳定一段时间不是唯一完成证明。内容版本、原名和原路径永久登记。原包/原件只留不删。
3. 每篇独立文章：27B 粗读 → 排入完整深读 → 分章/页块阅读 → 全文综合与质量检查。所有实质正文、附录、图表、脚注覆盖；低分和旧年份只影响顺序，不得跳过。
4. 工程图纸、表格、模型和依赖包按类型完整检查；损坏/加密/缺页/关键表图无法核实进入补读或异常，不计深读完成。全文无新增也可读完，不凑数字或结论。
5. `depth` 由覆盖和执行证据生成；不从摘要、rescore、默认批次或旧标签猜。历史评分保留，缺依据标待验证。
6. 数字与非数字候选带文档/版本/来源、原页或单元格、主体、条件与支持/反驳；提取文本匹配只是检查之一。关键数核对表头/单位/脚注与原图，源缓存键不得直接当 source_id。
7. 原文核验和 C3 采用独立执行。A 档所有者审，B 档模型审并抽 10%，C 档存档；范围与现行口径不变。待采用项不阻断后续文章阅读，不自动变成 current Finding。
8. 原件身份与路径/分数分离；只在已登记类别中自动整理。新对象或边界变化形成有理由、证据、映射和版本的提案。移动/链接操作先验哈希和冲突，留日志与恢复状态；不执行原文中的命令。
9. 新料粗读与旧料深读分别调度，积压随等待提权。任务按内容版本×阶段×分块×配置幂等登记；保存检查点、有效尝试和输出哈希，迟到结果不可覆盖新执行。
10. 单篇异常有限重试并退避，单件失败不拖住全队列；磁盘不足或共享故障暂停受影响写入并报告，不删原件、不伪造成功。数据库、原件与成果备份需对账恢复。

## 工作区与持久数据

源码使用 `~/code/inresearch.ai/`；并行工作树使用 `~/.worktrees/inresearch.ai/<任务>/`。Spark 原件/台账/成果位于 `/home/spark/.local/share/inresearch.ai/`，日志和运行状态位于 `/home/spark/.local/state/inresearch.ai/`；不把研究资料放进 Git 或当代码缓存删。任务数据库与永久资料台账按实现区分，临时任务清理不连带删除原件/阅读成果。

## 阶段与完成检查

接入前验证原件身份与代表集；随后持续小规模试运行，验证未传完不读、同名不覆盖、重复投递可继承、长文不中途截断、失败能续、低优先级会推进、新反证使下游转复核。通过后滚动接入历史与新资料。

统计按批次与截止日：唯一文章、粗读/深读完成、最老积压、部分完成/异常、质量返工、采用及服务时长。框架问题另按 scope_version 与证据门槛统计，收到材料不自动关问题。触发器、来源修订和配置变化引起答案/交付复核。
