# 企业窗口接通产品资料（2026-10-07）

本轮补充四区块首页的数据映射。唯一入口 `/product-catalog.html?c=<公司ID>` 保持，完整规格按点击读取。

## 断点与实现

上一生产验收的 Supermicro 有五款服务器及原表（见第二批计算目录交接），记录 taxonomy 为空；旧首页跳过所有未分类记录，所以误显示原厂分类尚未交付。业务卡此前依赖 GPU/server/edge 名称搜索，实际 SYS 型号并不包含这些词。

- 首页直接读取当前接收批次 SQLite 的 ID、型号、kind、官方路径、taxonomy、listing 和原表数量；返回目录实体/具体型号/有规格型号/原表数，以及每类最多两个型号入口。不返回规格单元格、原件或私人载体。
- Supermicro 公司披露的六类业务有稳定 ID。共享 `product_navigation.company_line` 按已捕获官方 URL 路径关联资料，不猜型号名、不改变原厂 taxonomy。已知五款对应 GPU 1、MP/Hyper/CloudDC 服务器 3、IoT 边缘 1。此计数来自既有交付身份，不是今天实时目录统计。
- 产品索引、业务筛选、精确型号深链及 CSV 导出共用同一关联。空分类返回空结果，未知路径有待关联入口。完整资料入口用 scope=all，不遗漏已收录但缺原厂分类的条目；原厂大类显示全部系列，避免首页数量和第一系列筛选不一致。
- 其他公司按真实接收目录生成首页分组和代表型号，不依赖产品登记表的搜词卡。目录页/未分类资料保持可见；零收录不表示公司无该业务。
- 只改展示投影，不重写原件、当前接收库、ProductStore 或研究采用状态。新资料通过现有接收接口入库后首页自动更新。

## 采集与接收范围

Fetchspec Macmini 旧全公司原件归档、ProductStore 结构化目录、研究原件接收与 AWS 网站规格目录是不同环节。源码和历史生产验收记录不能证明所有已抓 PDF/HTML 已进入产品目录。本轮已请求当前 Macmini `status.json` 与网站 summary 输出，对账前不宣称所有历史资料已接通。Macmini 原件路径和兼容操作见 Fetchspec `docs/adapters/supermicro.md`；不拿五款示例覆盖更大或更新的现有批次。

本轮真实运行数据、部署回执、CI 版本与截图保存在 Git 外的 `/workspace/artifacts/company-catalog-map/`。浏览器集成用真实接收器、隔离 SQLite 与 HTTP；生产型号/官方路径身份搭配明确 `TEST_VALUE` 单元格，不是生产规格值。该测试不联网请求行情/新闻，不证明采集覆盖或当前生产新闻。
