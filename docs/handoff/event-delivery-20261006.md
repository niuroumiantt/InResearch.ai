# 逐事件交付与阅读执行交接（2026-10-06）

## 本阶段实现

- 日报项目动态通过接收回执、原件 SHA 与来源侧车对应关系进入公开项目动态；公开投影只含标题、日期、来源链接、阶段观察和需求 ID，不含正文、PDF 内容或本地路径。
- 补来源、来源对应、园区身份、容量与研究采用各自列出任务；一条已交付动态可仍有核验任务，计数不可相加。来源齐全不自动更新正式项目或 GW。
- Reader 每四次服务一次最老任务、一次完成交付阶段、一次有来源的短 HTML，余下一次按优先级。空槽回退原调度；认领下限、全文覆盖、冻结配方与散热保护继续执行。
- 匹配页增加分流计数、通道筛选、交付动态链接和真实接收时间。公共 projects.html 的 pipeline 展示日报标题与来源。

## 验证

- Python 单元测试 1691 项通过；supply、industry、datacenter_news 浏览器测试通过，含 390px 页面与外部标题转义。
- governance、严格数据校验、registry 通过。它们不证明来源语义、项目消歧或正式采用已完成。
- Spark 只读预检：308 条事件中，96 条满足项目动态交付条件，183 条缺来源；其余分别处理来源对应与非园区研究。部署后须从网站实际接收快照核对，不能用此预检冒充上线。

## 后续模型切换

用户希望先用 M5 Codex CLI 推理解除 Spark 热暂停瓶颈，原件、主数据库、接收和发布仍在 Spark。M5 codex-cli 0.160.0 已用 gpt-6.1-sol、medium 完成一次无材料 JSON Schema 探测。公共适配器当前只有 Claude CLI、Ollama、gateway，Codex 直接适配与实际材料端到端验收尚未完成；131 份材料尚未因此转交。

保持模型配置和阅读版本可追溯。不得把新配置写入已有未完成版本并混用模型。已完成结果保留；未开始任务或显式新阅读版本可迁移。切回 Spark 使用统一角色配置，核对旧 READER_* 覆盖项并重启执行进程；先做真实材料验收。CLI 的 JSONL 本次未携带服务端实际模型字段，不能把请求的型号伪造为服务端返回的实际型号。
