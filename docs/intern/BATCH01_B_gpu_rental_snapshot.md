# 工单 BATCH01-B：GPU 时租现货价月度快照

你好。这张工单是我们价格体系里**最活**的一条线：GPU 每小时租金是整个 AI 算力市场
供需最灵敏的温度计，华尔街的分析师也在看同样的数——而我们要比他们记得更规整。

## 任务

每月固定一天（建议每月 1 日），抓取下列公开价格页，记录 **H100 与 B200 每卡时租**：

| 商家 | 页面 | 记什么 |
|---|---|---|
| Vast.ai | 公开市场页 | H100 SXM 中位挂牌价（不是最低价——最低价常是坏节点） |
| RunPod | 定价页 | H100/B200 按需（on-demand）价 |
| Lambda | 定价页 | H100/B200 按需价 |
| CoreWeave | 定价页 | H100/B200 挂牌价（如仅报整机 8 卡价，照记并注明） |

## 口径规矩（这单的全部难度就在口径）

1. **每商家单列一条记录，永远不做跨商家平均**——按需 vs 预留、单卡 vs 整机、
   含不含存储和网络费，各家口径都不同，平均出来的数没有意义。
2. 每条记录必须带：`value`（数值）、`unit`（USD/GPU-hr）、`as_of`（抓取日）、
   `region`（如页面区分区域）、`assumptions`（按需/预留、单卡/整机折算、SXM/PCIe）、
   `source_url`（价格页链接）。
3. 如果页面只报 8 卡整机价，**除以 8 可以**，但 assumptions 必须写「整机价折算」——
   这是全项目唯一允许的推算类型：四则运算且假设写明。
4. 价格页改版找不到对应产品时，如实记「该商家本月无此口径报价」，不要找替代品硬凑。

## 交付

- 每月一次，投递到 `docs/inbox/submissions/你的名字_日期/`，格式参照
  `data/prices.json` 里 `gpu-hourly-h100-spot` 序列的现有记录（已有 5 个点，
  你是在续这条线，不是新开一条）。
- 第一次交付前，先把你打算记录的字段样例发来核对一遍口径，对齐后再正式开始——
  第一个月的口径定了，后面每个月照做就行。

这条线做满六个月，就是一张任何投行报告都要引用的图。谢谢你。
