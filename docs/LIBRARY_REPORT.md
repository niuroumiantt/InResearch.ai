## 三、分类标准全文（给新人直接照做）

### 3.1 处理一份材料的完整流程

```
1. 提取文本   python3 pipeline/extract.py <file>...      → cache/text/<key>.txt
2. 判读       digest_view.py 看数字行 / 高价值件读全文     → 定 importance 与 confidence
3. 起新名     {importance}{confidence}_{年份}_{主题四到八字}_{机构}.{ext}
4. 写 summary ≥200 字，尽量多装可落库的数字
5. 落地       commit_batch.py batches/batch_YYYYMMDD_NN.json
6. 交付       deliver.py（= 复制到 inbox + push + 校验本地远端 commit 一致）
```

### 3.2 打分规则（标准 v2 + 本项目踩出来的补充）

**七维度**：D1 数据独占性 / D2 口径可考性 / D3 可落库密度 / D4 时效半衰期 /
D5 缺口匹配度 / D6 证据升级潜力 / D7 反面价值。取**加权印象分**，不是逐项打分求和。

**分数锚点**：9 镇库 / 8 支柱 / 7 重要 / 5-6 有用 / 3-4 存档 / 1-2 噪声。

**两条上调修正（最容易漏，本会话就在这里翻过车）**：

- **跨模块杠杆 +1**：一份喂 3 个模块的材料，比单模块同质量材料高 1 分；
- **中国板块 +1**：同等质量命中 M14 的材料 +1（中文一手材料稀缺）。

**下调规则（batch_07 事故后固化）**：

- 厂商**会议演示版**默认落 **5 分档**；
- 上 6 需额外满足其一：命中缺口模块 / 与库内材料构成交叉验证 / 提供别处拿不到的规格基准；
- 上 7 需是超大规模厂商或独立分析师的**一手口径**，或具备明确反面（压力测试）价值；
- 8-9 分在会议材料语料中基本不存在，**不要为凑分给出**。

**⚠ 边界情况：下调规则只适用于「会议演示件」，不适用于「数据集/数据表」。**
本会话把它错误地套到一份 370 行 × 79 列的算力指标表上，盲评偏差 -2 分触发停机。
数据表按 D3 落库密度的锚点判（TechInsights DRAM 季报式逐项数据表 = 8 分档）。

**⚠ 边界情况：一手实测但单产品窄范围 → 6 分，不上 7。**（Wolley NVMe-oC 实测校准出的判据。）

**confidence**：A 一手/实测/官方规范；B 机构预测/会议演示版；C 转述/汇编/方法论不明。

### 3.3 分桶规则：什么进精读队列，什么不进

**分桶不能只看扩展名，必须拿内容验一遍再定分母。** 本会话实测：用户排单的
「可精读文档 917 份」里有 **47% 根本不该进精读队列**，修正为 482。

| 桶 | 判据 | 处理方式 |
|---|---|---|
| **可精读** | 提取出可读文本、中文/英文占比正常 | 逐份或半自动生成打分行 |
| **图纸素材** | ①PDF 前 20 页 <200 字符；②位于出图/图纸目录且中文占比 <15%（标题栏字形损坏）；③dwg/dwf/skp/max/3ds | **目录级普查，不逐份改名**（改名会打断 dwg 的 xref 外部参照） |
| **软件中间件** | 文件名命中 `SAPSS_*` / `*.dat-ERR` / `DrawSet_*` / `Plan_*` / `Elev_*.CSV` / `plot.log` / `Thumbs.db` / `*.yjk` / `*.yg` | 目录级登记 |
| **噪声** | 营销材料、无方法论预测、引流件 | 1-2 分，隔离候选 |

**三个踩过的坑（新人必看）**：

1. **纯数字文件名的 PDF**（`00.pdf`、`1.pdf`）是 CAD 导出的施工图，不是文档。
2. **能提出约 1000 字符但全是乱码**（`クằ྇`、`ٺ Б मڏ`）的是标题栏字形损坏的图纸——
   **只看字符数会漏放**，要加「中文占比 <15% 且位于出图目录」的判据。
3. **大写 `.CSV`**（`DrawSet_Beam.CSV`）是 YJK 施工图设置导出，正则要大小写不敏感。

### 3.4 防幻觉铁律（不可协商）

1. **summary 里每个数字必须能在提取文本中原文找到**，找不到的标 `[未核]`；
2. 作者自述为估算（we believe / we estimate）的，必须标明估算口径；
3. 派生值（如 IT 负荷 = 机柜数 × 单架功率）一律标注「计算值」；
4. **字形损坏检测**：部分 PDF 的 ToUnicode 表损坏会整类吞掉字母数字
   （MI300X → "M00X"），`extract.py` 用字母频率检测自动拦截，**绝不能据此类文本写 summary**。

### 3.5 重复件怎么处理

用户 2026-08-16 批复：**只取一份**。做法是两份都登记（保证触达率如实），
summary 开头加 `【去重·保留】` / `【去重·不保留】` 并注明以哪份为准，分数给一致
（打的是材料价值而非副本地位）。

### 3.6 校准纪律

- **每批开头盲评 3 份**（`calibrate.py draw` → 读原文打分 → `reveal`）；
- **偏差 ≥2 分就停机**，重读标准，改完再抽一轮复测通过才能开批；
- **按尺度纪元抽样**：尺度调整过就新开纪元，只从当前纪元抽，否则测的是「与历史平均的距离」；
- **同会话内自己几小时前打的分不构成有效盲评池**，如实记录「无法盲评」，改用分布校验 + 锚点直接对标。

### 3.7 交付纪律（三个坑都踩过）

1. **只 copy 不 push 不算交付**——云端从远端拉，`deliver.py` 以「本地与远端 commit hash 一致」为判据；
2. **`docs/inbox/*` 是黑名单式忽略**，新增交付类型必须在 `.gitignore` 显式放行，否则永远推不到远端；
3. **rebase 前自动 stash 非 inbox 的改动**（云端会话可能正在写 `framework/indicators.json`）。

## 七、本轮踩过并已固化的坑（供后续会话直接复用）

1. **分桶只看扩展名会让分母虚高 47%**——必须拿内容验一遍再定分母。
2. **`needs_password.py` 会把 `archive_skip.json` 重建为空**——本轮因此丢过一次 362 条清单，
   靠 `archives_scan.json`（保留 462 条加密包路径与大小）找回。**刷新类脚本要先备份被覆盖的状态文件。**
3. **auto_batch 的关键词表要分中英文**——中文词表跑英文语料会把整批判成无命中、系统性低一档。
4. **不能只凭「中国」二字就判命中 M14**——中文语料几乎每份都有，会把整批推高一档
   （实测 1,488 份里 741 份因此被判 6 分，收紧后回落到 350 份）。
5. **中文语料里的「IDC」绝大多数是「互联网数据中心」的通名，不是调研机构 IDC**——
   按机构名收录会污染信源统计（本轮曾误标 143 份，已全部回退）。
6. **模块编号必须对着 `research/M*.md` 的实际定义写**——本轮 auto_batch 的关键词表里
   把制冷标成 M07、芯片标成 M09、市场标成 M04，与主仓库实际的
   M08 散热与制冷 / M06 芯片与服务器 / M01 市场规模与增长 全部错位，
   **1,946 条已更正并重新推送**。
7. **同目录内多份文件会重命名撞名**——落地前要按 `(dir, new_name)` 查重并加序号。
