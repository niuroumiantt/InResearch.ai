# 数据中心全生命周期 TCO 模型

> RESEARCH MODEL · 2026-09-27 · 框架先于数据：参数是研究假设，页面单列数据缺口，指明每个缺口该抓什么。

`tco.html` 是数据中心成本结构的通用模型，不依赖任何一篇文章。它按决策顺序组织七组输入，算出逐年现金流，折现后给出平准化年成本和单位成本，每一处改动都相对基准显示变化。`economics.html`（主体账本）回答谁付钱、谁挣钱，是这个模型之上的一个视角；`cost.html` 保留 2026-09-14 的单账本基准。

## 权威边界

- 口径与全部假设：`data/datacenter_tco_model.json`（schema 1，含 `evidence` 每个输入的数据状态与抓取指引）
- 前端引擎：`web/components/datacenter-tco.js`（`window.InresearchTco.compute`）
- 参考实现与恒等式断言：`model.py` → `results.json`
- 因子树与抓取目标：`framework/tco_factors.json`
- 基准数字：`data/prices.json`，页面按 `benchmark_series` 取最新时点
- 浏览器测试：`tests/datacenter_tco.cjs`

## 七组输入

| 组 | 决定什么 | 关键输入 |
|---|---|---|
| 1 项目定义 | 规模与时间轴 | IT 容量、冗余等级、建设期、运营期、负载爬坡 |
| 2 站点 | 地域价格 | 电价与年涨幅、需量费率、土地、人力指数、财产税、水价（站点预设：北弗吉尼亚、得州、爱尔兰、柔佛、宁夏） |
| 3 设计 | 效率 | 冷却方式 → PUE、WUE、机械造价 |
| 4 IT 设备 | 设备经济 | 设备类型 → 单位造价、负载、更新周期、更新造价比例、GPU 密度与利用率 |
| 5 建设 | 资本开支 | 自建 / 租壳 / 托管；建筑、电气、机械、装配分项；软成本与不可预见费 |
| 6 运营 | 运营成本 | 人员、维护（设施 / IT）、软件、保险、带宽、其他、涨幅、退役 |
| 7 财务与对标 | 折现与比较 | 折现率；对标口径（GPU 出租 / 批发托管 / 自用）与市场价格 |

## 计算

1. 设施资本开支 = (建筑 + 电气 × 冗余系数 + 机械 × 冗余系数 + 装配 + 土地) + 软成本 + 不可预见费，建设期均摊；IT 资本开支投运年投入，按更新周期以更新造价比例重置。
2. 运营期逐年：电费（负载 × 爬坡 × PUE × 电价，按电价涨幅）、需量费、水费、人员、设施维护、IT 维护、软件、保险与财产税、带宽、其他、租壳或托管费；末年退役。
3. 折现为 TCO 现值；除以运营期年金因子得平准化年成本；除以容量、折现 IT 电量、折现付费 GPU 小时得每 MW·年、每 kW·月、每 IT kWh、每 GPU 小时。
4. 对标：GPU 出租比每付费 GPU 小时成本；批发托管比不含 IT 的每 kW·月成本；自用只看成本。

不含所得税、折旧抵税与融资结构（这些在主体账本视图里）。

## 页面

KPI 带（六个单位成本，各带对基准的变化）、平准化成本结构（当前对基准的 100% 堆叠）、逐年现金流（堆叠柱 + 基准虚线）、成本明细表（平准化、占比、每 kW·月、现值、名义、对基准）、资本开支拆分（浅色为基准）、敏感性龙卷风（每 kW·月）、情景对比、成本对市场价格、价格库基准、数据缺口清单、方法说明。"把当前设为对比基准"可把任何状态设为新基准。

## 数据状态与缺口

`evidence` 给每个输入四种状态：用户给定、已有来源（价格库或研报）、作者假设、待获取。页面按状态标记输入并列出缺口表（分组、输入、现状、抓取类型、要找什么）。这张表与因子树的抓取目标一起，是后续定向抓取的对象清单。当前 46 个输入中已有来源的约 10 个，其余多为作者假设。

## 恒等式与合理性（`model.py`）

- 各类现值之和等于总现值；平准化年成本 × 年金因子 = 总现值；每 kW·月 × 容量 × 12 = 平准化年成本。
- IT 更新次数 = 1 + (运营期 − 1) ÷ 更新周期。
- 液冷 N+1 自建设施造价落在 10–20 $M/MW；GB300 级每付费 GPU 小时成本落在 2–6 美元。
- 得州电价低于北弗吉尼亚时电费现值更低；租壳时仅剩装配资本开支并出现租金。

## 更新规则

- 新数据先进价格库或研究档案，再把对应输入的 `evidence.status` 从作者假设改为已有来源并写来源。
- 新站点、冷却方式、设备类型先加进预设表并标注来源。
- 引擎改动先改 `model.py` 通过断言，再改前端；浏览器测试核对基准 KPI 与对比行为。
