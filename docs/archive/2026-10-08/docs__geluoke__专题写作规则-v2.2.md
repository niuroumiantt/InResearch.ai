# 格洛可专题长文写作规则

版本：2.2｜更新日期：2026 年 10 月 1 日｜替代 v2.1；增加精简专题、模板总览图与手机 HTML 排版规则

适用于围绕一个核心问题展开的中文深度研究长文（AI、芯片、算力基础设施、数据中心）。本版吸收成本、利润及《AI数据中心为什么越来越需要律师》（2026-09-29）的制作与用户修订经验。用户所称“长文规则.md”“长文写作规则.md”均指本文件，不另建并行规范。用户当次的明确要求优先；本规则不自动授权发布、发送或定时任务。

---

## 一、选题与论证主线

1. 一篇只回答一个核心问题，用一句话写在大纲首行，正文每章都要回到它。标题直接表达核心问题或经证据支持的判断，不预设胜负，不把预测写成事实。
2. 用户的观点、感受或假设是待检验的研究问题，主动找支持证据、反例与适用边界，不选择性引用。
3. 先定"账本边界"再谈数字：同一件事在不同主体（出租人、托管商、云、模型方）的账上完全不同，先说清分析对象是谁的账、什么口径，再比较。
4. 每章按"对象与概念 → 作用机制 → 数据证据 → 对比与影响 → 约束与验证指标"推进；段落之间不设小标题，用首句承接。每章结尾给出可核验的指标或日期节点。
5. 篇幅分两档：完整研究专题保留原来的 1.5–1.8 万字参考，正文 6 章、每章 12–16 段；用户要求“不太长／5000—7000字”时采用精简专题，仍可保留 6 章，但按论点压缩段数，不强凑每章 12–16 段。导语两段、点评三段随总篇幅缩短。交付分别记录正文汉字数和含标点字符数，排除图注、来源及制作说明；不靠注释凑字数。上一稿的长度不自动覆盖新稿的明确要求。
6. 不写"值得关注""我们认为""毫无疑问"等判断词，不用感叹号，不写 URL 进正文，不写内部检索、工具与验收过程。
7. 先研究再决定是否成稿：围绕近几个月的变化，判断核心矛盾、可核实数据、具名案例、反例与未来验证节点，给出“值得写／证据不足”的理由及大纲。大纲获采用后直接完成文章与配图，不反复确认已确定的方向。

## 二、来源与事实核验

1. 优先级：监管与电网文件、公司公告与 SEC/交易所文件 > 研究机构报告 > 主流媒体 > 行业媒体 > 聚合站与搜索摘要。存在一手来源时不得引二手来源；搜索摘要不能作为数据点。
2. 每个数据点记录：主体、数值、单位、期间、分母或口径、属性、来源机构、URL、来源日期、原文短引。研究卡（`cards.json`）是撰稿的唯一数字来源，正文不得出现卡片和研报摘录之外的数字、名称、日期。
3. 区分：事件日期与报道日期；计划、签约、开工、并网、投运；合同总额与年租金；承诺与到账；规划容量与投运容量；关键 IT 负载与总功率（gross）；EBITDA 与净利润；债务本金与账面值。
4. 研报引用写机构与日期（"摩根士丹利 2026 年 9 月《AI 指南》"），并核对该数字在报告中的页码；同一框架若在早期报告首见，备注说明。无法读取全文的材料如实记录，不假装读过。
5. 已知易错点（本次实测）：单位换算 1 百万美元 = 100 万美元，"1,833 万" 与 "183 万" 之差是十倍；亿与十亿、亿元与万元；"全行业"与"超大规模厂商整体"的主语；"到户电价"与"发电侧可研电价"；容量费等只见媒体转述的金额不写数值。
6. 法律与政策案例先读法院判决、已提交诉状、合同或政府原文，定位页码或条款。严格区分原告主张、法院认定、公司回应与未来承诺；提交集体诉讼不等于已获认证，批准被撤销不等于永久禁建，政策框架不等于全部生效。合同有删节时，不推算未披露的期限与赔偿。
7. 第三方项目跟踪须保留统计范围与去重限制：受阻或延期项目金额不是实际损失，跨期项目不能未经去重直接相加；团队总人数不是新增招聘或专职人数。固定债务余额的简单利息是资金占用，延期新增损失须比较按期与延期两套现金流，避免重复加总。
8. 关键口径在数字或案例首次出现处说清；必要边界保留在图内与备注，不让每段都变成重复免责声明。事实、机制解释与待验证推断要自然衔接。

## 三、数字的五类属性与写法

1. 每个数字首次出现时标属性，五类：已披露事实（公司或监管披露）、研究实测（研究机构测得或指数）、厂商测试、预测估算（机构估算与公司目标、指引）、作者说明性计算（我们自己的换算与模型）。机构的定性表述按"预测估算"处理；格洛可自建模型属"作者说明性计算"。
2. 每个百分比说明分母；每个比率说明分子分母的口径（NOPAT÷总资本开支、NOI÷开发成本、EBITDA÷收入）。
3. 作者说明性计算必须写公式与取整方式，例如"190 亿 ÷ 20 年 ÷ 401MW ≈ 237 万美元/MW·年（名义值，未折现，不计递增）"；敏感性分析必须公开全部假设。
4. 单位写法统一：美元用"亿美元／万亿美元"，来源原始单位为十亿美元时在图注注明；人民币用"亿元"；GPU 租价写"美元/GPU·小时"；租金写"美元/MW·年"或"美元/kW·月"；电价写"美分/kWh"或"元/千瓦时"；汇率只在需要对照时换算，注明汇率来源（如"按万国数据公告隐含汇率 6.79"）。
5. 同一数字全文最多出现两次，第二次引用第一次所在的章（"第二章的 31%"）；跨章统一取整（35.94 亿与 36 亿、24.9% 与 25% 只保留一种）。
6. 预测注明提出机构、日期与目标年份；两套基数不同的预测不并列（如信通院 2023 年基数与能源局 2025 年基数）。

## 四、制作流程（六个阶段，每阶段有对抗式核稿）

流程按篇幅与证据量组织；精简专题可由主编统一撰写，再做独立事实核稿和专项复核，不必机械地按每张卡、每章重复启动代理。复核必须重新查看关键来源，不能只复述初稿。

1. **取材**：下载并抽取研报全文（PyMuPDF），做页码级摘录 `report_facts.md`；把研报关键表格逐项转成数据点。官网 PDF 若被 JS 跳转拦截，带同站 Referer 请求即可获取。
2. **研究卡**：按主题拆成 8–12 张卡，每张一个抓取代理 + 一个复核代理（复核代理必须重新抓取来源、逐个数字核对，并补充明显缺失的数据点）。合并后由编辑做一轮单位与口径抽检（用正则找"X,XXX 万美元/MW"之类的可疑量级）。
3. **撰写**：每章一个撰稿代理，输入为大纲、研报摘录、研究卡、上一篇专题的相关章节；输出段落（每段附来源键）、图的数据点、逐一数字自检。随后一个核稿代理逐句核对并返回修正稿。
4. **压缩**：按本次约定的总字数压缩，完整专题可参考每章 12–16 段，精简专题按论点保留必要段落。只删、只合并、只改写，不新增数字；再做差异核验，确认无新增数字、无数值变化。被删的口径说明进入 `dropped_numbers.md`，供备注选用。
5. **导语、点评、首图文字与终审**：主编代理读六章定稿写标题、两段导语、覆盖行、三段点评、备注、首图文字；核稿后由终审代理做跨章检查（重复、口径不一致、缺属性、预测写成事实、章节衔接）并逐段给出替换文本。终审的"未决项"由人工编辑裁定并记录在交付说明。
6. **组装与验收**：来源按机构分组编号，正文段末加 [n]；生成公众号 HTML、完整网页版、轻量版；跑桌面与手机渲染、复制往返测试；逐张目检图片；写交付 README。

## 五、文章结构

1. 顺序：首图 → 完整标题 → 两段导语 → 一行"本篇覆盖" → 分章正文（图文穿插） → 格洛可点评 → 来源 → 备注 → 二维码 → 署名。
2. 导语一交代问题与本文用到的几组核心账本（含数字）；导语二给结论与边界（哪些是预测估算、哪些是已披露事实、作者计算未折现、中国只作参照）。
3. 点评三段：第一段说明利润或结构在各层之间如何分配及原因；第二段连接两个以上地区并引具名案例（标日期）；第三段把可验证节点排在日历上（含日期）。只用正文出现过的数字与案例。
4. 备注收录：研报版本与日期（含"框架首见于何时"）、取整与口径说明、汇率、被删的来源版本说明、未核实而未采用的内容。不写内部流程。
5. 来源列表：正文只列机构名（同一机构多份文件合并为一个编号），完整 URL、标题、日期放在 `sources.json` 单独交付。

## 六、首图与正文图表

1. 首图或全文总览图采用 2:3 竖版，目标宽度 ≥1080（优先母版 2400×3600），深蓝工程底色、白金信息层级、青色细边卡片。优先沿用用户给的模板：品牌与日期 → 本篇标题和副题 → 与论点相关的工程剖面 → 全文主题卡 → 关键数据和后续观察 → 判断与署名。主题卡可用 3 列×2 行覆盖六章，不机械沿用上一稿的回报条、收入层或旧事实。总览图应单独可读，标明工程示意，数字及条件与正文一致。二维码只使用可验证的原图，不生成伪二维码；独立总览图可把该区域用于结论。
2. 正文图常规 4–6 张；用户要求“图片多、质量高”时以 6–8 张为参考，机制图、数据图、案例卡和时间线各有用途，不用装饰图凑数，总览图另计。设计宽 640 px、DPR 2 渲染（1280 px）、256 色量化 PNG，并交可编辑 SVG；摄影式总览图按原始栅格交付，不伪称有矢量源。手机上正文字号 ≥17 px（设计稿）、标题 28 px、副题 18 px、来源 16 px。柱图从零起算，长度与数值成比例；不同单位不共用坐标轴。
3. 每张图标注：单位、期间、数据属性、口径、来源机构与页码；作者计算附公式。图内文字与正文的数字、单位（亿美元／十亿美元）必须一致，正文改动后图要重制。
4. 常用图型：按类别的水平条图（造价、敏感性）、收入—成本堆叠—利润的三行迷你瀑布、案例卡片（合同、政策）、双栏对照表（中美参数）、垂直时间线（节点）。表格类图每格 ≤30 字，注释行放口径。
5. 色板（深蓝 #0B1F3A 底）：蓝 #3987e5、橙 #d95926、绿 #199e70、黄 #c98500，金 #E0B45C 只用于标题、基准与结论。颜色要有含义并在来源行说明（如"蓝=直租，绿=转租+担保"）。
6. 生成后逐张目检：换行是否把数字与单位拆开、来源行是否与单位注重叠、图例是否与数据一致、颜色是否与说明一致。
7. 模板图只提供视觉结构，旧标题、案例和数值不得带进新稿。图像生成先固定已经核实的中文文案，生成后逐项检查文字、数字、脚注、裁切与清晰度；保存提示词、使用方式及原始分辨率。若实际只返回 1024×1536，就如实记录，不靠放大声称取得高分辨率母版。
8. 生成失败应如实记录，可重试；不得用旧图或占位图冒充成品，也不得未经授权切换收费 API 路径。补成图片后更新交付清单与压缩包，区分独立总览图和实际已嵌入 HTML 的首图。

## 七、排版参数（公众号 HTML）

1. 公众号复制版的正文容器不添加左右内边距与装饰边框，避免与平台边距叠加；正文区白色，单列流式、全部内联样式，无脚本、无外链样式、无按钮与操作提示。完整网页及轻量版按第 5 条单独处理手机边距。
2. 字号：主标题 26 px/700/#0068B5；章节标题 22 px/#08577C，前置章号；正文 17 px、行高 1.8、#1F2A37、两端对齐；信息行与日期 14 px/#5A6B7F；图注 12 px；来源与备注 11 px；引用标记 [n] 0.85em/#1E66B3。
3. 字体栈：Arial, "PingFang SC", "Microsoft YaHei", "Noto Sans SC", "WenQuanYi Zen Hei", sans-serif；点评用仿宋栈 FangSong, STFangsong, "FangSong_GB2312", "仿宋", "Songti SC", "AR PL UMing CN", serif。
4. 图片 `display:block;width:100%`，Base64 内嵌；整文件 ≤3.8 MB，建议 ≤2.0 MB（首图公众号版 1080 px、JPEG 质量 88；正文图 256 色 PNG）。
5. 三个版本：公众号版（上述）；完整网页版（桌面正文最大宽 720 px、居中、左右各 16 px 内边距）；轻量版（图片改为同目录相对路径）。完整网页与轻量版在宽度 <768 px 时，左右各 8 px、页面背景白色，去掉灰色侧边带，不叠加第二层容器边距。图片用足正文宽度，标题采用均衡换行，避免单字孤行。响应式 CSS 只加在网页版本，不破坏公众号版的行内样式。
6. 用户说“左右留白太多”时，先核对其指的是正文 HTML、图内留白还是查看器边框；已经明确为 HTML，就改页面容器，不重生成图片。修改后同步完整网页、轻量版、构建脚本和交付包。

## 八、验收与交付

1. 事实验收：每章撰写后核稿、压缩后差异核验、终审跨章检查三道；编辑另做单位量级抽检与研报页码抽查。
2. 数据验收：图与正文数字逐项对照；作者计算复算；百分比分母、属性标注齐全。
3. 视觉验收：逐张看图；桌面 1000 px 与手机 390 px 整篇渲染无横向溢出，检查实际正文宽度、两侧边距、标题孤行和图片清晰度；Markdown 与轻量 HTML 的图片路径须全部存在，显示图号按正文顺序。复制到 contenteditable 的往返测试中图片全部保留。未在公众号实粘的一律标"公众号待验证"，浏览器检查不能代替平台实粘。
4. 交付清单：完整标题；公众号 HTML；完整网页版；轻量版；首图母版与公众号版；正文图 PNG 与 SVG 源；可编辑 Markdown；`sources.json`；研究卡与研报摘录；制作脚本；`checks/`（渲染缩略图与 validation.json）；README（验收状态、边界、未决项）；整包 zip 放在仓库工作目录供直接下载。
5. 仓库入库：交付物 HTML 登记到 `framework/interface_manifest.json` 的 `excluded_pages`，运行 `governance --refresh` 与单元测试后提交；`verify`、`indicators` 产生的改动不提交。
6. 换会话时写一页交接：已确认偏好、当前规则版本、成品路径、验证结果、未完成项与下一步。新对话只读交接和唯一规则源，不整段复制历史；新文章必须重新研究和核实日期，不把上一稿数据作为新事实。用户尚未给选题时，先索取选题或材料，不擅自替用户决定。

## 九、研究反哺

文章交付后当天，按 [专题反哺规则](专题反哺规则.md) 把视角、数据与规范回流到 inresearch.ai：建 `docs/research/<日期>/<主题>/` 档案（正文、来源、复算脚本、反哺台账），把文章视角做成相关页面的输入、输出、情景预设与基准，已核验数据点进价格序列或事实层，未录完的写进台账候选。反哺不改变既有页面基准，每个新增数字带时点与属性。

## 附录 A：利润专题术语示例（按新稿主题选用）

以下含 2026-09-27 利润专题的历史参数，只作术语和口径示例；新稿引用任何数值须重新核实，不能视为当前市场基准。

| 术语 | 释义 | 在账本中的位置 |
|---|---|---|
| Powered shell（带电的壳） | 已完成土地、并网变电、楼宇、供配电与冷却、但未装服务器的数据中心建筑；出租方按 10–25 年租约租给自带 GPU 的承租人。摩根士丹利称此类公司为 powered shell providers | 收入：美元/MW·年；风险：造价、工期、租户信用 |
| Colocation（机柜托管） | 连机柜、电力、冷却与运维一起提供，客户只放自己的设备 | 收入：美元/kW·月 |
| GPU 云 / 新云（neocloud） | 自购加速器按开机小时出租的云服务商（CoreWeave、Nebius 等） | 收入：美元/GPU·小时；利用率、单价、折旧、利息都在其账上 |
| 模型 API | 按 token 计价的推理服务 | 收入：美元/百万 token |
| Capex / 资本开支 | 一次性投入；IT capex（服务器、网络）与非 IT capex（壳与机电）分列 | 摩根士丹利 1GW GB300：230 亿 + 160 亿 = 390 亿美元 |
| EBIT | 息税前利润 = 收入 − 营业成本（含折旧） | 不扣利息，与融资结构无关 |
| NOPAT | 税后营业利润 = EBIT × (1 − 税率) | 摩根士丹利用 21% 税率 |
| ROIC | 资本回报率 = NOPAT ÷ 总资本开支 | 本篇 31% 的定义 |
| EBITDA / 调整后 EBITDA | 息税折旧摊销前利润；"调整后"另剔除股权激励等项目 | 新云报表的主指标，未扣折旧与利息 |
| NOI | 净营业收入 = 租金 − 出租人承担的运营成本；三净租约下 NOI ≈ 租金 | 壳与托管层的分子 |
| Yield on cost（成本收益率） | 稳定后年 NOI ÷ 开发成本 | 壳层 16%–20%，REIT 开发项目 11.5% |
| Triple-net（三净租约） | 承租人承担电费、税费、保险与维护 | 出租人 NOI 接近租金 |
| Modified gross（修正毛租约） | 出租人承担部分运营成本 | NOI 低于租金 |
| Backstop（担保兜底） | 第三方（如 Google）为承租人的租约义务提供担保，使项目可以举债 | 换取股权或认股权证 |
| RPO / 收入积压 | 已签合同中尚未确认的收入 | 与当期收入相隔建设周期 |
| 关键 IT 负载 / gross 功率 | 供服务器使用的功率 / 含冷却与损耗的总功率 | 换算每 MW 数字时必须注明 |
| MSR、上架率、计费率 | 万国数据的每平米月收入、已用面积÷运营面积、REIT 底层资产计费面积占比 | 中国托管层指标 |
| CROCI | 现金投资回报率（高盛口径） | 超大规模厂商 24%–31% |
