# 知识层格式规范 — 模块研究文档

> 知识层是本项目的**主体**：`research/Mxx.md` 每模块一份"活研究文档"。
> 35 问报告是初始内容来源；此后文档随数据更新持续修订，报告只是它的导出物。

## 基本单元：Finding（研究结论）

一条 Finding = 一个**可独立证伪、可独立更新**的研究结论。粒度判断：如果新证据出现时
只需要改这一条而不牵动别条，粒度就对了。原报告的一个 Q 通常拆成 1–3 条 Finding。

## 文件结构（机器可解析的 Markdown 约定）

```markdown
# M08 散热与制冷 — 研究文档

## M08-F1 结论标题（一句话，就是结论本身） {Q26}
- **状态**：current ｜ **修订**：2026-08-14 ｜ **触发器**：indicators:liquid_cooling_penetration
- **结论**：完整表述（2–4 句，可直接进报告）
- **论证**：
  - 支撑点（从原报告详细支撑压缩，保留推导链条）
- **证据**：
  - [S2/company] 描述性引文 — URL
  - [数据层] companies:vertiv ｜ prices:cdu-lead-time@2026-06-30
- **口径提醒**：不能怎样误读（原报告的口径纪律，逐条保留）
- **待办**：数据层缺口、待补实体、待验证点（可空）
```

## 字段规则

| 字段 | 规则 |
|---|---|
| Finding ID | `Mxx-Fn`，模块内递增，**永不复用**（废弃的编号留给 superseded 记录） |
| `{Qnn}` | 溯源到原报告问题号；纯新增研究标 `{new}` |
| 状态 | `current` 现行 ｜ `needs-review` 有信号待复核 ｜ `stale` 超期未复核 ｜ `superseded` 已被取代（保留原文+指向新 Finding） |
| 修订 | 最后一次实质修订日期；只更新状态不算修订 |
| 触发器 | 什么信号出现时本条要复核：`indicators:id`（指标越阈）、`entity:id`（实体重大信号）、`periodic:180d`（定期） |
| 证据 | 来源分级沿用口径手册 S1–S5；`[数据层]` 行把结论挂到六张表的具体记录 |
| 口径提醒 | 原报告"不能这样解读"的纪律逐条保留，导出时随 Finding 一起输出 |

## 更新流程（知识层的核验闭环）

```
信号（collect.py）命中触发器 → Finding 标 needs-review →
人工/AI 复核证据 → 结论变 → 修订正文、旧结论如仍有参考价值则 superseded 存档
                → 结论没变 → 仅更新修订日期回 current
```

`stale` 判定并入 verify.py：`periodic` 到期或修订日超过 365 天未复核。

## 与其他层的关系

- **数据层**：Finding 引用记录（`companies:id` 等）；记录变化是 Finding 复核的触发器之一。
- **模块定义**（`framework/modules/Mxx_*.md`）：管"问什么"；研究文档管"答什么"。
- **导出器**：报告 = 选模块 → 取 `current` Finding → 按模板渲染（结论/论证/证据/口径提醒
  分层输出）。`needs-review`/`stale` 的 Finding 导出时强制带警示标注。
