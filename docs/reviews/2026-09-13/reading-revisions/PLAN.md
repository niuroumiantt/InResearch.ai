# 阅读版本整改：修改前证据与实施契约

## 现状证据

- storage/catalog.py 的 documents 同时拥有内容身份、冻结 recipe、执行状态、覆盖计数和 report_rel；jobs 只有 doc_id，不能独立识别一次重读。
- workflow/reader.py 的 retry 只重新开启 failed/blocked 任务；已完成材料返回 0，换默认模型不重读。这条保护保留，不把 retry 偷换成重新阅读。
- ReadingStages 将报告固定写到 artifacts/<doc_id>/report.json，提取文本也只有文档目录；缓存只比较 recipe。不能在此目录覆盖新配方并声称保留旧证据。
- reader_export 直接从 documents.report_rel 取报告；没有待验收版本与当前版本的选择边界。claims/evidence 的 ID 仅含 doc_id 和块位置，重读会复用旧身份。
- OCR worker 直接查询 documents 的 blocked 状态；迁移不能遗漏这一库外执行消费者。知识快照接收器会过滤未知字段，阅读版本身份须贯通这一边界。
- 原始数据与 M4 独立深读工作不属于本轮写入范围。完整文件处置见 file-plan.csv，引用见 consumers-before.csv，隔离复现见 baseline.json。

## 目标职责与数据权威

| 对象 | 唯一权威 / 职责 | 消费与限制 |
|---|---|---|
| 原件 / 内容身份 | documents：SHA、原名、存储位置、接收关系、当前阅读版本指针 | 不因重读复制文档身份、移动或删除原件 |
| 阅读版本 | reading_runs：旧版本基线、请求键、原因、冻结配方/上下文、独立产物路径、状态、报告摘要、验收记录 | 队列任务携带 revision_id；重试在同一版本内，不覆盖旧版本 |
| 当前阅读投影 | current_readings SQL 视图；只选择 current_revision_id，无当前结果时展示首次阅读进度 | 导出、状态和网页每个内容身份最多一项；新候选失败不替换当前成功结果 |
| 执行与替换用例 | workflow/reading_revisions.py 与 Reader 的同一队列 | 显式 reread → inspect → activate/reject；不能自动进入 C3 |
| 版本产物 | 独立 artifacts/extracted 版本目录，写入后校验并冻结；历史路径原样保留 | 验收前后验证覆盖、原件、配方、报告及各块摘要；报告 ID/证据 ID 不复用 |
| 原件目录视图 / 接收回执 | 既有 operations/intake_operations | 与阅读版本分开；重读不再次搬运接收副本，既有命名入口保留为原件别名 |
| 网页候选 / 正式知识 | reader 快照是投影；research_knowledge 与 C3 才拥有正式采用 | 增加阅读版本出处，不改变候选权限，不重写历史采用记录 |

## 核心转换与失败边界

1. 新建材料产生首次阅读版本；原有首次阅读、整理和接收流程保留。换默认模型只影响新建版本。
2. reread 必须带文档、开始时当前版本、稳定请求键和原因；同请求重放不重复建任务，同一内容只能有一个未决重读。冻结当前选定的模型、提示配方和研究上下文。
3. 新版本从原件重新提取、逐块读和综合，产物独立。ready 表示机检达到待验收条件，不表示理解正确或正式采用。
4. activate 必须带已看过的报告 SHA、旧版本基线、审核人和理由；在 SQLite 单事务内校验并切换指针、保存验收。失败/过时请求保持旧指针；同一成功操作可安全重放，不允许倒序覆盖。
5. reject 只关闭未决候选，不动当前版本；运行中的任务不被假装已经取消。重试仍使用原版本冻结配方，不静默路由到新模型。
6. 查询/导出使用同一 SQLite 读快照，避免切换途中拼出新旧混合结果。历史报告、候选与证据明确带版本身份；原件目录名不是阅读结果权威。
7. 旧 SQLite 在持队列锁时先做完整备份，再事务迁移文档/任务与首次阅读版本；保留全部记录、任务尝试和原产物路径。迁移失败回滚，外键检查失败拒绝启动。不得直接改真实 Spark/M4 数据库。

- 退出当前报告固定路径、跨版本复用证据 ID，以及导出直接读取未验收报告的路径；旧实际文件不删除。

- 保留 Reader 的公共调用入口、首次阅读自动产出候选、retry、原件链接/回执恢复、旧配方阻塞、备份、HTTP 候选权限与 C3。保留原因与迁移结果须在 consumers-after.csv 逐消费者说明。

## 验收与交付

真实业务路径：接收→首次完整阅读→导出→显式重读→待验收时仍导出旧版→验收→仅导出新版；旧文件/证据可回查。用同一份有尾段与可定位内容的材料验证。

失败路径：模型失败重试、旧配方冲突、产物损坏、不完整覆盖、报告 SHA 不符、迁移中断、数据库提交前故障；旧有效结果不能失效。并发路径：独立进程同时创建请求、重复验收、读导出遇到切换、迟到/倒序替换；断言单当前版本和引用一致。
