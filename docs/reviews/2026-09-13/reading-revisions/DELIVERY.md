# 全文阅读版本：实现、验证与保留边界

修改前证据提交 `a6597cb`；实现提交 `707f852`，之后整合主分支 `b01fed7` 的已发布事实溯源修正，并在合并前整合 `212dfe3` 的新研究事实与缺口。规范登记更新为 `2026.09.13.5`。本轮收口全文 reader 的版本替换，不宣称全项目架构整改完成。

## 已完成

- documents 保留内容身份、原件位置与一个当前版本指针；执行状态、冻结配方、报告和验收移到 reading_runs。任务以阅读版本、阶段和块去重；同一请求重放只产生一个版本。
- `reread → inspect-revision → activate-revision / reject-revision` 共用 ReadingRevisions。新版本重新访问原件、生成独立提取和阅读产物；ready 表示待审，失败不影响旧成功结果。验收使用实际看过的报告 SHA 和旧版本基线，在一个 SQLite 事务内切换指针并保存审阅。较晚日期或更大模型不自动获得替换权。
- 导出只读 current_readings，并持有同一数据库快照；目录导出通过版本文件名及最后原子写入的 manifest 选择当前报告。新证据/陈述 ID 包含阅读版本，网站候选接收保留版本出处，正式采用记录不被替换。
- 旧 catalog 在持队列锁时先完整备份、再事务升级，保留任务尝试、来源、旧产物路径和原件；外键或孤立任务有问题则拒绝迁移，不能通过丢记录让升级成功。旧报告可回查，并保留“未经本轮质量验收”的标签。

## 已验证

本轮 Python 全量测试及具体环境见 verification.json，独立进程并发、失败重试、报告/块损坏、旧基线冲突、拒绝后迟到提交、数据库提交前中断、导出过程中切换、旧库回滚与占用保护，以及备份恢复历史版本均有实际执行用例。不存在“因为测试数量增加所以架构完成”的推论。

真实 Claude CLI 小样见 real-flow.json：781 字符的合成工程材料，首次阅读和显式重读都完整处理；旧版在 queued/ready 时继续导出，审阅后切至新版；请求与验收重放不增加材料份数。逐项核对七条引文、3000 W 仅为服务器功率小计、排除负载、未知条件和尾段候选限制。随后实际调用 receive-snapshot，将版本身份带入隔离接收端；仍为候选，没有 C3 采用。实际模型为 claude-opus-5，执行客户端为 claude-code；没有声称验证了第二个真实模型或行业代表集质量。

严格数据校验与知识结构检查通过。存量事实专项审计仍存在历史溯源缺口；主分支的事实内容与本轮版本功能独立，未补造来源或哈希。新增网站源码和真实 Spark/M4 服务分别验收，本地结果不证明远端数据库已升级。

## 消费者、迁移与旧实现退出

public-contracts.csv 逐项列公共实现、全部已知仓内直接消费者及结果；consumers-before.csv / consumers-after.csv 以 AST 导入、CLI 注册、SQL 和操作命令补齐可定位引用。初版基线的 50 条是文本匹配数；最终表从基线 Git 内容重新做 AST 与 SQL/CLI 检查，口径不同，不拿引用数量增减作为迁移成绩。未知库外脚本无法靠 Git 穷尽；Spark/M4 的已知入口明确保留未实机验证状态。

| 已退出的实现 | 替代 / 保留理由 |
|---|---|
| documents 上的 recipe、state、phase、priority、覆盖和 report_rel 写入 | 阅读执行只写 reading_runs；旧表形状仅出现在升级代码读取和迁移测试中 |
| jobs 仅凭 doc_id 选择执行配方与完成计数 | 所有执行、计数、失败重试和 OCR 调度按 revision_id 定位 |
| 新任务固定覆盖 artifacts/<doc_id> 下的报告与提取块 | 新版本使用独立 revisions 目录；已存在的旧文件路径保留，不移动、不删除 |
| 新阅读复用旧证据 ID | 新版以 revision_id 生成证据/陈述 ID；旧已引用身份保留 |
| 导出按未验收报告或目录中所有 JSON 文件认定当前结果 | SQL 当前指针和 manifest 唯一选择器；历史版本文件继续可回查 |
| OCR 查询被移除的 documents 状态列、失败时按文档释放版本占用 | 查询执行视图，领取、重试和失败释放使用相同阅读版本 |

保留 Reader 公共入口、原 retry 语义、原件 library 别名、接收回执与恢复逻辑、模型配置与 C3 采用边界。重读不重新搬运接收副本，不按新评分改名原件。旧视图链接只是原件入口，不是当前阅读报告权威。没有另加第二套 C3 或推理适配器。

file-plan.csv 覆盖修改前全部在册文件与计划；file-results.csv 覆盖最终全部路径，明确实际新增/修改/保留及计划偏差。未新增独立错误类，复用既有 Blocked/IntegrityError；这是计划内实现选择，相关文件明确保留。补充的审计表属于交付证据，不扩大运行规范来源。
