# 当前阅读权威：修改前证据与实施计划

基线 `083e3b10c4208cca40d8ce3394928e6691dc5cae`（包含 #171 的研究改动）。本计划与全文件清单先提交，再修改应用代码。用户已授权实现、合并、上线和本地同步。

## 现状和反例

reader 已以 catalog.documents.current_revision_id 选择一套当前全文结果，新版本须沿原件、冻结配方、逐块覆盖、报告及审阅替换。L2 则从 l2_read.jsonl 的录入/skip 回执产生 read_documents、documents_read、already_read 和 eligible_unread；零事实声明也算“已读”。这与 04/08/09 所说的完整阅读不是同一对象。L2 pack 不读取 catalog，已有合格全文阅读也会重复抽取，且不给终端当前报告及版本。两条路径缺少共同查询入口。

修改前可执行反例见 baseline.json；全部基线文件处置见 file-plan.csv；仓内消费者引用见 consumers-before.csv。旧记录是真实历史，不删除、不自动认定符合全文标准。

## 目标职责和数据权威

1. catalog 继续唯一管理原件身份、阅读版本和当前指针；不新增第二个“当前阅读”库。读取服务按完整 SHA 查询当前指针，在同一个 SQLite 快照内验证现有原件/配方/覆盖/产物封印。旧库、缺失库、待处理、旧未验证结果分别明确返回；损坏不得静默降级成成功。查询不初始化、迁移或写数据库，不加载/调用模型。
2. 把 ReadingStages 已有的产物路径、缓存身份、覆盖与封印检查原样迁至 materials.reading_artifacts，生成阶段、版本验收和新查询共同使用。没有新的一套质量算法，也不把机检当语义审核或 C3。
3. workflow.reading_results 提供当前结果查询及只读 catalog 状态。reader current 与 deep-read current 共用它；两者使用同一个 READER_DATA_ROOT / --data-root（L2 为 --reader-data-root），默认同一项目数据根。
4. L2 pack 如有验证通过的当前全文结果，复用其原件绑定的页块正文并提供报告路径、版本和 SHA，不重新抽取或生成第二份阅读结果。阅读包仍是独立任务输入；没有当前结果时保留现有抽取能力，明确“没有可复用全文结果”。损坏当前结果应报错，不能以重新抽取掩盖损坏。
5. l2_read.jsonl 的稳定存储格式和旧内容保留，只负责事实处理回执；公开 API、CLI 计数和相似提示改用 processed/processing。record/skip/pack --again 不改变 catalog 指针，不授予全文已读。模型身份仍分别记录实际执行器与模型，不绑定型号。

## 文件迁移、删除和兼容

file-plan.csv 覆盖全部基线文件及预期新增文件；未列为修改的源码、数据、第三方和历史原样保留。旧实现退出：ReadingStages 中产物校验方法的独立正文（改为继承同一产物责任）、L2 把回执称为全文“已读”的 API/CLI 字段。没有过渡性的双计数别名。旧 l2_read.jsonl 文件名和 operation_id 保留，以免重复处理和破坏恢复；其名字作为历史格式在文档说明。旧测试逐项迁移到正确概念，不删除失败/重试断言。所有新公共实现的消费者与结果另交付清单。

本轮不迁移真实 M4/Spark 资料，不从人工回执编造 report、覆盖、执行配方或阅读版本。只有已配置数据根可共享同一 catalog；跨机器尚未连接的副本仍须按受控同步/导入核对，不以本机接口实现冒充实际迁移完成。

## 验证与发布顺序

- 原反例：零事实回执不再增加全文完成数；已有完整结果开包不再调用抽取器，复用报告和正文末段。
- 实际流程：用隔离原件和真实 Claude CLI 创建 reader 结果，再经 L2 查询/开包/事实处理；原件、报告哈希和当前阅读份数不变。
- 失败重试：损坏封印、原件变化、缺失/旧库、权限/只读、发布失败；不得覆盖当前结果或自动迁移库。既有事实主提交/回执恢复测试继续通过。
- 并发与版本：独立进程激活新版本期间，查询及开包必须绑定一套快照；新候选、失败重试、换模型不替换当前；审核替换后后续查询才看到新版，旧包继续指向旧版本。
- 全量 Python、治理、严格数据、研究注册表和浏览器 CI；提交规范、影响清单和复审映射。合并后正式发布，核对源码/运行字节/HTTPS/admin/API，并把本地 main 快进到相同提交，逐个验证本地唯一文件未变化。

源码、测试、文档、数据配置、审计和第三方各自统计，不能把原件/运行库数量混入 Git 计量。测试、同步和上线各自说明完成范围。
