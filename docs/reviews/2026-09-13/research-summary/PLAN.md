# 3D 研究关联摘要：修改前证据

基线 311c246（#176 已发布，规范 2026.09.13.10）。本批补充投影职责，不改研究采用规则、BOM、材料或运行数据。

## 现状与真实反例

生产完整 /api/research 为 18,654,813 字节（gzip 2,177,256）。mountNodeResearch 在两场景的档案内调用 loadResearch 完整视图，却只显示问题/精确证据/关联任务计数及前 5 个相邻对象。线上控件/查看器交互通过时，研究面板仍显示正在读取；机柜页面验证结束仍有完整研究请求未完成。现有测试只等档案 h2/查看器，没有等研究数据就绪，因此此前通过不能证明研究内容已显示。另一次 page load 等待 90 秒超时；需区分主要组件就绪与后续纹理/GLB 资源完成，不推断为已证实的 GPU 或网络根因。

## 目标职责及唯一权威

- registry 提供共同研究状态组装（相同验证、采用/完成判断、任务用例）；完整视图继续增加 legacy 文档与 catalog。新增 /api/research-summary 是这份状态的关联字段投影，只传对象身份/名称、关系、问题与知识/任务的身份引用。
- 不在 Python 重新写“此节点关联哪些证据”的算法。两种视图继续交给同一个 JS buildResearchIndex.forNode；摘要保留其所有关联字段，但不携带正文、原文路径、产品目录、Reader 大型状态或材料全文。3D 不展示的文档列表不纳入摘要，不把空投影文档列表解释为没有原件。
- 请求生命周期共用一个按接口分开的加载器；失败不会永久缓存，旧失败不能清空新请求。mountNodeResearch 用独立挂载版本防止 A→B→A 的旧成功/失败写回，明确 loading/ready/missing/error，并提供失败重试。
- 两场景通过唯一 part-dossier→mountNodeResearch 消费摘要；完整工作台及现有外部 full API 消费者保留。不能用“减少响应”删掉真正需要完整数据的接口。

## 全文件迁移、旧实现退出

file-plan.csv 覆盖全部 689 基线文件，consumers-before.csv 是全部可观察引用。无新应用目录或平行数据文件。

| 原实现 | 处置 |
|---|---|
| mountNodeResearch→完整 loadResearch | 退出，改关联摘要 |
| full/summary 各自采用/任务/关联算法 | 禁止新增；共用研究状态与同一 JS forNode |
| pendingResearch 单实例失败清空逻辑 | 退出，按接口维护有身份的请求缓存 |
| 旧 mounted nodeId 只比字符串 | 退出，按挂载版本比对，失败也受同一约束 |
| 完整 API、工作台 buildResearchIndex | 保留：确实消费正文、材料和 catalog |
| renderer/纹理/GLB 加载及首屏数据获取 | 本批保留，仍独立待审阅；不以摘要成功宣称所有资产完成 |

## 验收

实际 HTTP 完整/摘要对比；对全部研究对象用同一个 JS forNode 比较问题/证据/任务 ID 与关系、跳转、隐藏对象语义；采用支持链/问题/任务关联夹具保证非零证据。摘要不构造 catalog、不含原文或大型 Reader 字段；缺失/坏快照仍用同一拒绝规则。失败→重试、同容器 A→B→A、迟到失败/成功以及刷新缓存替换验证。两真实场景必须等研究面板 ready，检查实际计数/邻接，不再仅等标题；确认不请求 full API。最终线上测量同一时点摘要体积并验证研究内容就绪。分类统计与公共消费者/退出结果修改后更新。
