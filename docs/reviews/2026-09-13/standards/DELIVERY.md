## 公共消费者和保留项

consumers-after.csv 逐行记录本轮涉及的公共实现的 62 条直接导入/CLI 目标引用及结果；consumers-before.json 是修改前快照。内部静态 Python 图为 87 模块、214 条边、0 环，见 dependencies.json。调用链的间接页面/API 消费继续沿原共享入口，完整仓库图的上轮快照见 architecture；本表没有把直接引用数当成独立业务流程数。

- review_valid 的直接调用者仍是 registry.validate 与 supported_adoption；后者驱动 completed_questions、question_tasks/current_tasks、研究快照及其 HTTP/CLI/阅读队列消费。没有另写第二套 C3 关闭逻辑。
- check_item、matched_workorder、tier、to_batch_rows 由 submissions.main/selftest 和 test_intake 消费；CLI 的 submissions 名称保留。兼容候选 CSV 与“成员精读”深度保留，因为后续合并/阅读队列仍消费它们；它们不是已采用知识。
- atomic_write/write_json/json_transaction 的全部仓内直接使用者保留同一实现。CommitUncertain 是 OSError 子类：已迁移的三类修改入口返回明确状态；其他消费者继续失败或按原日志恢复，尚未逐个验证提交后同步失败的业务恢复，不宣称全部已修复。
- verification_errors 仅由治理入口及专项测试消费；CI 沿原 governance --check 自动执行新检查。摘要登记由审阅者显式修改；这种约束只能揭示漂移，不能证明审阅者理解了所有规则。
- 库外入口：生产容器使用 manage.py serve；Spark 的 reader/receive/publish/news-sync units、M4 的管理命令仍使用同一包。新源码是否实际装到 Spark/M4 未验证；未知外部脚本和其他活跃终端无法通过 Git 清单穷尽盘点。
