# 来源冲突与修订进事实层：实现、验证与保留边界

本轮把 `framework/01_data_standards.md` §60 已经写下的一条规则落成机器检查：
**相容口径仍冲突时保留双方与原文，标记争议并进入 C3 A 档，不因来源等级或发布日期直接覆盖。**
规范文本未改（01 在册摘要不变），改的是事实层的键与 record 的放行条件。

## 为什么原来的做法是错的

上一版设计（本会话给出，未合并）按 `evidence.sha256` 判争议：文件不同才放行。
读表的一方用两组真实数据把它否掉了，而且否得对：

- 绿色数据中心白皮书一份 PDF 里同时引了 416.2 TWh 与 ICTresearch 的 1,103 TWh——
  **一个文件哈希、两个断言者**，按文件判会把真争议拒掉。
- IDC 对 2016 年已安装容量改过五版（2018-11 / 2019-01 / 2020-04 / 2021-03 / 2023-08）——
  **五个文件哈希、一个断言者**，按文件判会把自家修订标成来源争议、误送 A 档。

两头判反的原因是同一个：用文件身份代替断言身份。**谁说的，与从哪份文件读到，是两件事。**
§60 自己也写了「转载同一原文、两次 OCR 或两个模型复述不算独立来源」——这句话的主语就是断言者。

## 已完成

- 新字段 `asserter`（短机构名，必填，≤40 字）进 `claim_key`；报告名、期号、发布日期仍在
  `evidence.originator`。转述者不是断言者：花旗转述 IDC 的数，`asserter` 写 IDC。
- `claim_identity`（不含断言者）单独存在，它是「同一个问题」的键——冲突能被找到靠的就是它。
- 三种形状分开判：同断言者同键 = 重复（拒）；同断言者、`as_of` 带 `@版本` = 修订
  （要求 `supersedes`，旧版不覆盖）；不同断言者 = 争议（要求 `disputes`，双方并列，进 A 档）。
- 预测不适用修订要求：同一家在两个时点对同一年的两次预测是两个都还活着的判断（`forecast_key`
  原有规则不变）；同一家对历史实际值改口才是接替。
- `record` 写入前补反向链接 `disputed_by`，并把每对争议的**两侧值、断言者、原文定位并排打印**。
  A 档是所有者的活，把活递过去的人负责让它一屏可审。
- 1,562 条既有事实按 `evidence.originator` 回填 `asserter`，归一出 47 家；188 条为「未注明」
  （其中 148 条 originator 本就为空，40 条原文明写未具名）。
- 「未注明」与具名断言者在同一问题下相撞时按重复拒收：**宁可拒一条真的，也不让来源不明的数
  取得一个它没有的独立印证地位。**

## 已验证

`tests/unit/test_m4_l2.py` 新增 `AsserterTests`（9 例）与 `DisputeRecordTests`（2 例），
覆盖：两家不再撞键而仍共享同一问题键、同一家两次仍撞键、缺断言者被拒、报告名被拒、
「未注明」不得与具名并列、两家必须互相指认、修订要 `supersedes`、预测两版并列不要 `supersedes`、
反向链接落库、两侧并排打印。全量 `tests/unit` 通过；`validate --strict` 0 warnings。

## 未验证 / 保留边界

- **归一表是人写的映射，不是判定。**47 家断言者由 `originator` 前缀匹配得到，
  同一机构的不同中文译名或简称若未列入规则会落到「未注明」；188 条「未注明」需要人工回查原件才能补。
- **机器只判「形状」，不判「谁对」。**争议进 A 档之后的裁决仍是所有者的人工判断，
  本轮不提供任何按来源等级或日期自动取舍的路径，也不打算提供。
- 「未注明」按重复拒收是保守取舍：会拒掉一部分本来正确、只是没署名的数。
  代价明确——它们会以缺口形式留在 `data/metric_gaps.jsonl`，而不是悄悄进库。
- 既有 1,562 条的 `asserter` 未经逐条人工复核；跨库交叉验证（同一断言者在不同材料里的一致性）
  未做。
