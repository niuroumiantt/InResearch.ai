3. `serve.api_add_price` 写入 prices 后才运行校验器，失败再回滚。`MUTATION_LOCK` 只串行化一个 HTTP 进程；其他 CLI 不持它，原子 rename 也不能防止丢失更新。L2 用固定 `.json.tmp` 写事实，两进程会覆盖临时文件和旧快照。

5. 根目录 HTML、assets、自有代码和测试混在一起；不少脚本通过 `sys.path.insert` 获得隐式同目录依赖。运行命令散落在 HTTP 白名单、CI、Docker、Spark systemd、手册和测试中。
6. 现有主题脚本兼管偏好、导航、旧导航识别和面板包装。已有 13 页外观测试不能证明页面结构职责已经收敛。两套风格应共享结构和状态，各自拥有视觉令牌。

## 2. 目标职责与允许依赖

采用标准库模块化单体。文件夹按职责命名，不以执行机器或模型命名。模型、网页、CLI 都不能自行定义业务采用规则。

| 路径 | 拥有的职责 | 禁止成为的职责 |
|---|---|---|
| `src/inresearch/materials` | 内容身份、观察清单、原件收件、有效判读投影、移动及映射 | 事实采用、页面权限、模型配置 |
| `src/inresearch/knowledge` | 对象/问题/证据约束、事实口径、有效任务推导 | HTTP 请求解析、模型调用、文件搬运 |
| `src/inresearch/workflow` | 显式用例、阅读阶段和重试、队列与提交、派工 | 第二套事实规则、第二套账号规则 |
| `src/inresearch/delivery` | 报告/索引/快照的派生与导出 | 原件权威、采用审批 |
| `src/inresearch/adapters` | 可替换模型、文件格式、新闻及 3D 资产外部接口 | 业务事实自动采用 |
| `src/inresearch/interfaces` | HTTP/CLI 参数、身份、错误映射、治理入口 | 复制用例内的读改写规则 |
| `src/inresearch/storage` | 原子文件与完整事务、追加日志、移动恢复 | 对分数、角色、事实的业务判断 |
| `web/pages`, `web/components`, `web/themes`, `web/assets` | 页面入口、共享交互、Attio/folk 主题和静态资产 | 从 CSS/皮肤推断业务状态 |
| `tests/unit`, `tests/*.cjs` | Python 规则/流程验证和真实浏览器验收 | 运行时依赖 |

入口 → 用例 → 领域规则/端口 → 存储或适配器。工具型导出可读领域模型；领域代码不可依赖 HTTP。现存跨职责依赖逐条列入消费者清单，移动后仍反向依赖的项目不能标成架构完成。不为每个模块增设空接口、无用转发层或重复配置。

稳定 Python 包入口为 `inresearch`，统一命令为 `python3 inresearch.py <command>`，部署可使用 `python3 -m inresearch`。HTTP、CLI 的参数层调用相同用例。外部客户端不依赖内部源码路径。根目录 `data/`、`framework/`、历史证据目录保留稳定身份；网站的公开 URL 与源码目录分离，旧公开 URL 映射到迁移后的唯一文件。

## 3. 核心契约与数据权威

| 对象 | 唯一权威／写入者 | 派生消费者与替代规则 |
|---|---|---|
| 原件内容 | 内容 SHA-256 与受保护原件；接收用例 | 路径只是观察/位置。相同字节重复导入不重新阅读；不同字节创建新身份。M4 物理整理与 Spark originals 不可变的 scope 不合并 |
| L1 当前判定 | 追加判定日志 + `materials.records.current_results` | 所有队列、终端 pack、评分校准、报告、移动和导出共用。失败是尝试，不覆盖成功。历史成功版本可追溯；显式重评分才产生新有效判定 |
| reader 执行 | catalog SQLite 的 documents/sources/jobs/operations；阅读用例 | 租约/领取事务决定任务所有权，模型配置不是材料身份。配方冻结；失败可重试；完成资料不因默认模型改变重读 |
| L2 事实 | `data/facts.json` + metrics/data_contract；事实提交用例 | 原文定位、口径和冲突先校验，再提交；READ_LOG 是执行记录，不是事实权威。重复请求不重复追加事实；中断后可重放 |
| 采用知识 | `data/research_knowledge.json` 和框架对象/问题规则 | reader 运行快照只贡献候选，C3 仍需正式证据/依赖校验。换模型、分数高、日期新均不自动覆盖采用结论 |
| 工作任务 | 当前知识推导集合 + assignments 的人工状态 | CLI 与 HTTP 同一身份/状态检查；旧生成 workorders 只提供历史信息，不能挡住新任务 |
| 价格 | prices.json 与 data_contract | 完整文件事务内校验候选，不把无效候选暴露给读者。指标是可重建投影 |
| 账号 | 现有 users.json 和密钥所在位置；账号服务 | 本次不迁移生产账号/密钥。自助改密、管理员修改、CLI 保持同一事务和最后管理员约束 |
| 阅读快照 | reader 候选快照 + 已接收版本 | 校验后，锁内比较版本再提交。旧版本或重复提交不能覆盖；与正式采用存储分离 |
| 报告/网页 | `delivery.report` 等领域投影 | HTML、Markdown、docx 是消费者。生成时间和路径变化不冒充证据的新核验版本 |
| 运行配置 | deploy/models.json 的 role → profile | 暂用 Claude CLI，Spark/更大模型可替换；实际模型和执行客户端分别记录。每个配置只定义一次 |

文件写入契约：锁住完整读取→领域校验→写入；临时文件同目录且唯一，先 fsync 文件，原子替换，再 fsync 目录。错误不改变旧权威文件。锁覆盖线程与进程；追加日志允许恢复未完成尾行，内部损坏必须报错。多文件更新必须指明主提交点和可重放派生记录，不能假称多个 rename 构成一个事务。

版本替换契约：区分尝试、有效结果和正式采用。旧成功结果在重试失败后继续生效。显式重读请求记录被替代版本及原因；成功验证后才切换当前指针，过时基线提交返回冲突。reader 完成资料的全文重读替换需要可恢复的版本目录和事务，本项若尚未落地须保留为未完成，不能用 L1 选择器替代证明。

## 5. 六阶段顺序与验收

| 阶段 | 交付内容 | 通过条件 |
|---|---|---|
| 1 核心契约 | 正式规则、身份/结果/错误/写入约束 | 冲突情景有确定结果，权威来源无双写歧义 |
| 2 用例和写入 | 共享命令与完整事务，全部消费者迁移 | HTTP/CLI 同一操作得到同一结果；并发写不丢失；无效数据从未成为当前文件 |
| 3 拆分脚本 | reader、L2、Office 按真实职责分离 | 调用链可解释、无万能上下文代理、既有流程保持；剩余巨型脚本逐项披露 |
| 4 目录迁移 | 包、页面、测试、部署入口及规范全迁移 | 全文件清单闭环；没有意外旧路径依赖，数据和公开链接不丢失 |
| 5 页面结构 | 显式共享 shell，主题只管外观 | 13 页 × 两风格 × 明暗 × 桌面/手机；权限、业务状态、导航、表单和错误状态正确 |
| 6 删除旧实现 | 旧入口和重复实现真实删除 | 无运行消费者仍依赖旧实现，历史引用有身份；删减统计排除移动和生成审计文件 |

业务验收矩阵：

1. 用实际文件完成接收→SHA 去重→登记→抽取→判读→候选→报告/网页，重复接收不产生第二套有效结果；实际 Claude CLI 调用另记，固定模型替身只用于可重复故障注入。
2. 模型超时/坏 JSON/提取中断→失败记录→重试；成功结果继续可读，任务不丢失，重试预算有界；损坏日志内部行不可悄悄跳过。
3. 两个独立进程并发派工/价格或事实提交；同主键冲突与不同主键并发分别验证；读者只能看到合法旧/新版本。
4. 快照新旧倒序到达、重复请求、重评分失败再成功，以及采用依赖失效后的版本处理；明确区分 L1 与 reader 完成重读替换。
5. 独立服务中以真实 HTTP 请求验证登录、权限、CLI/HTTP 用例一致与静态资源边界；不修改生产账户。实机部署是额外验收，不代替架构测试。
6. 治理 --refresh/--check、strict 数据检查、研究检查、Python 测试和浏览器回归；所有结果与实际命令/日志关联，未跑项标“未验证”。

完成状态分别登记：**已完成**表示实现/迁移已存在，**已验证**表示所述场景在注明环境实测，**未完成**包括遗留架构、远端消费者和无法进行的实机验证。文件夹变多或代码行净增本身既不是成功也不是失败；应同时报告被消除的职责重复、净新增契约/测试/审计代码、仍存在的复杂度。
