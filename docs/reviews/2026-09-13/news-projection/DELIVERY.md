## 实现完成

registry 的 `_snapshot_inputs` 和 `_reader_state` 为完整研究与新闻视图共同使用：
现行框架/正式知识验证、候选隔离、框架/身份冲突退化和接收时间新鲜度仍只有一份。
`build_news` 不构造 catalog/tasks；`/api/news` 只给出必要状态和最多 80 条显示字段。
源新闻、模型/来源元数据保留在原快照和永久台账，不复制成第二份新闻结果。

HTTP GET → build_news → 共同输入/状态 → homepage/ops 共用组件，是新消费链。
原 GET /api/research → build_snapshot → research-graph、registry --snapshot 和已有外部客户端
继续保留；旧新闻对完整 API 的依赖完全退出。具体已知源/测试/指南引用逐行列在
public-consumers.csv；文件处置与旧代码保留原因见两个对应 CSV。未知外部客户端未声称穷尽。

新闻更新设置 20 秒超时；新请求取消旧请求，迟到结果按请求身份丢弃。失败保留最后展示并
标明失败，重试成功恢复。未连接、等待同步、未初始化、损坏快照和延迟分别展示。
Attio/folk、中文标题、安全链接、北京时间和移动端结构保留。

## 已验证

- 本机 998 项单元/业务测试通过（21.347 秒）；全部 9 组浏览器回归通过。
- 真实 HTTP 接收 100 条新闻快照后只投影最近 80 条；禁止构造 catalog/tasks 的测试通过，
  私有路径和无关字段不进入新响应，完整 API 的状态相同，读取未改变存储字节。
- 缺快照、旧接收时间、新快照替换、重复/倒序接收、损坏/框架冲突与身份碰撞共用原规则。
  新闻字段形状损坏返回明确 503 并保留快照。
- 浏览器验证首页/ops 不再轮询完整 API；故意让旧请求忽略取消并晚到，仍不能覆盖新结果；
  离线失败保留旧内容、重试恢复、未连接/损坏/延迟提示通过，两种皮肤和移动端通过。
- 本机无 Reader 连接的同一基线：完整响应 2,907,346 字节，新响应 95 字节；这是明确的空快照
  场景。非空场景由 100→80 条真实 HTTP 用例验证，生产实际体积在上线后另测。
