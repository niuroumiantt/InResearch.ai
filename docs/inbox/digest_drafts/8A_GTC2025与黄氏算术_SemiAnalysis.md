## 拟新增 framework 级规则：引用 Nvidia 官方数字前必须过「黄氏算术」三道检查

- **状态**：draft ｜ **修订**：2026-08-15 ｜ **触发器**：entity:nvidia（每次发布会）、periodic:180d
- **结论**：Nvidia 官方数字有三条系统性口径偏移，作者称之为「黄氏算术」（Jensen Math），每年还会新增一条。本研究引用任何 Nvidia 数字前必须逐条检查：
  1. **算力**：头条 FLOPs 按 **2:4 稀疏**计量（现实中无人使用），真实指标是稠密 FLOPs——例如 H100 的 FP16 稠密算力为 **989.4 TFLOPs**，却被标称为 **1979.81 TFLOPs**。即所有 Nvidia 标称算力需先**除以 2**。
  2. **带宽**：按**双向**计量——NVLink5 标称 **1.8TB/s**，实为 **900GB/s** 发送加 **900GB/s** 接收之和，而网络行业标准是标**单向**带宽。
  3. **GPU 数量**（2025 年新增）：自 **Rubin** 起按封装内的**裸片数**而非封装数计量——因此第一代 Vera Rubin 机架称为 **NVL144**，尽管其系统架构与 GB200 NVL72 类似、用同样的 Oberon 机架、**同样是 72 个 GPU 封装**。作者预言这将成为长期需反复澄清的困扰。
- **论证**：
  - 这三条不是偶发失误而是**持续的计量惯例**，且每年演进，因此必须作为常设检查项而非一次性提醒。
  - 第三条的危害最大：它直接破坏跨代际的「每机架 GPU 数」时间序列。NVL72 与 NVL144 听起来是翻倍，实际封装数相同——任何按机架 GPU 数推算容量、功率或采购量的模型都会因此**系统性翻倍高估**。本研究既有的「芯片数不折算 MW」纪律必须扩展为「**封装数与裸片数必须分列**」。
  - 与本库 Blackwell Perf TCO（2024-04）一篇的「按硅面积归一化」构成互补：前者管的是**分子**（性能怎么算），本条管的是**分母**（数量怎么数）。
- **证据**：
  - [S3/机构一手研究] SemiAnalysis《NVIDIA GTC 2025》2025-03-19 — 本地文件 `8A_2025_GTC2025与黄氏算术_SemiAnalysis.pdf`
  - [数据层] companies:nvidia
- **口径提醒**：本条本身即口径规则，建议直接并入 framework 的引用规范，而非仅作为某个模块的 Finding。
- **待办**：检查知识层现有条目中所有引用 Nvidia 算力与带宽的数字，确认是否已按稠密/单向口径换算；NVL144 相关表述需在 Rubin 出货后统一为「72 封装 / 144 裸片」。

## 拟补强 M06-F? Blackwell Ultra B300 以牺牲 FP64 换取 FP4/FP6，标志数据中心 GPU 与 HPC 正式分道

- **状态**：draft ｜ **修订**：2026-08-15 ｜ **触发器**：entity:nvidia、periodic:180d
- **结论**：B300 相对 B200 提供高出 **50% 以上**的 FP4 密集算力，内存升至每封装 **288GB**（8 堆 12-Hi HBM3E）但带宽仍为 **8TB/s**；实现方式是**削减（但非全部移除）FP64 ALU 并替换为 FP4 与 FP6 ALU**。作者指出双精度主要服务 HPC 与超算而非 AI，这对科学计算社区是坏消息。GB300 不再以整板出售，而是以搭配 Grace CPU 的 SXM 模块与 BGA 两种形态供货。
- **论证**：
  - 这是一次明确的**架构取舍信号**：Nvidia 在同一颗芯片上不再试图兼顾 HPC 与 AI，而是把晶体管预算投向低精度推理。对采购方的含义是——用 AI 代际 GPU 跑传统 HPC 负载的性价比将持续恶化，两类需求的硬件路线开始分叉。
  - 与内存的组合看更清楚：容量翻升而带宽不变，说明优化目标是**长序列推理的 KVCache 容量**而非吞吐——与本库 GB300 一篇（12-Hi HBM3E、288GB、8TB/s）及推理时扩展的叙事完全一致。
- **证据**：
  - [S3/机构一手研究] 同上；交叉印证本地文件 `7A_2024_GB300与推理经济_SemiAnalysis.pdf`
  - [数据层] companies:nvidia
- **口径提醒**：「50% 以上」为 FP4 密集算力口径，不可与 FP16/BF16 的代际提升混比（沿用上一条的检查表）。
- **待办**：需跟踪 HPC 用户的实际迁移路径——若 FP64 持续被削，超算采购是否转向 CPU 或专用加速器，这会影响 M06 的市场分层。

## 拟补强 M15-F? 推理时扩展使 token 需求非线性膨胀：推理模型 token 量 20 倍、算力 150 倍

- **状态**：draft ｜ **修订**：2026-08-15 ｜ **触发器**：periodic:90d
- **结论**：Nvidia 给出的支撑数字为：模型现已需要超过 **100T token**，推理模型的 token 量是 **20 倍**、算力是 **150 倍**；测试时计算每次查询消耗数十万 token、每月数亿次查询；后训练每个模型消耗数万亿 token，且有数十万个后训练模型。据此 Nvidia 主打**推理成本 35 倍改善**以支撑推理与智能体的经济性部署，口号也从「买得越多省得越多」变成「省得越多买得越多」。
- **论证**：
  - 作者视之为杰文斯悖论的典型案例，并直接回应市场对「DeepSeek 式软件优化叠加硬件进步导致 token 过剩」的担忧：价格确实影响需求，但随着智能价格下降，智能能力的前沿持续外推，需求反而增加。
  - 类比论证很有力：争论光纤泡沫时期每包连接成本下降、却忽略互联网应用最终对社会与经济的影响是错的；关键差异在于**带宽需求有上限，而智能需求随能力提升趋于无限**。
  - 本条与本库 DeepSeek 辩论（2025-01）、ClusterMAX（2025-03）、扩展律（2024-12）三篇同向，四者共同构成 M15 看空情景的反方证据链。
- **证据**：
  - [S2/company] Nvidia 在 GTC 2025 主题演讲给出的 token 与算力倍数（经 SemiAnalysis 转引与评述）
  - [S3/机构一手研究] 同上
- **口径提醒**：20 倍 / 150 倍 / 35 倍均为 **Nvidia 自身口径**的公司主张，作者转引但未独立验证，属 S2 级证据；不得与本研究的独立测算并列使用，也不可用于乘算容量。
- **待办**：需寻找独立来源验证「推理模型算力 150 倍」这一倍数的定义边界（相对哪个基线模型、哪种任务）。
