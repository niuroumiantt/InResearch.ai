## 4. 两个研究循环：前两轮讨论的保留摘要

### 4.1 持续建库

全产品发现 → 文件完整性与来源登记 → Macmini 保留原件 → Spark 清单验收与永久归档 → 格式解析 → 完整阅读 → 参数/关系/主张/证据候选 → 可查询研究索引。

- 抓取范围不受现有研究问题和少量产品计划限制；未映射对象保留待登记状态。
- 厂商分类与研究分类并存。保存官网分类路径及版本；另以文档类型、适用范围、内容用途、研究对象和问题进行多维关联。跨产品与营销不是低价值或未知材料的同义词。
- Macmini 的 blobs 保存原字节，library 是可重建视图，ledger 保存来源、版本、队列与回执，deliveries 保存交付批次；原件、数据库和凭据不进 Git。
- 批次以 partial 状态传入 Spark incoming；逐文件检查 SHA、大小、来源和清单，永久登记后回执。中断可续传，重复投递不重复建内容；无接收回执不能称交付完成，不自动删除 Macmini 原件。
- 格式解析由程序执行，阅读由 reader 调用配置模型。文章完整深读；工作簿与工程表格按类型完整普查。不执行宏、外部链接或材料内指令。
- 每份阅读包包含：文档档案与覆盖地图；产品/配置；参数与测试条件；原理/接口/限制/主张；精确原文证据；冲突与缺口。
- 参数区分额定/最大/典型/实测，标配/选配，单部件/节点/整机；缺失、不适用、解析失败不当零。系列上限不能自动继承到所有型号。

### 4.2 按需研究

用户指定对象、角度、条件、日期与输出 → 结构化查询 + 全文检索 + 可选语义检索 → 比较适用性 → 程序计算 → 证据支持的论证 → 报告/表格/关系图/缺口 → 审核采用与任务回流。

- 相同积累可以支持选型、接口、运维、能效、基础设施约束、供应链等不同角度；不能只存一篇固定摘要。
- 新角度缺字段时，回到原文定向补充提取并保存版本依据，不根据常识补值。专题分析不覆盖全文 reader 的当前结果。
- 全部符合条件的产品应通过结构化范围枚举，不能以语义 Top-K 片段冒充全集。
- 跨行业分析需要相应行业材料、单位/边界/工况映射。产品 spec 不能独自证明实际价格、交期、市场份额或运行可靠性；其他供应方向应接入同一证据底座。
- 快速探索可使用明确标识的候选与假设；正式采用继续走 C3。下载、阅读和研究问题关闭分别计量。
- 每次分析保存问题、查询范围、资料截止点、输入版本、计算、证据、输出及依赖，使成果可复跑、可复核、可受变更影响分析。

### 4.3 建议的数据职责

| 层 | 存储与职责 |
|---|---|
| 原件与阅读运行 | 复用 Spark originals、catalog/catalog.sqlite；documents/current_readings 等继续拥有原件与当前阅读身份。 |
| 提取/阅读产物 | 版本化 extracted/artifacts；保留正文、表格、参数与关系候选、报告和精确定位，不只保存摘要。 |
| 研究查询层（拟新增） | `research/index.sqlite` 作为可重建查询投影：产品/配置、参数观察、关系、主张、证据、适用范围和分析索引；不另立正式知识权威。 |
| 正式知识 | 沿用 facts、research_knowledge 及其口径、审核和发布流程。 |
| 专题运行档案（拟新增） | 持久保存每次研究计划、输入 manifest、计算和输出；索引可重建，原始分析档案不是可随意清理的缓存。 |

反补 inresearch 的四条路径：产品档案补全；对象/问题证据补充；缺口与冲突任务；审核采用后的回答与研究交付。任务集合沿用 registry.current_tasks/task_board，不另起竞争任务树。

## 5. 多站点代码：共享引擎、组合模式、厂商适配

建议在 fetchspec 一个产品资料采集仓库内实现，不按公司建立 200 个 repo，也不把 reader 和研究采用复制到各适配器中。

| 层 | 共用职责 | 网站特有部分 |
|---|---|---|
| 执行核心 | 持久队列、租约/心跳、限速、重试、HTTP 条件请求、流式下载、断点安全、内容校验、归档、清单和交付回执 | 无厂商 CSS、型号命名或数据库私有写法 |
| 发现模式 | sitemap、普通目录链接、HTML 表格、分页/游标 API、资源库筛选、已授权浏览器渲染流程、文件接口 | 模式参数及被选择的具体组合 |
| 站点档案 | 统一配置 schema 与校验 | 主机/路径范围、入口、地区/语言、分页规则、字段映射、访问身份引用、频率及限速 |
| 厂商适配器 | 统一输入输出与测试契约 | 特殊端点、型号/修订解析、特殊分站、选择器和必要的浏览器操作 |
| 研究解释 | 统一产品/文档/证据/变化事件合同 | 厂商术语与编号映射；不直接修改正式研究知识 |

同公司拆多个 `site_profile`：如主产品目录、资源库、支持站、旧产品站、地区站。以上是建议的逻辑角色，不表示已验证 Supermicro 有这些独立域名或相同 API。每个 profile 可选择不同发现模式，但输出统一。

适配器只产出类别、产品、文档链接、变更通知和发现边，并报告分页/范围覆盖；请求交给核心执行，不私写 blob、台账和重试循环。公共边界包含：

- 发现项：company_id、site_profile_id、source_url、discovered_from、原始标签、原厂标识、分类快照、语言、候选适用关系及提取依据。
- 请求项：受控范围、请求变体、访问身份引用、期望内容、优先级、幂等键。凭据和带秘密的链接不进入普通日志/网站快照。
- 结果项：最终地址、状态、响应元数据、内容 SHA、格式、完整性、解析器与规则版本。
- 覆盖项：本轮成功/失败/未完成的类别、分页和端点；任何附件数量预算只限制本轮，不把剩余项当不存在。

优先解决具体站点：先跑通 Supermicro 的真实特例，并保存可复现测试；在其他站点出现相同机制时抽出复用模式。不能只凭都使用某 CMS/前端框架就共享未经验证的解析器，也不追求预设复用百分比。保留少量局部特殊代码，比复制整个引擎或构建万能配置语言更合适。

公共模块升级需让已有站点样例回归通过。规则、适配器、提取器版本随运行冻结；线上结构漂移应成为 schema_drift 异常，而不是成功返回零个产品。

## 6. 稳定身份：不要把 URL、名称、产品与版本混为一物

| 身份 | 含义与关联 |
|---|---|
| 公司 / 分站档案 | 谁发布、通过哪个来源范围观察。 |
| 产品实体 | 优先使用有依据的原厂型号/料号；显示名是可变属性，不单独承担唯一身份。 |
| 硬件修订 / 配置 | 同一型号可能有不同板本、组件、选件、批次适用性；有证据才建立实体和适用关系。 |
| 逻辑文档 | 一份手册/规格书/通知的持续身份，参考文档号、类型、语言、产品范围；不只按标题自动合并。 |
| 文档版本 | 厂商标称 revision、日期、语言/格式变体、内容 SHA；revision 缺失或重复也保留每份不同字节。 |
| 内容 blob | 完整 SHA-256 对应原字节；下载名与扩展名不决定内容身份。 |
| 来源观察 | URL/请求变体、原始链接与下载名、来源页、抓取/核验时间、响应头、状态以及取得的 blob。多观察可指向同一 blob。 |
| 变化事件 | 发现、改名、移动、字节变化、规格变化、PCN、站内缺席、不可访问、正式 EOL 等分别记录。 |

内容相同只合并物理字节，不丢掉新来源、文件名、所属分类或产品关联；已有阅读能否继承仍按 SHA 和阅读标准判断。新来源并不自动授权把旧证据适用于新产品。

同一内容在两个格式/语言中出现，不按语义相似去重。PDF 与 DOCX 通常是不同字节的表达版本，不能仅因转换关系认定后一份 supersedes 前一份。

原件路径稳定且不可覆盖；原始文件名永久记录，library 为带短 ID/版本的可重建入口。既有真实目录如需迁移，要先盘点引用、备份和回执，不在讨论阶段搬动。

## 7. 持续观察：自动与手动用同一套运行机制

建议提供三种有区别的检查，而不是一个含义模糊的“刷新”：

1. **增量检查**：检查已知产品、资料、通知入口及到期的已知附件；发现新项并重新验证到期资源。父页面没有变化，不豁免该页所链 PDF 的独立检查。
2. **全站复查**：在登记的公司/分站/语言范围重新枚举目录、矩阵、分页、资源库和旧产品入口，对照上一份完整清单；未变附件仍可走条件请求，不等于全部重新下载。
3. **强制内容核验**：对所选范围绕过本地“未变”捷径，重新获取允许访问的完整内容并算 SHA，用于不可靠服务器标记或人工怀疑同名更新；不绕过网站访问限制。

频率可按分站与近期变动率配置；例如日常轻查、每周完整普查、较低频内容审计只是起始建议，不是本轮已经开启的任务。未知更新时刻意味着只能在下一次成功观察发现，不能承诺实时或恢复首次采集之前的全部历史版本。

自动与手动共享任务队列、优先级、幂等键、主机/共享 CDN 限速和单范围执行租约；手动全站请求与正在运行的相同范围合并或排队，不双跑。中断保留游标；超额/磁盘不足挂起并报告，不删原件腾空间。

每轮保存 scope_id/version、分类快照、解析器版本、开始/结束时间、端点和分页覆盖、状态及清单。范围或解析规则改变时明确映射与新基线，不能直接用不可比清单推断产品减少。

## 8. 不重复与不漏更新的具体语义

| 观察到的情况 | 处理 |
|---|---|
| 同 URL/请求变体，服务器返回可用的未修改响应 | 更新核验时间与校验依据，复用已有内容；不是重新取得字节的证明。 |
| 同 URL、同文件名，但取得内容 SHA 不同 | 新建不可变内容版本，进入差异检查；旧版保留。 |
| 新文件名、后缀、地址或新下载表达 | 建立新的发现/观察任务并取得核对，不凭相似名称跳过，也不跨 URL 盲用旧缓存标记。 |
| 取得新地址内容后 SHA 与旧件相同 | 增加来源、别名、适用关系，共用原字节；不重复永久保存或无条件重读。 |
| SHA 不同，但抽取的文字相同 | 两份原件均保留；可能涉及元数据、排版、图或表，不能以文本相同证明文件等价。 |
| 文档号/revision 相同，字节或规格不同 | 保存“同标称版本内容变化”，核验静默修订、生成噪声或分站差异，不静默覆盖。 |
| 新 URL 返回与已有内容相同，但名称/适用对象有变化 | 保留该变化事件；重复字节不等于业务元数据无变化。 |
| 403、429、登录页、超时、解析失败或分页不全 | 本轮范围 incomplete/blocked，不将未看到的产品判为消失。 |
| 完整且可比的枚举中不再出现 | 记录 missing_from_listing，复查其他入口；不删除原件、不推断停产。 |
| 重复检查后地址 404/410 或有正式撤下信息 | 可标不可访问/已撤下；产品 EOL 仍需单独通知或依据。 |

传输去重与存储去重是两个目标。HTTP 条件请求能节省重复传输，但 ETag 不是内容 SHA；弱 ETag/时间标记和不可靠服务器不能证明逐字节一致。无可靠验证器时，为避免漏改必须定期获取内容后比较，无法同时绝对保证零重复网络字节和不漏同名变化。相关语义依据：[RFC 9110 §8.8、§13.1、§15.4.5](https://www.rfc-editor.org/rfc/rfc9110.html)。

实现需把验证器绑定到资源与请求变体（语言、Vary、访问身份等），不跨站复用；保留有意义的 query 参数，不能统一去掉版本/下载 ID/语言参数。仅可对已测试的跟踪参数或签名表达使用站点专门规则；敏感签名留在受控本机，不发到公开投影。

断点续传要验证表示未变化；否则重开临时文件，不能把旧文件前半与新版后半拼接。错误 HTML、登录页和截断响应不能因为状态 200 或后缀 PDF 就入库为有效原件。清理临时文件也不能触碰已验证的唯一原件。

## 9. PCN、规格修订与产品演进

至少分三条版本线：产品/硬件修订、规格/手册文档修订、PCN/ECO/EOL 通知；另外还有我们每次观察和阅读的版本。它们有关联，但不是同一个序列。

PCN 建议保存通知号及自身修订、发行方、通知类型、涉及料号/型号/板本、变更前后、原因、发布日期、生效日期、批次/序列号适用条件、兼容/替换要求、关联文档与原文证据；未披露字段保持未知。通知可能涉及多个产品、多个文档，也可能只有部分产品配置。

三种时间明确分开：厂商发布日期、厂商声明的生效/适用时间、我们首次/再次观察时间。抓取日期不能充当产品变更生效日期，也不能据文档 revision 猜硬件 revision。

不能假设所有变更都有可公开抓到的 PCN。通知可能只有经授权的门户或用户投递件；网站也可能静默替换规格。未找到 PCN 时记录“待找通知/生效条件待核”，不否认已观察到的内容变化，也不编造正式 PCN。

官方支持站存在具体 PCN 线索：[Supermicro FAQ 28511](https://www.supermicro.com/en/support/faqs/faq.php?faq=28511)讨论了某部件的 PCN 与能力更新；FAQ 本身不是完整 PCN，也不能用于推断所有产品均有公开 PCN 列表。本轮未定位或验证全量公开 PCN 接口。

差异分三层保存：

- 字节层：完整 SHA 是否变化，原件不动。
- 文档层：页/节/表/单元格/图片及 revision 标识变化；格式噪声与正文变化分别标注。
- 研究层：参数、配置、接口、限制、兼容和生命周期变化；检查是否影响既有比较、假设、计算和回答。

差异用于排序和定位，不能自动免除新内容按现行标准阅读，也不能自动替代正式采用结论。疑似同一文档的新旧件先建立候选关联；正式替代须有相同范围和证据。回退到曾经出现的旧 SHA 也要记新观察，不改历史顺序。

产品页应分别显示：最新观察到的材料、厂商标称版本、当前已知适用配置/修订、inresearch 当前采用依据。不能用一个“latest”覆盖所有含义。

## 10. 变化如何回流研究

变化事件 → 对照旧/新原件与配置 → 形成候选差异及通知关联 → 查证据/参数/计算依赖 → 生成去重的复核建议或任务 → 研究审核 → 必要时更新正式知识与受影响交付。

- 无变化只更新核验时间，不重建文档、不重复阅读、不刷出新问题。
- 同 SHA 的新关联只做适用关系核验，不无条件把它当新内容。
- 新 SHA 按现行阅读标准处理，并保存新旧差异；后续专题分析使用明确版本。
- 来源变化本身不直接改写已发布 facts、知识和历史报告；复核建议与正式撤回/采用分开。
- 历史报告锁定原输入，可回答“当时依据什么得出结论”；当前分析可筛选截至日期、型号、硬件修订、地区和候选/采用状态。
- 新版的生效范围不清时新旧并列，避免把将来的配置能力套到已出货设备。

## 11. 显性的站点观察与版本界面（拟建）

放在现有供应中心下的“站点与更新”，不另开竞争管理台。公司总览聚合多个 site_profile，详情可以下钻：

- 站点范围/语言、规则版本、访问状态、自动观察开关与频率、最后尝试时间、最后成功增量/全站时间、下次计划时间。
- 已发现分类/产品/文件、已验证内容数，新增/字节变化/改名/目录缺席/受阻等事件；传输节省与存储去重分开。
- 本轮未完成入口、分页、附件和失败原因；显示“完整范围”与“部分结果”，不能只挂绿色成功标记。
- 操作：检查更新、全站复查、选定范围内容核验、重试失败项、暂停/恢复。执行走持久任务队列，网页请求不直接跑长爬虫。
- 产品/文档时间线、原文与版本差异、PCN 与适用范围、影响的研究问题/报告、待审核项。
- 多次无变化的普通成功检查保留台账，默认不制造研究待办；规格变化、重要 PCN、覆盖异常和持续失败才形成可操作提醒。

网站展示经权限控制的派生投影，原件不默认公开。自动开关、调度器和运行回执要分别验收，UI 有按钮不代表后台已接通。

## 12. 建议的实施顺序与验收情景

1. 在 Supermicro 上完成可追溯的全目录/多入口发现，找出真实特殊规则；同步定义来源、产品、文档版本和观察事件合同。
2. 公共核心实现持久队列、完整性、来源多挂、内容版本、增量验证、可恢复批次与回执；将现有台账备份后受控迁移，不覆盖唯一数据。
3. 用不同网站形态验证模式复用；只有已证明相同的机制进入公共模式库，站点仍有自己的回归样例。
4. 接入自动与手动观察、全量可比快照、变化事件和站点 UI；再接 PCN/差异与研究依赖复核。
5. 用真实材料贯通阅读、查询、两个不同研究角度的输出和任务回流；源码上线、Macmini 定时运行、Spark 接收/阅读和网页状态逐项验证。

以下是拟新增的验收情景，不是已执行测试：

- 同地址未变：条件检查不重复创建内容和阅读任务。
- 新名/新后缀/新地址同字节：取得核对，新增来源/别名，只有一份永久 blob。
- 同名同 URL 改字节，含正文修改、仅图表修改、无服务器验证器、错误验证器：都能通过对应审计发现并保留版本。
- 文本相同但图表不同、新标称 revision、同 revision 不同内容、格式/语言变体、网站回退旧文件分别登记。
- 产品名不变但硬件 revision 或 PCN 适用批次变化：不改写其他配置的参数。
- 全站扫描失败/分页被截断/登录页假 200/解析器漂移，不触发产品删除或 EOL。
- 完整清单缺席、链接移动、临时 404、正式 EOL 为不同事件，历史原件始终可查。
- 自动/手动同范围并发、运行中断、磁盘不足、传输校验失败、回执重放和恢复不丢文件、不重复写入。
- 变更能列出受影响研究输入；未审核不覆盖正式采用；旧报告可以按旧 manifest 重现输入。
- 公共解析模式变更时，已有站点 fixtures 回归；样例须脱敏并遵守许可，不把整份第三方 PDF 或登录态塞入 Git。

## 13. 需要在实际接入时明确的边界

- 已授权范围与材料许可、地区/语言、历史产品入口、PCN 可访问渠道；无法访问要显式记缺口，不承诺全站之外的隐藏资源。
- 日常/全站/内容审计频率、磁盘与带宽预算，按真实运行测量调整；不能从一次 4 PDF demo 估计 200 家公司的稳定吞吐。
- 缺少正式 PCN 时的补证渠道，以及未知/重用料号的产品身份人工核验。
- Office/图表提取与当前 reader 的统一覆盖合同、模型实机能力、候选证据与正式采用边界。
- 源站许可属于实际接入条件：本轮查阅的 [Supermicro 网站条款](https://www.supermicro.com/en/about/policies)包含个人/内部/非商业、单副本及网络使用等限制；公开可访问不等于已获得批量镜像、跨机器处理或原件发布授权。启动全量运行前需核对适用许可或书面授权，不以 robots 可访问代替使用许可判断。本条记录来源限制，不作法律结论，也不授权删除已有资料。
