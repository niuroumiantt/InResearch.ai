# 成员投递口

本页是操作指南。C3 唯一规则见 [01 口径手册 §4](../../../framework/01_data_standards.md#4-来源冲突与证据采用)，结构见 [submission schema](../../../data/schema/submission.schema.json)。

一次投递是一个目录和一份 submission.json。原件通过约定材料通道交付，不将原件、账号或密钥写进 Git。投递记录不证明原件已收到或全文已读完。

运行 `python3 manage.py submissions [投递目录]`：验证字段类型、M01–M15、年份整数、自评分 1–9、来源等级及不少于 200 字的摘要。自评 ≥5 须附 key_numbers 或 key_statements；每个数字需单位和原文定位，每个非数字陈述需类型、原文引文与定位。没有数字不构成拒收理由。

同名仅提示待核对，不按标题或路径拒收。真实身份由材料接收流程核对原件 SHA。同名异文保留不同内容版本；相同内容的多个来源关系仍保留。

workorder 使用当前任务的 wid，并与声明模块和材料模块匹配。未知、已结束或不匹配的工单退回并注明原因；留空的中分材料保持待匹配候选。拟改写旧结论填写 replaces_record_ids，进入 A 审核；此声明不会直接修改旧结论。

`--accept` 只输出 B 待审核及 C 存档候选 CSV，depth 仍为“成员精读”，不能上正式证据链。该命令没有执行模型审核。批次按候选导出内容标识，重跑同一批不新增文件，同一天另一批不能覆盖前批；此标识不代替原件 SHA。A 与待匹配项留在审阅卡中，完成对应审核/匹配后再推进。

机检通过率只表示格式和登记通过；研究命中率须以实际解决的当前缺口另行评价。
