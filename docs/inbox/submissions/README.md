# 成员投递口

一次投递 = 一个目录 + 一份 `submission.json`（格式见 `data/schema/submission.schema.json`，
可直接复制 `_template/`）。

**材料本体不进 git**（二进制不进 git 的铁律不变）——投递单里写文件名，
材料本身通过所有者约定的渠道传递。git 里只留结构化投递单，这样云端会话才读得到。

提交后跑 `python3 manage.py submissions` 出机检结果与三档分流。

## 你交的是素材与登记，不是结论

Finding（结论）由所有者与模型出。原因不是不信任你，是**口径判断需要长期积累**：
同样是造价，招标控制价 / 中标价 / 竣工结算价是三个数；同样是容量，
IT 容量 / 设施容量 / 并网容量 / 签约容量是四个数。写错口径的结论表面完全看不出问题，
却会悄悄污染整个知识层。所以：**你把数字和口径如实带回来，判断交给下游。**

## 机检五关（过不了直接退，不占所有者时间）

| 关 | 判据 |
|---|---|
| 格式 | 必填字段齐全，summary ≥200 字 |
| 溯源 | 每个 `key_number` 必须有 `locator`（页码/表号）——**写不出就说明你没真看到那个数** |
| 查重 | 文件名/标题撞库内已有即退 |
| 合法 | 模块号 M01-M15、confidence A-C、claimed_importance 1-9 |
| 命中 | 声明了工单的，检查是否真的命中该模块 |

## 你的 KPI 是命中率，不是投递量

交 100 份退回 90 份，不如交 10 份全中。
