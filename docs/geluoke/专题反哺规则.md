# 格洛可专题研究反哺规则

版本：1.0｜更新日期：2026 年 9 月 27 日｜首次执行：《造一座数据中心有多挣钱》→ `cost.html`

每篇专题长文都是一次集中取材与核验。文章交付后，取材过程里形成的视角、数字与来源必须回流到 inresearch.ai，否则下一篇又从零开始。本规则规定回流的对象、落点、步骤与验收；与 [专题写作规则](专题写作规则.md) 配套，写作规则管“怎么写”，本规则管“写完之后沉淀到哪里”。用户当次的明确要求优先；本规则不自动授权发布或修改现行规范。

---

## 一、反哺的三类对象

1. **视角**：文章用来拆解问题的框架（账本边界、四层利润分配、成本与收入两侧、口径对账）。它们决定网站页面应该有哪些输入、输出与对比，是最先反哺的对象。
2. **数据**：研究卡里带来源、时点、单位、分母与属性的数据点。只有同时满足这五项的数据点才有资格回流；搜索摘要与二手转述不回流。
3. **规范**：写作过程里发现的口径、单位、术语与流程规则，回流到写作规则或数据口径手册。

## 二、落点与对应仓库对象

| 对象 | 落点 | 何时采用 |
|---|---|---|
| 研究实体（正文、来源清单、复算脚本、反哺台账） | `docs/research/<日期>/<主题>/` | 每篇必做 |
| 页面视角与情景预设 | 相关页面的版本化 JSON（如 `data/datacenter_cost_model.json`）与前端组件 | 文章视角能落到已有页面时 |
| 单点基准数字（带时点与属性，供页面展示） | 页面 JSON 的 `benchmarks` 字段 | 与页面直接相关的 5–10 条 |
| 价格与租金序列 | `data/prices.json` | 同一指标有多个时点时 |
| 项目与公司事实 | `data/facts.json`，经 `knowledge.fact_contract` 校验 | 已披露事实与研究实测，且能定位原文 |
| 研究问题 | `framework/research_questions.json` | 文章回答了或提出了尚未立项的问题 |
| 规范 | `docs/geluoke/专题写作规则.md`、`framework/01_data_standards.md` | 发现新规则或旧规则失效 |
| 决策记录 | `docs/DECISIONS.md` | 每篇必做，一段摘要 |

公众号 HTML、首图、正文图与制作脚本留在 `outputs/geluoke-research/<日期>-<主题>/`，研究档案只链接，不复制。

## 三、步骤（文章交付后当天完成）

1. **盘点**：读文章大纲与研究卡，列出文章用到的视角；对照网站现有页面与数据结构，标出“页面已有／页面缺失／需要新页面”。
2. **建档**：新建 `docs/research/<日期>/<主题>/`，放 `README.md`（身份、权威边界、与既有档案的关系）、`article.md`、`sources.md`（由 `sources.json` 生成）、`feedback.md`（反哺台账）。
3. **对账**：凡文章有自有算例的，写复算脚本放进档案，与网站现有模型跑同一套输入，写明两种口径的差别（如 CRF 年化 vs 直线折旧 + 税后 ROIC）。脚本内用断言锁住研报数字与网站基准，基准不得因反哺而改变。
4. **改页面**：把“页面缺失”的视角做成输入、输出或情景预设；每个预设带 `note` 写明来源、折算方式与作者拆分。基准数字进 `benchmarks`，每条带 `label / value / unit / as_of / source / evidence_class / url`。
5. **录数据**：与页面无直接关系但已核验的数据点，按第二节落点录入；一次录不完的写进 `feedback.md` 第三节“候选”，注明研究卡 ID，供下一篇或专门录入会话处理。
6. **立问题**：文章提出但未回答的问题，进研究问题库，附验收条件。
7. **改规范**：写作规则或口径手册需要更新的，按 [当前基准](../../framework/CURRENT.md) 的“每次更新如何收口”流程修改。
8. **收口**：`DECISIONS.md` 加摘要；`current_state.json` 相关主题的 `implementations` 加新文件；跑浏览器测试、单元测试、`governance --refresh` 与 `--check`；提交并开 PR。

## 四、验收

- 台账 `feedback.md` 四张表齐全：视角去向、已采用数据、候选数据、规范变更；每条已采用数据可回到研究卡或研报页码。
- 页面上每个新增数字都带时点与属性，页面文案不把预测写成事实；旧基准结果与既有测试断言不变。
- 复算脚本可独立运行且断言通过；网页、脚本与文章三处数字一致。
- 未完成项写在台账第五节，不留在口头。
