## 文风：A「行业编辑讲解」为主，B「科技报道叙事」辅助

以后新写、修订的专栏与长文统一采用这个组合：像懂行的编辑把一件事讲清楚，专业、自然、连贯，有依据就给出判断，判断保持克制。叙事帮助读者顺着具体事情理解原因与影响，不要求每篇都写成故事。

1. **围绕一个具体问题组织全文。** 多篇来源共同解释这件事，不按媒体逐篇拼接。实质说法不同才比较；资料目录不充当文章目录。
2. **从有来源的事情进入。** 用已经发生的事件、明确的新变化或实际问题开篇，再讲技术、政策和商业机制。场景、人物动作、对话、采访与亲历必须来自读过的材料，不能补写。
3. **小标题写本节的内容。** 不预设“最新进展与已确认事实”“尚待验证的问题与后续观察”“关键背景”“产业影响”“后续观察”等栏目；读完材料，再按本题的对象、动作和问题拟标题。用户已经确定的主线与具体目录优先。
4. **把抽象话落到人、事情和数字上。** 谁公布、谁建设、哪里卡住、谁付钱，直接讲。技术词首次出现时解释；事实、背景、机制与判断在需要处自然衔接，不按“事实→背景→各方说法→影响→未知”逐栏填空。
5. **保留会影响判断的不确定性，用具体话说。** 核实后直接写缺什么，例如“公司还没有公布客户实际任务的测试结果”；不每段提醒证据不足。计划、归因、否定、条件和数字口径不能删除；未公开不等于未完成，预测不写成投运。
6. **结尾落在文章已经讲清的判断上。** 有具体事件与日期才写后续，不强制另列问题，不补“值得持续关注”。删除“真正需要判断的是”等引导层，直接写判断及理由。
7. **自然不等于随意。** 不靠“说白了”“这下有意思了”等口头禅，不写夸张金句、连续排比或故作高深的术语；也不把长文写成平淡的知识条目。长短句自然交替。
8. **连读验收。** 先连读导语、各节开头和结尾，再读全稿，检查多篇来源是否形成解释链。删掉可随意替换公司名的空话、重复保险句和制作过程；不以禁词计数或 AI 检测分数代替编辑判断。
9. **有角度，不充当和事佬。** 开篇给出材料支持的核心判断，章节逐步解释它；不为显得全面而机械补“这也对、那也要考虑”。水、电、冷却等基建先讲设备怎样工作、哪里受限、谁付钱，再讲影响。用具体环节与案例展开必要条件，不用抽象事项清单代替解释。删去只复述前段的总结、官方套话和不改变判断的平衡段。压缩稿按当次字数验收，资料全量留在研究交付，不挤进正文。

inews.today 的专栏规范与写稿实现已于 PR #256 采用同一组合；本文件是 inresearch.ai 长文的唯一执行源，自动新闻专栏的具体实现仍见该仓库 `docs/columns.md`、`src/lib/column-style.js` 与 `src/lib/column-draft.js`。2026-10-09 已核对它们同时修改了默认提纲和写稿提示词，本项目不复制出另一套固定目录。

## 一、选题与论证主线

1. 一篇只回答一个核心问题，用一句话写在大纲首行，正文每章都要回到它。标题直接表达核心问题或经证据支持的判断，不预设胜负，不把预测写成事实。
2. 用户的观点、感受或假设是待检验的研究问题，主动找支持证据、反例与适用边界，不选择性引用。
3. 先定"账本边界"再谈数字：同一件事在不同主体（出租人、托管商、云、模型方）的账上完全不同，先说清分析对象是谁的账、什么口径，再比较。
4. 按论点安排叙述：事件、机制、证据和影响在需要处出现，不机械套五段结构或每章观察清单。段落用首句承接；小标题只在帮助读者理解时使用。
5. 普通专栏不套六章、研究卡张数或导语/点评段数：一条明确主线，长度随材料和当次要求决定。较长研究专题篇幅分两档：完整研究专题保留原来的 1.5–1.8 万字参考，正文 6 章、每章 12–16 段；用户要求“不太长／5000—7000字”时采用精简专题，仍可保留 6 章，但按论点压缩段数，不强凑每章 12–16 段。导语两段、点评三段随总篇幅缩短。交付分别记录正文汉字数和含标点字符数，排除图注、来源及制作说明；不靠注释凑字数。上一稿的长度不自动覆盖新稿的明确要求。
6. 不用"值得关注""毫无疑问"等空泛套话；允许明确、有理由的作者判断，不用感叹号，不写 URL 进正文，不写内部检索、工具与验收过程。
7. 先研究再决定是否成稿：围绕近几个月的变化，判断核心矛盾、可核实数据、具名案例、反例与未来验证节点，给出“值得写／证据不足”的理由及大纲。大纲获采用后直接完成文章与配图，不反复确认已确定的方向。

## 二、来源与事实核验

1. 优先使用监管、电网、公司公告等原始资料。已提供的报告与可靠报道可直接作为写作材料，写清来源和年代；不为普通历史叙述逐条追回一手全文。重要现时数字、明确冲突和法律结论再定向查证。搜索摘要不作为独立数据依据。
2. 每个数据点记录：主体、数值、单位、期间、分母或口径、属性、来源机构、URL、来源日期、原文短引。数字应能回到已保存的材料、原文摘录或数据卡；普通专栏不强制另建 `cards.json`，较长专题可用研究卡统一口径。正文新增实质事实时补上对应来源。
3. 区分：事件日期与报道日期；计划、签约、开工、并网、投运；合同总额与年租金；承诺与到账；规划容量与投运容量；关键 IT 负载与总功率（gross）；EBITDA 与净利润；债务本金与账面值。
4. 研报引用写机构与日期（"摩根士丹利 2026 年 9 月《AI 指南》"），并核对该数字在报告中的页码；同一框架若在早期报告首见，备注说明。无法读取全文的材料如实记录，不假装读过。
5. 已知易错点（本次实测）：单位换算 1 百万美元 = 100 万美元，"1,833 万" 与 "183 万" 之差是十倍；亿与十亿、亿元与万元；"全行业"与"超大规模厂商整体"的主语；"到户电价"与"发电侧可研电价"；容量费等只见媒体转述的金额不写数值。
6. 法律与政策的结论性判断核对判决、诉状、合同或政府原文；普通事件报道可按已提供材料说明谁提出什么，不为背景一句话追加整轮法律研究。严格区分原告主张、法院认定、公司回应与未来承诺；提交集体诉讼不等于已获认证，批准被撤销不等于永久禁建，政策框架不等于全部生效。合同有删节时，不推算未披露的期限与赔偿。
7. 第三方项目跟踪须保留统计范围与去重限制：受阻或延期项目金额不是实际损失，跨期项目不能未经去重直接相加；团队总人数不是新增招聘或专职人数。固定债务余额的简单利息是资金占用，延期新增损失须比较按期与延期两套现金流，避免重复加总。
8. 关键口径在数字或案例首次出现处说清；必要边界保留在图内与备注，不让每段都变成重复免责声明。事实、机制解释与待验证推断要自然衔接。

## 三、数字的五类属性与写法

1. 数字首次出现时通过来源与动词自然交代属性，不要求逐项加标签。五类：已披露事实（公司或监管披露）、研究实测（研究机构测得或指数）、厂商测试、预测估算（机构估算与公司目标、指引）、作者说明性计算（我们自己的换算与模型）。机构的定性表述按"预测估算"处理；格洛可自建模型属"作者说明性计算"。
2. 每个百分比说明分母；每个比率说明分子分母的口径（NOPAT÷总资本开支、NOI÷开发成本、EBITDA÷收入）。
3. 作者说明性计算必须写公式与取整方式，例如"190 亿 ÷ 20 年 ÷ 401MW ≈ 237 万美元/MW·年（名义值，未折现，不计递增）"；敏感性分析必须公开全部假设。
4. 单位写法统一：美元用"亿美元／万亿美元"，来源原始单位为十亿美元时在图注注明；人民币用"亿元"；GPU 租价写"美元/GPU·小时"；租金写"美元/MW·年"或"美元/kW·月"；电价写"美分/kWh"或"元/千瓦时"；汇率只在需要对照时换算，注明汇率来源（如"按万国数据公告隐含汇率 6.79"）。
5. 同一数字全文最多出现两次，第二次引用第一次所在的章（"第二章的 31%"）；跨章统一取整（35.94 亿与 36 亿、24.9% 与 25% 只保留一种）。
6. 预测注明提出机构、日期与目标年份；两套基数不同的预测不并列（如信通院 2023 年基数与能源局 2025 年基数）。

## 四、制作流程（按文章规模执行）

普通专栏由一位作者把材料读懂、形成主线、写成稿，之后统一核对关键数字、来源归属和行文。已有摘录与侧车直接复用，不要求每条素材重复抓取、每章重复复核。复杂专题沿用下面的六阶段工具；独立复核集中于关键数字、冲突或法律判断，不为普通背景句重新启动整个流程。

1. **取材**：下载并抽取研报全文（PyMuPDF），做页码级摘录 `report_facts.md`；把研报关键表格逐项转成数据点。官网 PDF 若被 JS 跳转拦截，带同站 Referer 请求即可获取。
2. **研究卡**：按实际论点组织资料，已有来源、摘录与数据卡直接复用，不固定 8–12 张，不要求每卡重复抓取与独立代理。重要或相互冲突的数字另做定向复核。合并后由编辑做一轮单位与口径抽检（用正则找"X,XXX 万美元/MW"之类的可疑量级）。
3. **撰写**：作者读取本文件“文风”，围绕主线连续写作，输入为核心问题、用户已采用主线、本篇已读材料与来源定位、必要口径及配图任务；默认构思项不当公开目录，读完材料再写话题专属小标题。提示词明确 A 为主、B 辅助，禁止虚构场景和逐来源拼接；来源键留在工作稿，读者看到自然叙述。完成后统一核对实质数字与归属，不要求逐句保险说明或每章启动另一套流程。
4. **压缩**：按本次约定的总字数压缩，完整专题可参考每章 12–16 段，精简专题按论点保留必要段落。只删、只合并、只改写，不新增数字；再做差异核验，确认无新增数字、无数值变化。被删的口径说明进入 `dropped_numbers.md`，供备注选用。
5. **导语、点评、首图文字与终审**：主编代理读六章定稿写标题、两段导语、覆盖行、三段点评、备注、首图文字；核稿后由终审代理做跨章检查（重复、口径不一致、缺属性、预测写成事实、章节衔接）并逐段给出替换文本。终审的"未决项"由人工编辑裁定并记录在交付说明。
6. **组装与验收**：来源按机构分组编号，正文段末加 [n]；生成公众号 HTML、完整网页版、轻量版；跑桌面与手机渲染、复制往返测试；逐张目检图片；写交付 README。用户已授权长文自动反哺研究：交付完成后执行 `scripts/editorial-outbox.py seal <交付目录>`，由常驻发送器送入 inresearch.ai，不再逐篇询问。正文标作者分析并关联一手原件，接收、阅读、采用分别记账；执行细节唯一入口见 [专栏与长文自动交付](../local_reader/EDITORIAL_DELIVERY.md)。

## 五、文章结构

1. 普通专栏围绕主线直接展开，按需要使用标题、开篇、正文、图表与来源，不强制导语段数、“本篇覆盖”或点评模块。完整研究专题可参考：首图 → 完整标题 → 导语 → 一行“本篇覆盖” → 分章正文（图文穿插） → 格洛可点评 → 来源 → 备注 → 二维码 → 署名。
2. 开篇直接交代这件事的关键变化和本文判断，数字与条件在适合的段落展开，不把导语写成口径清单。较长专题可用两段导语，普通专栏不固定段数。
3. 完整研究专题的点评可参考三段，普通专栏不固定点评或段数：第一段说明利润或结构在各层之间如何分配及原因；第二段连接两个以上地区并引具名案例（标日期）；第三段指出决定后续走向的具体因素；材料有时间节点时再写日期，不机械列观察清单。只用正文出现过的数字与案例。
4. 备注收录：研报版本与日期（含"框架首见于何时"）、取整与口径说明、汇率、被删的来源版本说明、未核实而未采用的内容。不写内部流程。
5. 来源列表：正文只列机构名（同一机构多份文件合并为一个编号），完整 URL、标题、日期放在 `sources.json` 单独交付。

## 六、首图与正文图表

1. 首图或全文总览图采用 2:3 竖版，目标宽度 ≥1080（优先母版 2400×3600），深蓝工程底色、白金信息层级、青色细边卡片。优先沿用用户给的模板：品牌与日期 → 本篇标题和副题 → 与论点相关的工程剖面 → 全文主题卡 → 关键数据和后续观察 → 判断与署名。主题卡可用 3 列×2 行覆盖六章，不机械沿用上一稿的回报条、收入层或旧事实。总览图应单独可读，标明工程示意，数字及条件与正文一致。二维码只使用可验证的原图，不生成伪二维码；独立总览图可把该区域用于结论。
2. **图先回答紧邻正文的具体问题，再选择画法。** 写配图任务时先列“这一段要让读者看见什么”：谈地域和覆盖范围画地图，谈规模与差异画数据图，谈审批/建设过程画阶段或时间线，谈费用责任画收费基数与主体关系，谈设备和供能路径画对应工程图。图放在建立该问题的段落旁；不能因为同属一个行业，就拿园区场景替代电力地图或合同解释。本文的逐图任务见 [图文对应清单](../../outputs/geluoke-research/2026-10-09-us-datacenter-power/work/v3/figure-plan.json)。用户五张工程场景图仍作为适合工程图时的质感与结构参考，原件身份见 [参考登记](../../outputs/geluoke-research/2026-10-09-us-datacenter-power/work/visual-references.json)，不能把它解释成所有段落都采用工程画风。网站技术图册和迁移队列仍单独管理。
3. **重要信息在图中直接看懂。** 地域名称、边界含义、流向、责任主体、费用基数、历史/预测年份、合同/批准/投运阶段和影响结论的条件，直接标在相关区域、对象或主说明处；能在图上标注的，不挪到图外备注小字。图注可列标题与来源，不能靠图注补救图面歧义。讲具体技术路线，就画相应设备；燃料电池不能用内燃机替代，通用示意与真实项目证据在图内分清。地图使用可靠地理数据，区分州界、系统界和有限联络；概览分界与站点示意须图内明示，不能假造精确GIS。每张数据图保留单位、期间、属性、口径、来源与必要页码；作者计算附公式，正文修改后同步重制。
4. 完整研究专题以 10–14 张正文图为参考，按主要论证安排，通常每章 1–3 张；普通专栏按实际内容与长度安排，不硬凑图数。总览首图另计，不重复场景凑数，不把图片堆成文字卡片。设计宽 640 px、DPR 2 渲染（1280 px）；数据图可交 256 色 PNG 与 SVG，工程插画交原始栅格与发布 JPEG/PNG，文字层可交 SVG，不伪称插画有矢量母版。手机正文标注设计字号 ≥17 px，重要条件宜 ≥23 px，标题 28 px、副题 18 px、来源 16 px；按最终正文显示宽度实际目检。柱图从零起算，长度与数值成比例；不同单位不共用坐标轴。
5. 常用图型：地域地图、水平条图、区间图、阶段流程、责任关系、案例对照、时间线与工程剖面。表格每格宜短；重要口径在主说明中体现，不固定塞进注释行。具体选择由本段问题决定。
6. 色板（深蓝 #0B1F3A 底）：蓝 #3987e5、橙 #d95926、绿 #199e70、黄 #c98500，金 #E0B45C 只用于标题、基准与结论。颜色含义直接放在图例或对应对象处（如"蓝=直租，绿=转租+担保"），来源行只放来源。
7. 生成后逐张目检：换行是否把数字与单位拆开、来源行是否与单位注重叠、图例是否与数据一致、颜色是否与说明一致。
8. 模板图只提供视觉结构，旧标题、案例和数值不得带进新稿。图像生成先固定已经核实的中文文案，生成后逐项检查文字、数字、脚注、裁切与清晰度；保存提示词、使用方式及原始分辨率。若实际只返回 1024×1536，就如实记录，不靠放大声称取得高分辨率母版。
9. **工程图画法与技术复核**：主体要可辨识，显示设备安装位置、建筑剖口、地上/地下关系及真实连接；用暖白或浅色版面、柔光、可信金属/混凝土材质和克制的蓝/橙功能线。不要玩具块、空白大画布、霓虹背景、糊细节或靠密集文案代替设备。纯数据图保留准确比例，不为拟真牺牲数字可读性。
10. **图与事实分开**：用户样图提供画法，不提供具体工程事实。机房、变电、核电、燃气、供配电、冷却和燃料路径按本题材料核对；电线不画成水管，箭头/颜色有图例，车供气不冒充大型园区常态主供气，燃料电池与内燃机/燃气轮机分别标明。通用示意注明身份，不当作项目照片、现场证据、地图或施工图；AI 插画不能作为研究数据库的事实来源。
11. **制作与验收**：栅格工程图用 imagegen，样图先指定为风格参考，固定所解释的一个问题和必要技术约束；先干净底图，再由可编辑标注层添加需要校对的文字。保存提示词、原始字节身份、真实分辨率、使用角色和每张人工审核结果。数据图按数据表制作。逐张检查技术连接、设备区分、裁切、手机可读性、图文对应与压缩后的细节；公众号 JPEG 通常优先宽 1280–1536 px，在单张上传限额内以保留细节为准。
12. 生成失败应如实记录，可重试；不得用旧图或占位图冒充成品，也不得未经授权切换收费 API 路径。补成图片后更新交付清单与压缩包，区分独立总览图和实际已嵌入 HTML 的首图。


## 七、排版参数（公众号 HTML）

1. 公众号复制版的正文容器不添加左右内边距与装饰边框，避免与平台边距叠加；正文区白色，单列流式、全部内联样式，无脚本、无外链样式、无按钮与操作提示。完整网页及轻量版按第 5 条单独处理手机边距。
2. 字号：主标题 26 px/700/#0068B5；章节标题 22 px/#08577C，前置章号；正文 17 px、行高 1.8、#1F2A37、两端对齐；信息行与日期 14 px/#5A6B7F；图注 12 px；来源与备注 11 px；引用标记 [n] 0.85em/#1E66B3。
3. 字体栈：Arial, "PingFang SC", "Microsoft YaHei", "Noto Sans SC", "WenQuanYi Zen Hei", sans-serif；点评用仿宋栈 FangSong, STFangsong, "FangSong_GB2312", "仿宋", "Songti SC", "AR PL UMing CN", serif。
4. 图片 `display:block;width:100%`，Base64 内嵌；整文件 ≤3.8 MB，建议 ≤2.0 MB（首图公众号版 1080 px、JPEG 质量 88；工程插画保留细节的 JPEG/PNG，数据图可用 256 色 PNG）。
5. 三个版本：公众号版（上述）；完整网页版（桌面正文最大宽 720 px、居中、左右各 16 px 内边距）；轻量版（图片改为同目录相对路径）。完整网页与轻量版在宽度 <768 px 时，左右各 8 px、页面背景白色，去掉灰色侧边带，不叠加第二层容器边距。图片用足正文宽度，标题采用均衡换行，避免单字孤行。响应式 CSS 只加在网页版本，不破坏公众号版的行内样式。
6. 用户说“左右留白太多”时，先核对其指的是正文 HTML、图内留白还是查看器边框；已经明确为 HTML，就改页面容器，不重生成图片。修改后同步完整网页、轻量版、构建脚本和交付包。

## 八、验收与交付

每篇长文至少形成两套用途明确的成品：**公众号 HTML**用于图文编辑与发布；**研究文字材料**用于 inresearch.ai 的素材接收与后续审核。研究材料不能只是文章去掉排版，也不能把文章与原文重复计算为两份独立证据。

- 公众号图片遵守发布时可读取的微信官方要求，记录文档 URL 与访问日期。本次所核对的 [上传发表内容中的图片接口](https://developers.weixin.qq.com/doc/service/api/material/permanent/api_uploadimage)要求 jpg/png 且单张小于 1 MB；该限制属于正文图片上传接口，不冒充所有素材接口的一致限额。交付可单独上传的图片文件。Base64 是本地复制包形式，不能宣称它已成为微信可发布的素材 URL；公众号编辑器实粘或账号上传未执行时如实标明。正文总览竖图与列表封面分开提供，不用裁切正文图冒充完整内容。
- 研究文字材料至少提供 UTF-8 文本、现行需求对应表、来源清单、关键数字/机制及原文定位、事实/预测/合同/工程阶段、反证与剩余缺口。先按需查阅 `framework/CURRENT.md`、`research_questions.json`、`tco_targets.json`、对象与口径规则及实际素材接收 schema，冻结采用的需求与版本摘要，再定向搜集足以回答这些问题的原始材料；材料量不代替问题覆盖。
- 每份原件保留来源 URL、机构、源日期、检索时间、实际字节 SHA、读取范围及页/节/表定位。原件下载受限而通过网页工具读取时，归档响应并标注响应 SHA，不能冒充原始 HTML/PDF 字节身份；同源复述不算独立佐证。
- 使用现行接收格式生成投递单，并运行实际字段校验。节点与五类变量沿现行登记；不虚构工单，不因格式通过自动关闭研究问题、改写正式事实/价格/项目容量或模型基准。未完成深读/C3/远程采用的材料保持相应阶段，按现行采集与反哺规则推进，交付说明列出已覆盖与未覆盖要求。

1. 事实验收：成稿统一检查关键数字、来源归属、预测/事实与单位；压缩后检查是否改动数字。复杂专题按风险加独立复核，不将固定三轮或逐章复核强加给普通专栏。文风验收检查是否有主线、有判断，以及拼贴段落、模板标题和冗余保险句。
2. 数据验收：图与正文数字逐项对照；作者计算复算；百分比分母、属性标注齐全。
3. 视觉验收：先对照紧邻正文，逐张核对图片是否解释同一对象、问题与状态，再看最终手机图。地图的地理与分界、工程图设备类别、比较图费用基数、时点与限定必须可直接读到，不靠小字图注纠错。桌面 1000 px 与手机 390 px 整篇渲染无横向溢出，检查实际正文宽度、边距、标题孤行、图中关键字与清晰度；路径存在、图号顺序和复制往返图片保留由脚本检查。未在公众号实粘的一律标"公众号待验证"，浏览器检查不能代替平台实粘，图片数量或自动检查通过不能证明图文对应。
4. 交付清单：完整标题；公众号 HTML；完整网页版；轻量版；首图母版与公众号版；正文图 JPEG/PNG、数据图 SVG 源与工程插画原始栅格/提示词；可编辑 Markdown；`sources.json`；研究卡与研报摘录；制作脚本；`checks/`（渲染缩略图与 validation.json）；README（验收状态、边界、未决项）；整包 zip 放在仓库工作目录供直接下载。
5. 仓库入库：交付物 HTML 登记到 `framework/interface_manifest.json` 的 `excluded_pages`，运行 `governance --refresh` 与单元测试后提交；`verify`、`indicators` 产生的改动不提交。
6. 换会话时写一页交接：已确认偏好、当前规则版本、成品路径、验证结果、未完成项与下一步。新对话只读交接和唯一规则源，不整段复制历史；新文章必须重新研究和核实日期，不把上一稿数据作为新事实。用户尚未给选题时，先索取选题或材料，不擅自替用户决定。

## 附录 A：利润专题术语示例（按新稿主题选用）

以下含 2026-09-27 利润专题的历史参数，只作术语和口径示例；新稿引用任何数值须重新核实，不能视为当前市场基准。

| 术语 | 释义 | 在账本中的位置 |
|---|---|---|
| Powered shell（带电的壳） | 已完成土地、并网变电、楼宇、供配电与冷却、但未装服务器的数据中心建筑；出租方按 10–25 年租约租给自带 GPU 的承租人。摩根士丹利称此类公司为 powered shell providers | 收入：美元/MW·年；风险：造价、工期、租户信用 |
| Colocation（机柜托管） | 连机柜、电力、冷却与运维一起提供，客户只放自己的设备 | 收入：美元/kW·月 |
| GPU 云 / 新云（neocloud） | 自购加速器按开机小时出租的云服务商（CoreWeave、Nebius 等） | 收入：美元/GPU·小时；利用率、单价、折旧、利息都在其账上 |
| 模型 API | 按 token 计价的推理服务 | 收入：美元/百万 token |
| Capex / 资本开支 | 一次性投入；IT capex（服务器、网络）与非 IT capex（壳与机电）分列 | 摩根士丹利 1GW GB300：230 亿 + 160 亿 = 390 亿美元 |
| EBIT | 息税前利润 = 收入 − 营业成本（含折旧） | 不扣利息，与融资结构无关 |
| NOPAT | 税后营业利润 = EBIT × (1 − 税率) | 摩根士丹利用 21% 税率 |
| ROIC | 资本回报率 = NOPAT ÷ 总资本开支 | 本篇 31% 的定义 |
| EBITDA / 调整后 EBITDA | 息税折旧摊销前利润；"调整后"另剔除股权激励等项目 | 新云报表的主指标，未扣折旧与利息 |
| NOI | 净营业收入 = 租金 − 出租人承担的运营成本；三净租约下 NOI ≈ 租金 | 壳与托管层的分子 |
| Yield on cost（成本收益率） | 稳定后年 NOI ÷ 开发成本 | 壳层 16%–20%，REIT 开发项目 11.5% |
| Triple-net（三净租约） | 承租人承担电费、税费、保险与维护 | 出租人 NOI 接近租金 |
| Modified gross（修正毛租约） | 出租人承担部分运营成本 | NOI 低于租金 |
| Backstop（担保兜底） | 第三方（如 Google）为承租人的租约义务提供担保，使项目可以举债 | 换取股权或认股权证 |
| RPO / 收入积压 | 已签合同中尚未确认的收入 | 与当期收入相隔建设周期 |
| 关键 IT 负载 / gross 功率 | 供服务器使用的功率 / 含冷却与损耗的总功率 | 换算每 MW 数字时必须注明 |
| MSR、上架率、计费率 | 万国数据的每平米月收入、已用面积÷运营面积、REIT 底层资产计费面积占比 | 中国托管层指标 |
| CROCI | 现金投资回报率（高盛口径） | 超大规模厂商 24%–31% |
