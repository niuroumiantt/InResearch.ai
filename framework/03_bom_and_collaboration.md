## 部件表 2.0：切到有自己的价格、供应商与交期为止（2026-09-28）

`framework/bom.json` 2.0 是爆炸图的名词轴。切分只用一条规则：拆到有自己的价格、自己的供应商名单、自己的交期为止；普通紧固件合并，关键稀缺件不合并。按此规则 46 条变成 61 条物理部件，另有 1 条软件条目（DCIM/BMS/EPMS）与 1 条设施基型（预制化/微模块）；`kind` 区分 part / software / archetype，只有 part 占尺度。五个尺度用 S1–S5（园区、建筑、机房、机柜、部件），`layer` 键是兼容名，与经济模型的五类变量无关；`system` 指向八个生态之一（设施、电力、冷却、计算、内存、存储、网络、控制与软件）。用户 2026-09-28 批复的切分：通用服务器与加速器服务器分两行，BMC 与 CXL 内存单列，机柜配电条并入 PDU 不再拆，小型模块化反应堆登记为 emerging，软件条目进目标表。

站点权利与配额（土地、水权、电力配额与并网、天然气管道接入、网络接入、许可）不可采购，登记在 `framework/site_rights.json`，每条写明落在哪几类变量；因子树用 `site_rights` 字段引用。合同（PPA、租约、算力合同、融资）不进这两张表，按主体类事实处理。

部件 ID 是稳定锚点：存续的部件保留旧 ID 只改名；拆出的新部件用新 ID 并记 `split_from`；被拆分或移出的旧 ID 写进 `aliases` 指向去处，`research_graph.json` 的对应节点转为隐藏并 `redirect_to`，网页、3D 场景与产品目录经别名解析，不因重切失效。`data/products.json` 的 `bom_parts` 按产品线名重映射到新 ID。校验：`validate --strict` 检查 kind、尺度、系统、公司、别名去处与权利表；`tests/unit/test_bom.py` 固定上述决定。

## 模型表达

物理 P、系统 F、产业 V、需求 D、研究 R 共享对象身份。空间树回答“在哪里”，装配树回答“由什么组成”，供电、冷却、网络、控制、制造、持有、运营和使用通过有类型的关系连接。

读者可沿区域/园区、建筑/部署区、机柜/整机、托盘/组件、器件/封装、材料/工艺深入。实际装配允许不同深度；室外设备不强制经过建筑层，外部工厂不是机柜子件，CDU 服务多个机柜不等于它拥有这些机柜。

每条关系写明类型/实例、时点、配置、方向和证据；接口注明端口、介质/电压/协议、容量及工况。类型、厂商型号与真实资产分别登记，不从通用模型推断具体站点。

## 每层都有问题、材料和成果

每个节点按 [07 产品生态规范](07_product_ecosystems.md) 的九主题组织研究；总览为交付视图，问题、证据和任务为独立记录类型。产品采用不同研究深度，不适用项说明理由。每份材料与节点的关联应定位到页/节/表/图/单元格，标直接研究、实测、背景、仅提及或反证。上层有一篇资料，不表示全部下层已研究。

3D geometry 只引用研究对象 ID，不在脚本里维护第二份事实。点击节点可到结构、方案、参数、公司、原文、判断与缺口；从材料也可反查支持的问题。

视觉精细度、身份可信度、资料完整度与研究状态分开。标明概念示意、官方参考设计、项目设计、竣工核对或运行核对；内部未知不补猜。成熟度、供应紧缺、技术替代和证据质量各自记录，不共用一个永久 status。BOM 数量与采购套件、父项含价与子项成本、冗余设备与运行容量分别统计。

## 协作与变更

- 15 模块是兼容维护单元；每个节点/问题有明确 owner，跨模块贡献可追踪引用，最终合并按现有采用规则。
- 工单绑定 question_id、范围、工况、证据需求、交付与验收；获取文件只是子任务完成，不能直接关闭研究问题。
- 研究视图、团队页与派工接口共用 `inresearch.knowledge.registry.task_board()`；其任务集合由 `current_tasks()` 计算，问题任务只依据当前问题和有效采用结果生成。`reports/workorders.json` 只保存模块缺口工单与模块统计，不保存或否决研究问题任务。负责人记录按稳定任务 ID 保留。
- 同一事实一个身份、多处使用；变更登记影响面并触发下游复核。并行工作使用独立分支/工作树，按记录 ID 合并。
- Git 保存源码、声明与采用后的结构化知识。原件、数据库、阅读成果和 PDF 等运行产物不进 Git；已有用户批准的 3D 小体积资产例外继续遵守来源与许可登记。
- CODEOWNERS 用于提出评审责任，实际分支保护与权限以托管平台配置为准；文件中写了 owner 不代表已具备强制权限隔离。
- 新分类或关系先形成有证据、边界、映射与版本的提案，再登记生效；模型不根据每篇标题创建一级目录。

## 落地验收

先完成一条有官方材料的贯通样例，将空间/装配、电热数据、主体交易、负载与证据连通，未知保留；验证重复实例、父子循环、接口错连、单位/工况、原文定位与反证回流。再扩展供配电、网络、存储、软件等域。研究质量与资料可复查程度决定深化优先级，不以空节点或几何数量作为完成度。


## 视觉资产的内容身份与采用（2026-09-14）

`web/assets/models/manifest.json` 是视觉模型唯一发布登记。schema_version=1，file 与 sha256 绑定确切 GLB 内容；candidate、adopted、rejected 分开。仅 adopted 且 page 匹配的条目进入场景；adopted/rejected 有明确决定依据。现有样例沿用既有不采用记录，保留文件供选型参照，退出场景自动加载。此视觉采用不产生研究证据、事实或物理身份认证。

来源页与许可/署名、GLB 2.0 自包含、单文件不超过 10 MiB、有限且有效的变换共同构成准入。materials.model_assets 为共享校验；workflow.model_assets 为作者工作区导入用例；下载只创建 candidate，同名新内容拒绝覆盖，版本用新文件名及新的审阅决定。下载器不能绕过许可要求；不能根据第三方模型的网格数或命名宣称已具备真实部件拆解。

模型比较台显示全部已登记身份，参数只过滤登记内的文件；场景 API 投影只给出已采用条目。静态文件也由同一登记解析。GLB 文件存在不等于已登记，已登记不等于已采用，已采用不等于研究已核验。具体流程在 ADD_3D_MODEL 操作指南，历史自动上传/登记即上线说明退出。
