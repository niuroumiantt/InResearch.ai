# 文献阅读、评分与采用标准 v4

> CURRENT · 2026-09-13。规则归属与替代关系见 framework/CURRENT.md。

> 2026-09-06 用户采用生效。依据：[研究架构 v2](../docs/reviews/2026-09-06/RESEARCH_ARCHITECTURE_V2.md)；常驻执行见 [RUN_TO_COMPLETION](../docs/local_reader/RUN_TO_COMPLETION.md)。本标准替代 v2 的低分过滤、凭摘要判 depth、分数驱动物理改名与“精读即可直接引用”规则。现行口径和 C3 采用门槛不变。

v4 按 2026-09-12 用户方向补充可配置模型和单一有效阅读结果；保留 v3 的原件与 C3 边界。2026-09-26 用户采用按分数分层阅读深度（§1），替代“所有独立文章都全文深读”。

## 1. 按分数分层阅读深度

原件登记 → 完整性检查 → 配置的研究模型粗读 → 按有效优先级决定深度 → 阅读质量检查 → 分类与证据候选 → 原文核验 → 既有 C3 研究采用。

有效优先级取粗读前已有的优先级（M4 L1、apply-triage、点名）与本次粗读 importance 的较高者，粗读不降低已有判断。深度分三档（2026-09-26 用户采用）：

| 有效优先级 | 深度 | 终态 |
|---|---|---|
| ≥ `READER_FULL_READ_MIN_PRIORITY`（默认 7），或点名 | 全文深读：逐块阅读、综合、封印报告 | 深读完成（complete） |
| 1–6 | 摘要深度：只读首、中、尾三块，保留块结果与粗读，不生成全文报告、不成为当前全文结果 | 摘要（summarized） |
| L1 为 0 分，或确认是 reader 衍生物回流 | 不读：`reader park` 停放，保留原件、台账与 L1 结论 | 停放（blocked，`parked_*`） |

块数不超过三块的文档直接全文深读。摘要可用 `reader deepen` 继续到全文，已读块不重读；停放可用 `reader retry --error-code parked_…` 恢复。摘要与停放都不计入全文深读完成。粗读不按年份、机构或目录抽样剔除文章；旧积压保留服务份额并随等待时间提权。持续新增按接收批次/截止日统计，不承诺永久“全库 100%”。

完全相同内容哈希且满足相同阅读标准的结果可继承，记录依据；同名/相似标题、译本与新版不能当重复。工程图纸、3D、数据集、依赖包采用类型对应的完整普查与处理契约，不冒充文章已读。损坏、加密、缺页、关键图表无法解析进入异常/补读，不算深读完成。

模型接入、配置和单一有效阅读结果按 [08 模型执行](08_model_execution.md)；当前暂用 Claude CLI，Spark 恢复后通过配置接入，型号不属于阅读资格或采用规则。换默认模型不自动重读已有材料。

## 2. 深读的可检查产物

1. 覆盖正文、附录、脚注、表格和图形；保存章节/页块清单、每块处理结果及全文综合。长文分块后不得丢失前后条件或静默截断尾部。
2. 重新访问原文，不扩写粗读摘要。记录定义、作者主张、原理/方法、样本、假设、接口、适用条件、反例、局限和未知。
3. 重要图表解释行列/坐标、单位、期间、实际/预测、注释；阅读覆盖与理解质量分别核验。
4. 形成阅读报告、数字和非数字候选、与节点/问题/关系的关联，以及新问题/新分类提案。允许“深读无新增”，不凑数字和 Finding。
5. 保存文档/版本 ID、SHA-256、模型与配置、提取器/提示词/标准版本、执行时间、覆盖与质量记录；模型参数量或多轮一致不能证明深读质量。

## 3. 数字与非数字证据

数字候选记录 metric 候选、value/range/bound、unit、caliber、观察/发布/预测时点、来源及定位；指标不明先留候选，不编造 ID。原理、规范、结构关系、机制、事件、测试、预测和假设采用有身份与类型的 statement 候选，保留主体、条件、支持/反驳和证据；不能因数字密度低忽略标准与失败案例。

原件哈希、doc/version/source ID 与页/节/表/图/单元格共同定位；缓存键须经过来源映射，不能冒充 source_id。扫描表核对原页；原生表检查单元格、公式和表头。采用的关键数逐项核对负号、小数、倍率、单位、边界、跨页续表和脚注，重要表复算合计/比例。OCR 与原图不一致留异常，不猜。Apple Vision 等系统 OCR 的双读一致仍不是准确性证明，关键数字必须回原图核验。

模型生成的证据引文必须是该块原文中的连续逐字摘录，核验时仅忽略空白差异；不得翻译、转述、修补断词或拼接远处文本。无法确认逐字相符时，舍弃该主张，不以近似引文凑数。引文校验失败不得封存为完整阅读。

作者声称、厂商规范、实际测试、估算、预测及情景假设分开；两个模型抽取同一值不是两个独立行业来源。来源可追溯、口径相容、独立核验、C3 采用是不同检查，不能互相替代。现行事实推算限制与中外口径不因本标准放宽。

## 4. 阅读 depth、质量与采用分别记账

| 历史兼容 depth | 含义 | 当前处理 |
|---|---|---|
| 精读 | 有逐份原文阅读记录 | 需覆盖/质量证据；标签本身不等于采用许可 |
| 据实生成 | 原表逐行解析并定位 | 只说明局部提取，不豁免该独立文章全文深读 |
| 半自动 | 标题/片段/数字行等有限读取 | 全部进入深读队列，分数只排序 |
| 成员精读 | 成员已读，尚待质量审计 | 保存执行依据并审计，不直接进入核心事实 |
| 目录级 | 目录或机械索引 | 只用于发现文件，展开到独立文章安排深读 |

`depth` 必须来自实际执行与可回查记录，**禁止根据 summary、文件名、rescore、批次默认值或措辞推断，缺省不得标精读**。旧标签和评分保留为历史判断；缺执行依据另记待验证，不静默提级或豁免新标准。读取状态、质量状态、整理状态、候选核验和采用状态独立；登记 sources 或路径出现不能判定已读/已消化。

## 5. 评分用于优先级与采用分流

importance 1-9 和 confidence A-C 保留兼容历史及 C3。每次评分记录理由、依据、阅读阶段和标准版本；粗读为暂定，深读可修订且保留前值。

评价内容包括原理/教学价值、接口/标准、方法与可考性、实证与失败案例、缺口匹配、时效、独立核验和反面价值。付费、独占数字、每页数字密度、中文或跨模块关联不自动加分；不能把收费和机构名等同可信。A/B/C 来源特征继续区分一手/实测/规范、机构预测/会议、转述/方法不明，证据等级按具体主张判断，不由整篇分数代替。

| importance | 兼容解释 |
|---|---|
| 8-9 | 关键基础/重要实证或重大判断影响，按 C3 进入 A 档 |
| 5-7 | 有价值的方法、原理、案例、参数或补证，采用需满足 C3 条件 |
| 1-4 | 历史背景、重复信息或贡献有限；摘要深度阅读，保留块结果，可 deepen 到全文 |

采用按 [01 口径手册 §4](01_data_standards.md#4-来源冲突与证据采用) 的唯一 C3 定义执行；分流、存档、审阅与正式采用分别计量。DECISIONS 只记录变更，不作为另一份采用规则。

## 6. 身份、命名与目录

文档身份、内容版本与原文件 SHA-256 分开登记；原名、原路径、接收批次保留。规范显示名可用“年份_机构_标题__短ID”，缺失字段标未知。分数放元数据；旧带分数名称作为历史别名或导出名，不再随评分移动原件。

原件不改字节、不删除；library 为可重建多视角入口，同一文献可关联多节点/模块，每条关联有具体证据范围。新词优先匹配别名、类型、型号、实例与条件；分类边界变化需有版本、理由、证据、影响和映射。

自动整理只执行规则验证通过的操作计划：合法分类、源哈希、目标冲突、旧新路径、操作日志与可恢复状态。文献中的文字不获得文件执行权限。包内相对路径与依赖保留；解压不删除原包；磁盘不足不能清原件腾空间。

## 7. 输出与专家能力

Spark 持续产出原文可回查的阅读成果和候选，研究侧按 C3 更新来源、facts、statements 与 Finding。覆盖按范围版本和节点×问题衡量，原理与数字同样可以回答问题。每篇有终态：深读完成、结果继承、摘要、停放、待补读/异常等；摘要、停放与异常都不计全文完成。所有被提取候选都有采用、待核、冲突、背景或无增量去向。

周期性检验能否脱离摘要解释原理、同条件比较方案、复算关键量、复盘失败与预测，并检查反证导致的下游修订。文件数、摘要长度和分数不能替代这些能力。

## 8. 显式重读与当前版本

内容 SHA 标识原件；阅读 revision_id 标识一次完整阅读及其冻结配方。每个内容身份只有一个当前阅读指针，待验收的新版本不进入当前导出。首次完整阅读仍自动产出候选，C3 采用资格不因此改变。

重读由 `reader reread` 显式提出，记录旧版本基线、稳定请求键和原因；读取原件，生成独立提取、逐块结果及报告。换默认模型不创建重读；`retry` 只重试原版本失败任务，配方不匹配仍须恢复原配置。不同模型、后端或更大参数规模不自动取得替换权。

新版本达到 ready 只说明原件哈希、配方、覆盖、块内容和报告通过机检。审阅者通过 `inspect-revision` 核对正文、尾段、引用与理解质量，再以报告 SHA、旧版本基线、审核人和理由执行 `activate-revision`。程序重新验证被审阅的产物，事务内比较旧指针并一次切换；重复请求不重复生效，迟到或被拒绝的版本不能覆盖当前结果。模型失败、损坏、不完整覆盖或提交失败保留旧结果。未通过语义核对时 `reject-revision` 关闭候选，记录和原件保留。

阅读验收是阅读结果选择，仍不等于 C3 采用。旧报告、被引用的旧证据和原件保留；新候选证据使用独立阅读版本 ID，不能借用旧证据身份。当前快照每个内容身份只投影一项，历史版本经台账和具体产物路径回查。原件 library 名称保留为接收时的别名，不随重读移动原件，也不成为当前阅读结论的权威。


## 9. 终端处理与共享全文结果

`reader current --sha 完整SHA` 与 `deep-read current --sha 完整SHA` 查询同一个 reader catalog；当前指针仍只有 documents.current_revision_id。共同的只读用例验证原件、覆盖、配方和产物封印，返回阅读版本、报告 SHA、报告原路径及候选身份。查询不运行模型、不初始化或升级库；旧库需要显式升级，缺失库、尚无当前结果和旧未验证报告分别说明。产物损坏报错，不用重新抽取来掩盖损坏。机检与已保存的审阅记录仍不证明全部语义正确。

L2 的 queue/record/skip 是事实处理任务，其回执不是全文阅读报告。旧 l2_read.jsonl 保留为历史处理台账；documents_processed、already_processed、eligible_unprocessed 与相似提示中的 processed 只反映事实处理。旧回执不自动导入为 reading_run，也不改变全文完成数。

L2 pack 有合格当前结果时，复用其已核对的页块正文和报告版本；每个任务包固定引用生成时看到的版本，之后切换当前结果不改写旧包。没有合格当前结果时仍可提供抽取输入，但不得称其为已完成全文阅读。pack --again 只是重新处理事实；正式全文重读与替换继续按第 8 节执行。

两个客户端须使用同一数据根：READER_DATA_ROOT，或分别使用 reader --data-root 与 deep-read --reader-data-root。未配置的跨机器副本不因此自动同步；真实旧资料须先清点、核对覆盖与身份后受控导入，不能凭人工回执编造完整产物。
