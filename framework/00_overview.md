# 研究框架总览 — 15 模块 MECE 地图

> 本框架是项目的稳定骨架：**穷尽（覆盖数据中心行业全部维度）且互斥（每个事实只归属一个模块）**。
> 数据与结论会变，模块划分与模块间逻辑不变。调整框架本身需要走"框架变更"流程（见文末）。

## 三维体系

原 Q1–Q35 报告沿"物理供给链"展开，本框架将其升级为三个维度：

```
物理维度（供给链）    M01 规模 → M02 供给 → M03 需求 → M04 电力 → M05 土地
                      → M06 芯片 → M07 网络 → M08 散热 → M09 电气设备 → M10 建设运营
资本维度              M11 资本与金融（每 MW 值多少钱 —— 行业最硬的价格信号）
经济学维度            M12 需求侧经济学（Token 经济 —— 200GW 叙事能否成立的最终检验）
                      M13 有效算力（物理 GW → 经济 GW 的转化率）
横切维度              M14 中国板块（独立地缘/政策/供应链逻辑，与海外对照）
综合层                M15 情景与监测（唯一允许跨模块引用结论的模块）
```

## 模块间的固定逻辑（数据流向）

- **M01 只做口径对齐**，不自产数字；它的输入是 M02–M05 的实体数据聚合。
- **M02/M03 共享项目库和合同库**：一个项目在 M02 记"谁建"，在 M03 记"谁用"，容量数字只存一份。
- **M04–M10 是约束条件模块**：各自回答"这个环节会不会卡住 200GW"，输出统一格式的
  瓶颈评估（交期、产能、缺口），汇入 M15 漏斗。
- **M11 的每 MW 成交价、M12 的单位算力收入、M13 的利用率**是三个最领先的周期指标，
  领先物理层空置率 12–18 个月，M15 的预警首先看这三个。
- **M14 平行于 M01–M13**：同样的模块逻辑在中国语境下单独跑一遍，避免中外数据混加。
- **M15 是唯一的综合层**：只有它可以跨模块引用结论；其他模块之间只通过数据表交换事实。

## 每个模块的统一结构

每个 `modules/Mxx_*.md` 包含五节，缺一不可：

1. **定位与边界**：管什么、不管什么（互斥性声明）
2. **核心问题**：4–8 个持续追问的问题（原 Q1–Q35 映射到这里）
3. **关键指标**：可量化、可更新的指标，注册到 `indicators.json`
4. **数据依赖**：依赖六张表中的哪些表、哪些字段
5. **更新节奏与输出**：多久刷新一次结论、产出什么形态

## 框架变更流程

模块的增删、边界调整，必须：在本文件记录变更日志（日期 + 理由）；同步更新
`modules.json`；检查受影响模块的互斥性。日常研究**不允许**为了方便临时跨界。
