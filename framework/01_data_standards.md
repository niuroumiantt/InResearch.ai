# 口径与核验规则手册 v2

> CURRENT · 2026-09-06 生效。归属与替代记录见 [当前基准](CURRENT.md)。本手册适用于骨架研究（一棵树、五类变量、四问）；机器枚举与保鲜阈值由 `framework/data_contract.json` 统一声明。旧手册已归档，不再作为并行规则。

### 普通信息来源登记（2026-10-12，替代普通园区信息的前置事实审核）

按用户最新决定：普通信息先登记唯一主体、再持续更新，不以真假判断、全文阅读、C3评分、模型需求、专用采集凭证或网页URL为上线前提。`source-statements` 把原件中的已有信息追加进现有 `projects.json` 的 v3 观测；来源原件和版本指针保留，公开标记“基础登记待查”，不填写虚构的核实日期或审核分数。已知数字、区间、主体角色、水电指标可直接登记，缺项后补。结构、唯一身份和来源字节的检查属于防止串号、重复写入和丢失原件，不是事实核验。

普通类型对象的技术归类更正也保留历史：`registration_correction={of,action,reason}` 通过原具名操作员 `source-statements`／独立资料发布入口追加，状态仍为 unverified，不填写 C3 审核。`reclassify` 只允许改 metric／scope，原对象 ID、值、单位、性质、来源原件／局部引文、有效／披露／首次接收时间与时间范围逐项相同；同一旧归类只能更正一次，后续更正指向最新更正记录。原记录不改不删，当前字段和首页更新使用新归类，历史保留并按现有公开 revision 字段表达更正链。

姓名边界不明的普通对象可追加 `quarantine_identity`；同对象只保留一份当前隔离状态，`release_identity` 仅恢复已隔离对象。两者都不修改对象、字段、范围、值、来源或信息时钟，不推断另一个主体 ID，不删除原件、旧 ID 或资料。隔离中的普通对象不进入读者字段／首页更新／运行公司名录，原始审计保留；明确身份后再显式恢复或登记正确主体。任何已含正式研究观测的对象都不能由普通隔离隐藏，研究结论及既有 C3 修订仍走原所有者边界。此机制只适用普通类型对象，不扩大园区身份、坐标或既有研究修订权限。

首次物理园区的 `identity` 可成对提供 `coordinates`（现有 `lat,lon` 字符串）与 `coordinate_source`，未知时两项都省略。坐标须为有限数值，纬度在−90至90、经度在−180至180；来源注明 `coordinate_system=WGS84`（地图展示基准）、`precision=address/site/building`、`method=address_geocode/source_map/reported_coordinates`、真实归档 `source_sha256`、HTTPS来源、`locator` 与 `basis`。运营商表格中的自报坐标用 reported_coordinates，来源未明示坐标基准时在 basis 明说按 WGS84 展示，不能声称原文定义了该基准。地址地理编码只登记为 address 精度，不能声称是实测楼体中心；城市/国家中心不能冒充园区点位。登记及相同请求重放均复验定位来源原件字节，既有物理身份、坐标与定位说明不能通过普通追加改变。来源字节与接收审计留在私有记录，页面只投影精度、坐标系、方法、允许公开的来源URL与说明；坐标登记仍属基础登记待查，不授予C3或模型支持。

同一主体、字段、范围按有效信息时间选当前值；有效时间未知时依次使用披露时间、首次实际接收时间、首次登记时间，字段 `selection_time_basis` 明示选择依据，不补造有效时间。相同时间取较后登记的版本，分歧标注保留；所有旧记录仍可查，展示更新不改写历史。规划、投运、设施功率、水量和能耗分别存储，不混成一个数字；未来预测保留独立显示。无法唯一匹配的保留为线索；同城、同名、近似坐标不自动合并。条目失败不阻断同批其他对象，私有回执保留失败输入。

本节是普通来源登记的现行入口，取代下文旧逐条审核通道对普通园区信息的强制C3和未知时间不能更新的限制。下文 `project-review` / v2 仍是主动进行研究核验时的路径；来源登记不冒充已核实证据、完整答案或已验证模型输入。原件全文、私有路径、凭据和受限内容不随字段登记直接公开。首页与园区API共用同一字段投影；源码通过、登记成功和实际上线分别计量。

本次先实施园区入口，其他对象的旧 `object-review` 仍须后续贯通；不以本规则文本声称全类型改造、全库存量处理或171/17闭环已完成。


来源登记的阶段可以未知（2026-10-12）：首次v3园区未披露当前建设阶段时，status与verified_date均为null，不默认L1传闻或L2规划。旧已审核项目的缺失阶段仍报错。归档来源URL允许null且grade=source_statement，与真实catalog指针、独立首次接收关联；首批工程表登记不代表项目近期发生建设事件，不填容量和运营角色。相同明确项目名的多份工程表共用同一ID，分开保留来源记录。

## 1. 对象、记录与研究状态

骨架节点（系统 → 链路 → 部件，站点权利，主体）回答"哪个对象"，五类变量回答"哪一类数"；项目 L1–L9 是建设成熟度；尺度 S1–S5 是部件属性；M01–M15 只是兼容属性。四者不能混作一个层级编号。

对象类型、厂商产品线、具体型号、现场资产、公司和业务角色分开。一个对象有稳定 ID，可关联多个视角与问题。文档以内容哈希确定版本身份，名称、目录、评分和发布时间不能代替身份；改名不重造事实或重复计算资产。

文档登记、阅读覆盖、质量检查、核验、研究采用分别记录。资料计划与历史索引不证明原件可访问；全文读完不等于观点已被采用。数字与非数字证据都需原文定位和适用条件。**逐条信息采用不以整篇阅读完成为前提**：唯一物理对象身份已核实、相关原文及必要上下文／表头脚注已审阅、时间与口径明确或显式未知，即可独立进入条目审核；不得把局部核验写成全文已读或全文无反证。

2026-10-11 定向证据：园区信息入库不以关联研究需求为前提。`object_excerpt`冻结唯一已登记园区、字段、范围、原件 SHA、页码和完整所选页上下文摘要；`target_ids=[]`明确不声称模型支持。收到的 inews 事件也可凭同样对象绑定逐条更新既有园区。原件、引文位置或对象绑定变化使旧审核失效；原`targeted_excerpt`任务通道仍复验当前需求定义。`coverage.mode=targeted, complete=false` 和逐页 `reviewed_spans` 保留未全文阅读的事实。局部支持陈述只认可对应页及上下文摘要的证据；正式综合答案仍须满足其独立问题验收，不能因一个局部条目采用就自动闭题。园区采用通过现有 `project-review` 的 `object_excerpt`或`targeted_excerpt`来源适配器，继续保留实际 C3、来源权限、独立时间及历史版本；不创建第二个发布队列。

园区常规表达以 `site_id` 为稳定引用，国家、省州、城市、街区、街道地址及地块编号单列，未披露留空，地点原始描述保留。名称相同、同城或近似坐标不能自动归并；地址细化不能变成园区搬迁或扩大到地区组合。主体按土地权利人、资产所有者、开发方、设计方、EPC／总包、运营方、直接承租／使用方、最终使用者、股权出资方、贷款方、借款主体、担保方、租约出租方及电水网络服务方分别记录。同一公司可兼任多项，行业分类不证明园区角色，贷款不证明所有权。角色观测带有效时间、来源及审核时间。

规划 IT 总容量 `capacity_planned_it_mw` 与已投运 IT 容量独立记录，前者只接受明确的园区整体规划口径。旧筹备／建设分期不是规划总量，不能相加推造；规划减投运也不能推成在建量。未来容量、停工、取消、范围及口径变化留在时间线。水耗、取水、日用水、电耗、PUE、WUE 为可选指标，缺失不阻断园区登记；量、流量、功率与能耗分开，保留原生区间、统计期间、边界和测量／估算性质，估算与预测须有依据和假设。


### 正式研究库与 raw 资料库（2026-10-11）

两层是信息成熟度不同的持续台账。raw 先保存新闻、来源研究中的单一角度、项目/主体/地点、容量原文及口径、日期和来源，允许首页按报道状态与位置粒度展示；接收、公开专题发布不授予事实采用。正式层逐项核对身份、地点/边界、主体角色、阶段和时点、容量定义/单位、证据与去重，并保留有效的具名审核与采用回执。十二角度用于呈现已有和待补信息，当前不设置“超过N个字段即可自动验证”的门槛，也不把缺角度资料丢弃。

同一资料可保留 raw 原文版本并由正式字段引用；采用补充与替代仍沿原有链路，不能以模型分数、新闻新鲜度、字段数量或页面显示替代 C3。既有项目登记日期只证明登记时点，不能宣称整份档案已验证。raw 的 MW/GW、供电/发电、规划承诺和 IT 投运分开，首页可见不改变正式合计。

## 2. 口径相容才可比较与汇总

下列是原有四类常用数量，不是整个行业的指标全集。计算性能、精度、存储、带宽、延迟、流量、温度、可靠性、利用率、Token 和价格等指标各有独立定义，由 `metrics.json` 声明维度。

| 数量 | 常用单位 | 边界 |
|---|---|---|
| IT 容量 | MW / GW | 与设施功率、合同容量、规划容量分开 |
| 设施总功率 | MW / GW | PUE、负载率、工况和边界须明确；估算不冒充披露 |
| 用电量 | kWh / MWh / TWh | 指明统计期间；功率与能量不能直接混加 |
| 投资与资本开支 | USD / CNY 等 | 明确币种、年份、期间、范围与已承诺/已支付等状态 |

- 比较至少对齐指标、单位、口径维度、对象范围、时间、区域和实际/预测属性。来自不同口径的数保留差异，不为凑总数强行换算。
- 官方未披露字段保持空值；研究当前参考值允许估算、区间和后续细化。估算必须有类型、依据、假设或待补条件及时间，不能冒充官方披露或实测。继承的历史估算可标记 `legacy_estimate/provisional` 留用，原件或估算方法未追回须明示，不因缺少精确值一律清空。
- `capacity_assessment` 标记当前容量参考值的估算性质；行业汇总保留参考值并分列估算份额，页面同时显示状态、时间和待补条件。模型情景仍按自身适用范围审核，单一项目估算不自动推广为通用参数。
- 厂商宣传记录为 `author_claim` 等候选类型。设计规格、实测结果、推算和作者观点分别表达。
- 数值缺失、未披露、不适用、范围与上下界分开；未知不能写成 0。

## 3. 项目成熟度与容量去重

每个园区保留 `site_id`，分期/容量批次各有状态。项目改名、转手、分期及不同交易双方的披露不能重复计算同一物理容量。

| 状态 | 定义 |
|---|---|
| L1 | 传闻或意向 |
| L2 | 官方规划 |
| L3 | 土地锁定 |
| L4 | 电力申请 |
| L5 | 电力确定 |
| L6 | 开工建设 |
| L7 | 机电安装 |
| L8 | 通电投运 |
| L9 | 满载运营 |

当期已投运供给仅计 L8/L9，不能与其他阶段加成同一个“当前容量”。原始项目台账按来源披露和状态保留；只有明确的情景预测才使用有证据、时点和适用区域的转化率，并把预测结果单列。不得自动给所有早期项目乘一个系数后覆盖原始汇总。

`capacity_it_mw` 与 `capacity_it_mw_by_status` 不得并填。运营商签约容量与客户租用容量通过合同关系对应，避免双计。第三方总量保留为独立基准，不能混入自下而上的项目明细。状态更新保留前值、变更时间和依据，不把 P/F/V 的分类变化写进 L1–L9。

已确认同一物理项目的不同 ID 用 `duplicate_of` 指向无别名链的主记录，并附 `deduplication_note` 审阅依据。保留原记录、来源冲突和时点；行业聚合仅取主记录容量分期，关系与来源并列展示，不凭较新日期覆盖。禁止按相近坐标或同城市自动合并。来源年份、负载定义或覆盖范围未对齐时，全球基准与项目样本不做相减或覆盖率；样本集群边界和未披露量如实说明。

首次物理园区登记（2026-10-12）：object_excerpt或已接收日报可在target_ids=[]时提交initial_identity及首条v2观测。身份明确包含site_id、名称、国家、区域、来源地点和native_name/basis；省市街道、坐标及容量未知允许留空，来源原文中的园区名必须出现在已复验引文。新增名称/别名先与现有园区检查；同城不能证明同址。首次基线容量为空，已披露容量通过观测追加；首条必须审核name/status，非空主体字段也必须属于本次审核字段。禁止注入既有观测、采用历史或身份登记记录。沿用原件SHA、局部上下文、具名C3、独立时间和无写重放；后续更新仍核当前基线，不能搬迁或合并身份。归档无URL的园区来源入口、按条失败隔离和全库存量完成不由此能力证明。

### 持续更新的对象与观测（2026-10-11 用户方向）

项目维护稳定物理身份与边界，各公司/运营商/租户关系随时间变更；同城、同名或相近坐标不能自行归并。分期、扩建、相邻新园区以关系连接，避免重复计量。

每个指标按自身口径保存时间序列：数值/区间、单位、空间/分期/运行状态、有效时点、来源发布时间和接收时间、披露/估算/预测性质及依据。已取得同对象同口径的新观测时，以最新有效时点更新当前参考，历史仍可查询；接收日期和网页重抓时间不是项目状态日期。未来规划与当期运行分别更新，避免未来大容量覆盖当前运行。旧记录只有核验日期时，不能伪造观测日期。

合理小幅变化、约数及估算不构成拒收理由；身份、单位、范围和可解释依据是主要门槛。量级突变、零/非零切换、停工/取消与重大边界变化触发复核并保留新线索，不机械删除；增长也可能是扩产事件。设施/IT功率允许有明确PUE和边界的估算换算，水量/功率/电耗等不同指标不能只按数字相近直接覆盖。阈值应按指标制定，不用全站一个误差百分比。

正常新增时点不是撤销旧时点的事实；更正同一时点的错误、身份合并和分发放宽仍保留具名审阅与替代链。日常新闻用于定位对象和触发补采，不凭一条标题直接改全部字段。

项目观测由 `project-review apply` 的 `observation` 路径追加到 `projects.json` 对象，旧字段保留为历史基线，不建立第二套项目真值库。`effective_at`、`kind`、`basis`、`scope=whole_site` 与明确字段集共同限定本次变化，沿用实际原件、引用、具名C3、当前需求和乐观并发核验；正常新增时点无须撤销旧基线。地块身份、位置、重复合并不由此路径更改。容量总数/分期/估算性质作为原子束更新，禁止新旧两套重加；分期须有不重叠的独立来源断言。

独立保存 `effective_at`（对象/指标有效时间）、逐 SHA 的 `source_versions[].published_at`（该来源版本披露时间）和 `source_versions[].first_received_at`（本系统首次有记录的接收时间）；`reviewed_at` 与 `recorded_at` 分别是审核和正式写入时间。首次接收取实际归档/接收台账，不能由提案自报、审核日期或重放索引时间补造。未知使用 null 并保留依据；只知年、月、日就保留原精度，精确时刻必须带时区。页面 Updated 仅证明该版本更新日期，不能改写卫星图、施工或测试的有效日期。已索引的旧日报首次接收若不可恢复，保持未知并保留旧接收字段的历史含义。

当前项目视图逐字段按有效时间选择：完整晚于旧观测的年/月区间可以更新当前参考；时间范围重叠且值不同则保留分歧，不能用到达顺序或日期字符串挑胜者。未知时点保留待细化，未来时点和预测单列。等价单位先规范化比较；区间使用 `{value_range:[下界,上界],unit:"MW"或"GW",basis:依据}`，不取中点、填零或并入精确单值合计。IT 总数/分期/估算性质同束更新，`phase:<明确ID>` 仅更新该分期视图，不自动累加进整个站点。业主、开发方、建设方、运营方、使用方可独立变化；暂停、取消、关闭保留地点和历史容量，但不并入活跃容量汇总。事实库的其他指标仍沿用原有原子记录，不将站点观测自动推广为模型参数。

同一时点的更正/撤回追加 `revision`，指向仍有效的旧观测，范围、有效时间和字段束必须相同；保留旧记录和实际所有者对具体 after 的采用决定。普通新增时点沿具名 C3 审核，无须把正常状态变化登记为撤销旧结论。相同提案重放保留第一次正式写入时间，不生成新历史。

首页面向读者展示最新有依据的变化、有效时间、估算/区间/预测性质、公开来源与历史；接收计数、审核队列、复核派工与运行水位留在后台。尚无正式观测时如实给空态，公开来源资料仍可独立阅读。日/周/月任务规划、实际采集、封存阅读、正式采用和网站回执分别验收；六队的共用需求/原件/审核入口不表示四支未接通队已经运行。

## 4. 来源、冲突与证据采用

归档资料的对象优先接入（2026-10-12）：公司、产品、统计和报价的逐条观测可使用真实catalog导入来源，不强制先有HTTPS网页或特定采集sidecar。审核入口重新核原件SHA、documents身份及sources实际记录；首次接收取真实导入时间，冻结来源记录ID、路径摘要和接收时间。路径/个人资料留在运行库，Git只留摘要。网页URL未知保持null，不补造链接；公开仍需具名审核明确允许字段分发，购买原件不自动公开。原件/导入记录变化须重新审核，缺项、估算、未知时间不阻挡明确对象的初始信息。入库不等待全文阅读或模型用途；这不自动完成新园区创建、全文阅读、模型验证或受限分发授权。

| 分级 | 字段 | 来源类型 |
|---|---|---|
| S1 | regulatory | 监管、司法披露 |
| S2 | company | 公司一手披露 |
| S3 | research | 研究机构原报告 |

分级用于安排核验优先级，不是自动裁决真假的排序。先核对是否同一主体、指标、版本、时点、范围与工况；不相容的记录应并列并说明。相容口径仍冲突时保留双方与原文，标记争议并进入 C3 A 档，不因来源等级或发布日期直接覆盖。转载同一原文、两次 OCR 或两个模型复述不算独立来源。

估算须附 `assumptions`；预测与情景记录不等同观测事实。对作者主张的引文只证明“作者这样说过”，不自动证明其主张为真。

公司、产品、统计和报价也按唯一对象逐条采用，不要求研究目标。公司按已登记法人；产品按厂商、确切型号与版本（未披露版本明确记 not_disclosed）；统计按发布方、原生系列、地区和定义；报价按卖方、完整配置、市场、币种与计价条件。统计均价不是采购报价、产品额定值不是机房实绩。data/object_observations.json 保存正式追加观测和冻结身份，原有档案、候选目录与模型参数不自动覆盖。有效、披露、首次有记录接收、审核和写入时间分别保存；未知允许为空，不拿下载/cache 日期代替生效日。原生 JSON Pointer 取值与原件类型和值完全一致；文本证据核相关页及表头脚注。区间不取中点、冲突并列；修订/撤回指向同对象同范围旧观测并有所有者采用。

object-extract 和 object-review prepare 只做标准库提取、原件SHA/定位及身份冻结，不调用模型或生成审核。object-review apply 复验冻结提案、实际具名C3和确定性抽样，按CAS一次追加；重放不刷新历史。语义、工况及争议审核记录实际执行。

研究采用与公开权限分开：字段清单唯一源为 `framework/research_publication.json`，首页和 `/api/observations` 复用服务端投影。具名审核确认 `public_fields_reviewed=true` 后，允许公开清单内的对象、数值/区间、口径、条件、独立时间、来源链接、冲突和历史修订；缺项、未知时点、估算和冲突不构成整条阻断。不因选择网页或API而改变内容权限，不每批重复征求所有者确认。原件上下文、完整引文、内部接收/审核审计不自动随观测公开；其中一项受限不阻断其他经审核可公开字段。分发受限原件的放宽仍按下述所有者边界。

未来付费会员用于提供更完整的研究内容、检索和历史服务；不等同开发后台权限。当前 `member` 是内部团队角色，不是付费权益。会员内容须由服务端校验独立权益和资料分发范围，不以浏览器隐藏字段实现权限，不因付费自动取得受限原件或运行凭据。本次实现公开研究投影，不声称支付和会员权益已接通。

C3 的唯一现行定义在本节：

- A：自评 ≥8、敏感、与既有事实冲突，或拟改写既有结论，任一成立即由所有者审核。不得靠重新评分绕过 A。
  - **可委托，但审核者必须记名（2026-09-13 增）。** 所有者可把 A 档复审委托给具名代理（含模型代理），审核记录须写明实际审核者是谁、依据哪次委托，并与所有者本人审核区分。**默认口径是记名，不是署名所有者**——让记录说出实际发生的事，比让它看起来合规更重要。
  - **登记实现（2026-10-09 补齐）。** 新增或补充研究的代理采用记录使用 `review.tier=A`、`authority=delegated_reviewer`，`by` 为实际审核者；`delegation` 必有非空 `delegate`（与 `by` 完全一致）、`granted_by`、`granted_at`、`reference`、`scope=new_or_supplemental_research`。委托只知日期时按 `YYYY-MM-DD` 保存，不补造时刻；已知时刻须带时区，审核 `review.at` 仍须为实际带时区时间。授予日/时间不得晚于对应精度的审核日/时间。结构校验不认证所有者身份或委托真实性，仍须人工核对真实授权及可公开的引用；不能写成所有者亲审。
  - **两类不随委托转移**：①**分发受限材料的对外暴露**（原件标注机密/内部资料/禁止转发的），代理可以收紧、不可放宽，放宽由所有者决定；②**拟改写既有结论**，代理可给出建议与证据，采纳由所有者决定。理由是一样的：这两类的后果由所有者承担，而承担后果的人才是能同意的人。
  - 记录或审核声明非空 `replaces_record_ids` 或 `relaxes_distribution=true` 时只接受 A 档 `authority=owner`；空替代列表/明确不放宽不取得额外权限，坏类型拒绝。具名委托不代替原文、该条信息所需上下文覆盖、冲突核对或支持链审核；局部证据不要求整篇完整阅读，接收快照仍只产生候选。正式 adopted API 仅公开实际审核者及上述最小委托字段，支持证据也保留审核归属，附加私有审计字段不随之公开。
  - 委托复审同样不得靠重新评分绕过 A，也不得因来源等级或发布日期直接覆盖冲突的一方（见本节冲突规则）。
- B：自评 5–7、命中当前有效工单（或已明确唯一对象、字段及范围的条目）且无 A 类条件，由模型审阅并做确定性 10% 抽样复核。未匹配工单且未完成对象条目绑定的自主发现保留候选待匹配，不能宣称 B 审核已完成，也不因此降低材料内在价值。
- C：≤4 且无 A 类条件，仅候选存档。C 档不能作为正式采用的审核记录，不能关闭研究问题。

资料接收、机检、分流、模型审核与核心研究采用分别记录。成员投递的 `--accept` 只导出候选 CSV；改写意图用 `replaces_record_ids` 声明并进入 A，但声明本身不授予覆盖权。文件名/标题碰撞仅提示，同名新版不能拒收；真实材料身份由材料接收流程核对字节 SHA，不能从元数据推断。数字与非数字证据都可进入候选。

reader 和接收 API 只产生 candidate；正式回答需已采用证据、完整覆盖、原文定位及有效 A/B 审核记录，满足 `src/inresearch/knowledge/registry.py` 的验证才能关闭问题。人工审核记录仍须按本节判断资格，结构校验不代替口径判断或模型审核的实际执行。C3 待审不阻断其他文章阅读。

2026-10-09 技术对象归属补审：已采用陈述/证据若仅需删除错误的机器对象ID，可在保留原B/A审核的同时追加具名A `object_mapping_review`。限于对象集合的严格子集（可为空），不得新增ID；完整 `before_record`、其SHA、实际补审者/时间/委托、理由和审计引用必须齐全，除 `object_ids` 与新增补审字段外逐字段不变。该补充不撤回原文叙述、不替代结论、不改变问题/证据/源身份/状态/分发；正文、支持关系、权限或结论变化仍走上述所有者通道。结构校验不能证明授权真实性或对象语义正确。

### 历史事实的支持原件再核验（2026-10-11）

历史事实可以通过实际核验现存原件的字节 SHA、相对路径、物理页及连续引文，重新建立当前支持出处。此时 `evidence.identity_basis=reverified_support_original`、`historical_exact_input_identity=not_established`，并以 `support_reviewed_at` 保存实际复核日期；`local_file` 使用已核验的资料根相对 `originals/` 路径，不能从文件名、标题或数字相近推断内容身份。字段定义见 `data/schema/fact.schema.json`。当前匹配原件的字节已核验，不等于历史输入/下载与它逐字节相同；历史同一性仍需历史摘要、封存阅读版本或可核对的原输入链。

“当前缺支持 SHA”与“历史原输入同一性未建立”分开计数。重新绑定当前支持原件不自动减少历史输入同一性债务；各批次的原始分母、已核实支持数量与剩余缺口保存在采用回执，不互相冒充。再核验不自动提升 grade、depth、corroboration 或刷新 `as_of`，也不构造一次全文阅读或独立来源确认。报告封面日期、复核日期、所有者授权日期和事实有效时点分别保存；只知日期时不补造精确时刻。

同一现存原件支持旧说法的一部分，不代表旧值、主体、时间、范围和边界全部正确。既有值、区间、主体、口径、边界或性质更正仍按§4由 C3 A/owner 采用；保存完整 before/after、规范紧凑 JSON 的 SHA、实际研究复核者、所有者的明确采用答复与已知日期精度。作者明写的区间补入 `value_range` 会将原先数值留白改为公开区间，是结构化输出变化，不能夹带在自动 SHA 元数据修复中。所有者采用不写成所有者亲自核读原件；待审提案快照保留当时身份，不追改成当时已采用。

`fact_contract.check_fact` 对上述三字段执行实际结构校验：出现任一字段就必须有有效的再核验 basis、`not_established` 状态及合法日历日期；路径必须是与 SHA 完全相符的 `originals/{sha[:2]}/{sha}/{filename}`，文件名单层、非空且无目录跳转、反斜杠或控制字符。没有这三字段的旧 evidence 沿用既有合同。机器不访问原件文件系统，结构通过不证明原件存在、SHA已实测或语义复核实际发生；这些仍依实际核验与采用回执，不以本地路径或夹具假冒真机核验。

保鲜阈值的唯一机器定义是 `data_contract.json`：L6–L9 项目 90 天，L1–L5 项目 180 天；项目超阈进入复核队列并在视图标记，不因年龄使历史事实或全站严格校验失效。日期格式仍校验；重新抓取同一网页不刷新事实有效时间。价格按序列频率判断：annual 455、quarterly 150、monthly 45、spot 30、default 365 天；显式 frequency 优先，兼容序列名规则见同一声明。一次性 benchmark 与历史序列点保留原时点，不逐点当作当前报价催更新。

历史记录不因过期而删除。当前输出若引用过期或未核验结论，必须标明历史/待复核状态；不得伪装当前事实。各校验器只证明其实现的检查项，不能宣称机器已经完成全部语义核验。现有 `needs-review` / `stale` Finding 导出带警示，不应写成“全部输出自动剔除过期内容”。

## 6. 厂商性能数字的条件核对
