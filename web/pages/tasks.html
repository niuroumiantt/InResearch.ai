提问时先明确对象与范围

研究对象是什么，边界在哪里？

对象身份；范围与包含／排除；适用条件和未知边界。

由什么组成，各部分怎样关联？

通用构成和接口；实际配置及关系；类型／产品／实例证据连接。

怎样运行和演变，实际表现如何？

性能与资源使用；建设和生命周期事件；测量、设计、推导、计划及预测的分离。

产生什么结果，依据和缺口是什么？

经济及非经济影响；推导与适用性；反证、限制和后续问题。

POWER · MW / GW

容量：某个时点能承载多少

IT 负载 ≠ 设施总功率 ≠ 并网配额 ≠ 发电装机 ≠ 客户合同容量。

园区总量与分期不重复相加；已投运、在建、规划分别记。估算、预测和实测分别标注，区间不取中点。

ENERGY · MWh / TWh

电耗：某段时间实际用了多少

记录年度/月份、设施边界、计量范围与 PUE。国家总电耗保持国家口径。

MW × 8,760 不能直接当年用电；缺少实际负载率、运行时长和边界就留未知。PUE 不是负载率。

04 / DELIVERY

原件是底座，结构化候选让入库更快

优先交：原生 PDF / HTML / XLSX / CSV / API 原响应 + 来源清单和 SHA + observations.jsonl。

原生表格保留行列、表头和脚注，原生 PDF 保留可检索文字。扫描 PDF 原件仍要交；团队如已做 OCR，按页另交文本或 JSON，注明工具/模型版本、漏页和未读图片。OCR JSON 是派生副本，不能替代原件。网站默认正文阅读，不自动启动 OCR。

一包材料，六个入口

delivery-<team>-<UTC>-<batch>/
  manifest.json         来源、原件与采集器
  SHA256SUMS            原件 SHA + 相对路径
  originals/<sha>.*     不改字节的原件
  observations.jsonl    一行一个对象/指标/证据
  errors.jsonl          失败、缺失与未披露
  run-report.json       成功/失败分母与耗时
  derived/              可选文本 / OCR / JSON

模板使用 fetchdata-handoff/1 候选交换契约；空模板不算有效交付。四队接收联调与逐批真实回执另验，不能冒充 Fetchspec 请求格式或直接覆盖正式库。

机器、模型与人的分工

  1. 机器抓取与保存固定字段、下载、原件 SHA、分页与日志。填写实际主机和采集器版本；Spark 保管原件与阅读，不派去爬取。
  2. 模型按需辅助用原生文字定位/抽取；记录实际模型版本与阅读范围。每条候选带逐字引句、页码和限定条件，人工核读扫描表。
  3. 负责人交包离线验包，记录未找到的字段、错误和冲突；填交付地址或接收回执。真实材料与凭据走私有目录。
  4. 研究端映射与登记核对唯一身份和来源字节，映射后追加普通来源登记；正式结论、答案和模型支持按 C3。原件接收、阅读、登记及上线分别回执。
查看“一条候选”应带什么

一个园区 / 一项指标 / 一个范围：object + metric + 原始值与单位 + scope + 数值性质 + 信息有效时间 + 披露时间 + 原件引用 + 定位 / 原文引句 / 上下文。可附 target_ids: []，一般信息不强制绑定模型研究需求。

信息未知时用 null 与原因；未找到不填 0。明确别名与分期，保留旧版本、revision_of 与已知冲突。材料取得时间不能充当核实时间。
