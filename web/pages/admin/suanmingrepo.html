# Knowledge Model

This document defines the first internal model for the product's calculation and interpretation architecture. Each module is designed so it can later become a shared service for WeChat Mini Program, H5, and iOS.

## Product Interpretation Position

The product separates three layers:

| Layer | Meaning | User-Facing Explanation |
|---|---|---|
| Natal Structure | Long-term symbolic structure derived from birth date, time, and eventually birthplace | "出生信息生成本命结构，描述长期倾向和观察框架，不等于命运被决定。" |
| Daily Timing | The current day's calendar, stems/branches, solar terms, and transits | "今日运势是本命结构与今日时序的关系分析。" |
| Question/Today Hexagram | A dynamic symbolic reading generated for today's date and user focus | "今日卦象针对今日时点与所问主题，不是出生后永远固定的本命卦。" |

## Suggested Data Flow

1. Normalize input: date, time, time zone, birthplace.
2. Build `NatalStructure`: calendar, four pillars, five phases, western natal placements.
3. Build `DailyContext`: today's calendar, solar term, daily stem/branch, transits.
4. Build `QuestionContext`: focus area or explicit user question.
5. Run selected modules.
6. Generate interpretation with source tags and uncertainty flags.

## UI Source Tags

Every professional card should be able to display:

- `依据`: source IDs
- `输入`: what user data was used
- `规则`: selected rule family
- `置信`: exact / approximate / needs birthplace / needs solar-term verification
- `边界`: what this module cannot claim

# Source Registry

This registry defines the source hierarchy for the astrology and calendrical knowledge system. The product should cite the most authoritative applicable source for each calculation or interpretive claim.

## Source Tiers

| Tier | Role | Use In Product | Reliability Rule |
|---|---|---|---|
| T0 Computational Standards | Calendar, solar term, ephemeris, and astronomical position calculation | Date conversion, solar terms, sexagenary cycles, planetary positions | Use for calculations. Do not replace with interpretive books. |
| T1 Classical Foundations | Canonical cosmology and symbolic frameworks | Five phases, yin-yang, trigrams, seasonal order, change logic | Use for theory framing and explanatory source notes. |
| T2 Technique Manuals | Practical astrology and divination rule systems | Four pillars, hidden stems, combinations, clashes, Na Yin, timing rules | Use as rule families. Label school differences clearly. |
| T3 Modern Reference | Neutral encyclopedia or technical documentation | Western zodiac, horoscope structure, software/ephemeris explanation | Use for user education and implementation context. |
| T4 Product Interpretation | Our synthesized explanation layer | Plain-language readings, cautions, daily advice | Must point back to T0-T3 sources and avoid deterministic claims. |

## Citation Policy

- Calculation claims should cite T0 sources first.
- Interpretive frameworks should cite T1 or T2 sources.
- Western astrology educational text can cite T3 sources.
- If two sources disagree, the UI should show the selected rule family, not hide the disagreement.
- Product readings must use language such as "观察", "倾向", "结构", "参考", and avoid "必然", "注定", "一定发生".
