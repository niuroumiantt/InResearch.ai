# inews

从站长指定的媒体搜索页或官方 AI 专题取回文章(标题、时间、链接、正文)，生成一份
只供自己学习的静态站点；正文库不进入公开仓库。

目前接入 **Financial Times**、**Bloomberg**、**CNBC**、**The Wall Street Journal**、
**Reuters** 与 **Axios**。项目、Python 包和命令统一使用
`inews`；旧的独立采集器品牌已经移除。新增来源只需实现 `inews/sites/protocol.py`
定义的适配器契约并注册，不需要修改通用编排。

```bash
pip install -e .
inews --group all --pages 5 --limit 20 --since 2026-08-01 --order oldest
open out/FT.COM/index.html
```

## 它做什么

1. **发现** —— 按站点适配器打开关键词搜索或官方 AI 专题，并展开页面的更多结果；
2. **合并去重** —— 同一篇被多个关键词命中只留一条,记下全部命中词;
3. **剔凑数** —— 同一篇出现在过半语义组下判为站方填充稿(见下);
4. **查台账** —— 爬过的跳过,只处理新增;
5. **取正文** —— 登录态直抓优先,失败走本机浏览器;
6. **落地** —— 各站 `index.html`(可筛选清单)、统一 Dashboard(后台 + 关键词分析)、
   `p/<年月>/<uuid>.html`(每篇一页)。

## 常用参数

| 参数 | 作用 |
| --- | --- |
| `--keyword "AI agent"` | 直接指定词,可重复;给了就忽略 `--group` |
| `--group all` | 跑全部语义组(词表在 `inews/keywords.py`) |
| `--pages 5` | 每个词翻几页;某页 0 条即停并说明原因 |
| `--limit 20` | 本轮最多处理几篇**新增**;`0` 表示不截断 |
| `--since 2026-08-01` | 只要该日期之后的;**缺时间的一律保留** |
| `--order oldest` | 按发布时间正序(旧→新) |
| `--no-body` | 只要清单,不取正文(这一轮**不写台账**) |
| `--no-translate` | 不翻译标题(默认翻新增的那几篇) |
| `--retitle` | 给库里还没有中文标题的补译,一次性;之后跟着新增走 |
| `--recrawl` | 忽略台账重爬 |
| `--include-seen` | 清单里也列出爬过的 |
| `--out DIR` | 输出目录(默认 `./out/FT.COM`) |

## 标题中文化

清单上显示中文标题,英文原题留在下面一行 —— **核对时要看得见站方给的那一串**。
译文进存档和台账,重画不会丢,也不会为了重画再翻一遍。

走 **Cloudflare Workers AI**(`@cf/meta/m2m100-1.2b`,翻译专用模型,不是对话模型)。
出网地址在 `inews/translate.py` 里**写死**:「能读谁」只随代码审阅变动 ——
和 `browser/contract.py` 那张域名表同一条规矩,只是这条走 HTTP 不走浏览器。

```bash
# 在 Cloudflare 面板建一个 token,权限勾 Workers AI(Read 即可)
cat > secrets/cloudflare.json <<'JSON'
{"account_id": "你的 account id", "api_token": "你的 token"}
JSON
```

也可以设环境变量 `CLOUDFLARE_ACCOUNT_ID` 与 `CLOUDFLARE_API_TOKEN`。
`secrets/` 已被 `.gitignore` 和 `tools/guard_standalone.py` 双重挡着。

**超时重试一次**(请求根本没被处理,再问一遍不会有第二个副作用);
**403 / 429 一律不重试** —— 重试它们一次都不会成功,只会把一个清楚的问题拖成
「怎么这么慢」,而 429 本来就是额度用完。

**没配凭据是常态,不是崩溃**:不翻就不翻,标题保持英文,并把「缺什么、放哪儿」
写进本轮记录。翻译失败留服务端原话(403 是 token 少权限、429 是额度用完 ——
两者处置完全不同,一句「翻译失败」会把它们抹平)。

每轮**只翻新增的那几篇**:成本随「新增」走,不随「库存」走。`--no-translate` 关掉。

库里的存量补一次(**不搜索、不取正文**,只把台账里没有中文标题的那些翻掉,
译文写回台账与存档):

```bash
.venv/bin/inews --retitle --limit 0
```

一条标题约 1 neuron,免费额度每天 10000 —— 补几百条也只用掉零头。

## 准备工作

- **登录态**:为需要订阅的来源在已登录浏览器里导出 cookie，分别存到
  `secrets/ft.cookies`、`secrets/bloomberg.cookies`、`secrets/wsj.cookies`
  (Netscape 或 JSON 格式都行)，也可使用对应的 `FT_COOKIE`、`BLOOMBERG_COOKIE`、
  `WSJ_COOKIE` 环境变量。没有文件时仍可尝试当前已登录的可见浏览器，但会更慢。
- **浏览器通道**(可选,用于直抓失败时兜底):macOS 上的 Chrome,装好你惯用的
  付费墙绕过扩展并保持登录。

## 几条不肯让步的规矩

这些不是风格偏好,每一条背后都有一次真实的事故:

- **档位决定会不会弹窗,而且只由档位决定。** `inews/browser/tiers.py` 是唯一
  的裁决点。无头档就只走无头,失败如实失败——**不回落**。回落曾经导致
  「一打开电脑就自动弹出标签页,不是我点的,也关不掉」。
- **能读谁不可热改。** 域名放行在 `browser/contract.py`,只随代码审阅变动。
  运行时配置可以改「怎么读」,永远不能扩大「能读谁」。
- **失败要留服务端原话。** 取不到正文就把原始错误渲染到页面上,不用「暂无内容」
  顶掉——兜底文案会把「登录态失效」伪装成「这篇没正文」。
- **不猜时间。** 文章页读不到发布时间就记「时间未知」,不拿抓取时间冒充。
  假时间会一路流进排序、时间窗和台账,而且看不出来。
- **过滤名单的判据必须是结构性事实**(是不是同一域名、产不产内容、时间在不在窗内),
  **不能是质量评价**(好不好、像不像新闻)。判据一旦从「是什么」滑向「好不好」,
  那份名单就变成一个绕过系统的私人黑名单。

## 凑数剔除

站方真实命中不足时会拿最近的普通新闻填满结果页。这类凑数的指纹是
**同一篇出现在几乎每个关键词底下**——它不是被搜出来的,是站点的「最新新闻」。

判据:出现在**过半语义组**下即剔除。**票按组算,不按词算**——按词算会把最正中
靶心的那篇误删(一篇好的 AI 报道天然同时命中 `AI agent` / `agentic AI` / `AI coding`)。
搜过的组少于 3 个时不判:样本不足就不下结论。

## 产出目录

```
out/FT.COM/
  index.html  dashboard.html  site.css                ← 独立清单、兼容后台与样式
  p/2026-08/<uuid>.html                              ← 每篇一页,按年月分层
  data/articles/<uuid>.json                          ← 正文正本
  data/ledger.json  data/runs.json                   ← 台账与跑批记录
out/backups/                                         ← 打包的正本备份
```

**文件名保持 uuid**:那是站方发的唯一身份,标题会被编辑改、会带上「Updated」。
分年月只是为了几千篇之后 Finder 里还翻得动 —— 分层是给人看的,身份仍然只由
uuid 决定。读不到时间的归到 `p/undated/`,不拿抓取时间凑一个月份。

`data/` 整个不发布(见下)。老布局(全平铺在根上)升上来的,程序会自己把
台账/存档/跑批记录搬进 `data/`;根上那些老页面用一次

```bash
bash tools/tidy_layout.sh     # 先从存档重画,再删掉根上的孤儿页面
```

收拾干净。

## 台账

`out/FT.COM/data/ledger.json`。身份用 `article_id`(`/content/<uuid>`),**不用标题**——
标题会被编辑改、会带上「Updated」,uuid 一篇稿子从头到尾只有一个。

每轮只给新增取正文,所以每小时跑一次的成本随「新增了几篇」走,不随「命中了
几篇」走(后者每轮都是几百)。

## 时间硬地板

`browser` 之外还有一条不靠人记的边界:**2025-01-01 之前的一律不抓**
(`sites/ft.py` 的 `EARLIEST`)。`--since` 只能把窗口收得更窄,不能更宽。

写成代码而不是使用习惯,是因为 2026-08-21 站长少传了一次 `--since`,积压当场
从 276 涨到 1370 —— 一个「永远不做的事」只写在命令行习惯里,它总有一天不生效。

## 两条召回线

1. **关键词搜索** —— 45 个词,按语义分组(词表和分组都在 `inews/keywords.py`,
   数目以那份文件为准)。
2. **FT 分类页** —— `artificial-intelligence` / `technology` / `semiconductors` /
   `cyber-security`(四条路径 2026-08-21 站长在浏览器里逐个核对过)。这里是
   **编辑判定**的「这是 AI 稿」,关键词漏掉的(标题正文都不含我们的词、但确实
   是 AI 报道)只能从这里进来。同域名,不扩大「能读谁」。

**哪条路更值,由数据说。** 每轮给每条线记一笔账:开了几页(成本)、命中几篇、
入库新增几篇(价值),写进 `runs.json`;dashboard 上按「每页新增」排成一张累计表。
「站内搜索比分类页高效」目前是个**猜想**,不是判据 —— 攒几周再回头看真账。
归属按「本轮谁先看见」算,有顺序偏向,看表时要记着。

两条线按 `article_id` 合并去重。专题页**不进凑数判据的计票**:那条判据按
「搜过几个语义组」算,把非搜索的一条线算进去会悄悄改变阈值。

## 正文存档

`out/FT.COM/data/articles/<uuid>.json` —— **正文文本的正本**。页面是产物,存档是原料:

```bash
.venv/bin/inews --render-only    # 不出网,从存档把整站重画一遍
.venv/bin/inews --refill --limit 0   # 台账说取到过、存档里没有的,重新取回来
bash tools/backup.sh                  # 打包存档 + 台账,留最近 14 份
```

**「产物随时能重画」只在有正本的时候成立。** 2026-08-22 整理目录时,存档机制
上线之前爬的 23 篇被当成产物删掉了 —— 那批的正文只存在于渲染好的 HTML 里,
重画画不出来。现在两头都堵上了:`tidy_layout.sh` 不删存档里没有正本的页面,
清单页对本地没有的那几篇**不给链接**(挂「无本地页」,只留 FT 原文的外链),
`--refill` 负责把缺的正本重新取回来。

只有 HTML 的时候,换版式要重爬、做分析要倒着从标签里抠文本。2026-08-21 为了看
新版式重爬二十篇,就是这个缺口的成本。

发布时**不上传** `data/` —— 台账、跑批记录、正文存档全在里面,都是抓取的内部状态。

## 统一后台

`/rawarticle/dashboard/` 是各原文库共用的后台（仍在鉴权后）。第一屏是
**跨库指标条 +
图**:库内篇数 / 上轮新增 / 正文成功率 / 取正文失败 / 积压 / 还需轮次 / 已跑轮次 /
连续失败,底下是链路灯与每轮新增柱、正文状态堆叠条与入库按日、进度、
关键词×周热力图、召回来源累计账。

**关键词分析并进了这一页**:语义组、关键词、发布月份、正文状态、一篇命中几个词
五张分布表都在这里 —— 它们和链路、进度本来就是同一批稿子的结构性事实,分成两页
只是让人在两个标签之间来回找同一个答案。

**能画成图的不写成句子,能收起来的不摊在第一屏。** 全部标题(✓/✗/○,失败带
服务端原话)和本轮记录都是「出事之后才翻」的,折起来;数字和图是「每次都扫
一眼」的,摊开。一屏塞满段落等于没有后台 —— 该被看见的那一条会淹在里面。`runs.json` 每轮记一条 —— **「新增 0」是常态,「连着三轮失败」不是**,
从页面上两者长得一模一样,只有记下来才分得开。

## 累积库

清单页列的是**台账里全部爬过的**,不是本轮那几篇。每小时跑一轮时本轮通常只有
两三篇 —— 只列本轮的话,页面每小时清空一次,攒了几个月的库一次都不出现在
读者眼前。

正文页只给本轮新增的写:上一轮那些页面已经在盘上,重写要么得重新出网取一次
正文,要么就是拿空正文把它盖掉。所以台账(`ledger.json`)v2 多记了关键词与
分区 —— 它要能**独自重画一行清单**。

取正文失败时,**原话进台账、也进日志**。想知道「这批失败是不是同一个原因」:

```bash
inews --retry-failed          # 不搜索:先按原因把失败归类报出来,再重试一遍
```

后台页上也有一张「取正文失败 · 原因」表。归类判据是 `fetch.py` 自己生成的固定
措辞(付费墙拦截页 / 正文提取过短 / 浏览器兜底也失败 …),归不进去的进「其他」
并原样保留 —— **不硬塞**。

## 两个入口,一套登录

`inews.today`(时间线)和 `inews.today/rawarticle/ft/`(这份产出)在 infra 的
Caddyfile 里属于**同一个站点块**、过**同一个** `forward_auth accounts:9000` ——
一个账号进两处,不需要第二套登录。**导航是同一条**:时间线 / 清单 / 后台并排成一条 tab 栏,在哪一页看到的都一样 ——
一个 repo,一个项目。

## 每小时自动跑一轮

```bash
bash tools/hourly.sh          # 抓一轮 + 发布,带锁和日志
```

**想自己点一下就跑**:双击 `tools/抓一轮.command`(可以拖到 Dock 或桌面)。
它跑的就是 `hourly.sh` 那一轮 —— 同一把锁、同一份日志、同样不重试;失败会留在
窗口里并给非零退出码,不会一闪而过。

清单页上的**「抓一轮」按钮按下去,这台机器上真的会跑一轮**。做法是本机常驻一个
监听:

```bash
inews --serve       # 只绑 127.0.0.1,只认代码里写死的动作表
```

页面按钮敲的就是它,由它启动 `tools/hourly.sh`。**监听没开时按钮不会假装成功** ——
那时它退回到把 `bash tools/hourly.sh` 复制到剪贴板,并把浏览器的原话留在按钮上。
边界写在 `inews/serve.py` 开头:只绑回环、只认固定动作表、只认放行表里的来源、
不接受任何参数(跑什么、翻几页、发不发布,网页那边一个字都改不了)。

清单页**分页**:每页 25 / 50 / 100 / 全部,默认 50,选择记在浏览器本地。分页在
浏览器里做,**全部行仍然都在 HTML 里** —— 否则筛选就会变成「只在这 50 条里筛」,
而那看起来和「库里就这么多」一模一样。

清单页顶上三条带:**原文库**(篇数、覆盖区间、话题、正文字数、正文取到/失败的
覆盖条)、**本轮**(命中、新增、取正文、失败、积压)、**最近 5 轮**(每轮的时间、
新增柱、命中、失败原话)。定时静默停摆时页面本身是不变的,只有「距上一轮」那个
数字不再变小 —— 那句话就得写在每天真会看的那一页上。

后台页(`dashboard.html`)除了数字,还画了**架构图**(一轮走过的六步,每格对应
仓库里的一个文件)和**抓取逻辑**(固定日历错峰、每轮只翻第 1 页、新增不设上限、
失败不回落、失败留原话、读不到时间就写「时间未知」)。图上的档位、域名、时间地板
都从代码里取 —— 手抄的那份迟早和代码分叉,而分叉的文档比没有文档更坏。

**每轮只翻第 1 页。** 搜索页按时间倒序,上次运行以来的新稿仍在第 1 页。翻到第 5
页是在挖历史,而历史只需要挖一次:

```bash
inews --group all --pages 20 --limit 0    # 手敲一次,挖历史
```

时间地板 `sites/ft.py::EARLIEST`(2025-01-01)兜着,翻多少页都过不去;`--since`
只能把窗口收得更窄。

锁用 `mkdir` 而不是 `flock` —— **flock 是 Linux 的命令,macOS 上不存在**。
2026-08-21 站长在 Mac 上跑了四轮,每轮都因为取锁「失败」而静默跳过,日志里只有
一行「跳过」、退出码 0。一个定时任务静默地什么都不做,是这个项目最坏的失败形态。

现在有两层锁：逐站锁防同一个库重入；资源组锁把需要可见 Chrome 的正文来源并发
限制为 1，把 CNBC 的公开/无头通道限制为 1。两个资源组可以并行，但统一后台
使用原子文件替换，发布时再单独串行。资源忙最多有界等待 10 分钟；仍忙就以临时失败
退出，下一次定时轮从专题第一页补上，不让异常长轮把多个浏览器任务堆满机器。

装成 launchd 定时任务(macOS,用户级):

```bash
bash tools/install_hourly.sh   # 全部正文来源固定错峰 + 本机按钮监听
```

plist 里必须写绝对路径(launchd 不认 `~` 和环境变量),手抄那条路径抄错的后果
不是报错,是任务指向一个不存在的目录然后**静默地什么都不做** —— 所以由脚本填。
装完它会**回读一次** `launchctl print`:bootstrap 的退出码只说「收下了」。
正文任务统一使用 `StartCalendarInterval`：FT 每小时 `:05`、Bloomberg 每小时 `:20`、
CNBC 每小时 `:27`、WSJ 每小时 `:50`；Reuters 在奇数小时 `:35`、Axios 在偶数小时
`:35`，两站各每 2 小时运行一次。这样每个日历事件至少相隔 7 分钟，可见 Chrome
始终相隔 15 分钟。它们没有 `RunAtLoad`，所以安装、登录或重装不会多站立刻齐跑；
本机按钮监听仍是 `RunAtLoad + KeepAlive`。Mac mini 正常不自动睡眠；如果人工休眠
或重启，launchd 会把每个站错过的日历事件合并补一次，资源组锁负责挡住集中启动。

时刻表唯一正本是 `inews/schedule.py`。它同时记录站点、LaunchAgent label、分钟和
资源类型；安装器由它生成 plist。以后新增 `inews.sites.REGISTRY` 成员却没安排自动
时段，或两个站撞分钟/资源间距不足，校验会直接失败，不会静默漏装。

卸掉:`launchctl bootout gui/$(id -u)/today.inews.collector.hourly`。
完整状态可用 `launchctl print gui/$(id -u)/today.inews.collector.hourly` 回读。

`manual` 档仍是有头、可见的浏览器通道；本次明确授权这些来源定时运行。自动任务
强制使用带哨兵页的专用 Chrome 窗口，不切换站长正在浏览的窗口；要改成无头仍须
先有实测证据，不能因一次失败偷偷回落或换档。

抓取失败(退出码非 0)不发布:宁可服务器上停在上一轮的样子,也不要拿一份可疑的
产出盖掉它。

## 发布到 inews.today/rawarticle/ft

产出是一堆静态 HTML(`index.html` / `dashboard.html` / 每篇一页 / 共用的 `site.css`),
双击本地文件就能看,也可以原样挂到服务器上:

```bash
bash tools/publish.sh        # rsync out/FT.COM → 服务器 /srv/rawarticle/ft
                             # 默认走 ssh 别名 inews;别的机器用 RAW_HOST=... 覆盖
```

**不走 git。** 其它站都是「push 到 GitHub → autopull 拉取」,但正文来自站长个人
订阅,不能进公开仓库 —— 内容只存在于自己的机器和服务器上那个只读目录,仓库里
只有生成它的代码。

服务器侧在 [infra](https://github.com/niuroumiantt/infra) 仓库定义:
`inresearch-host/Caddyfile` 里 inews.today 站点块下的 `@raw` 段(Caddy 直接读文件,
不进任何容器),加 compose 里 `/srv/rawarticle` 的只读挂载。这段**留在 inews.today
的站点块里**,和其它路径一样先过 `forward_auth` —— 能读的人只能是登录用户,
不是整个互联网。

## 开发

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
bash tools/precommit.sh      # 提交前必跑;跑子集不算
```

`tools/guard_standalone.py` 守着两件事:不许 import 母项目、不许把 cookie 提交
进仓库。这份代码是从一个更大的项目里抽出来的——抽出来容易,保持抽出来难,
所以要有一条会红的检查,而不是靠自觉。
