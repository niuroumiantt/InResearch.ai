# 本地精读打分流水线 — 项目目标与计划（datacenter-reader）

> 背景：研报库本体（docs/library/，17,843 份 / 88.6GB）只在本机，云端会话读不到 PDF 原文。
> 因此在本地新起一个独立小项目 **datacenter-reader**，用本地模型逐份读取→打分→重命名归类→写
> summary→产出消化草稿；产出物全部是**可进 git 的文本**，云端会话（主项目）负责合并进
> LIBRARY_SCORES.csv 与知识层。两边通过 git 交接，互不阻塞。

## 一、项目目标（成功标准）

1. **全库触达**：17,843 份材料 100% 被分诊；其中值得精读的（预计 5-10%）100% 打分登记。
2. **每份产出四件套**：新文件名（命名规范）/ 分类目录 / 打分行（CSV）/ summary（≥200 字、含可落库数字）。
3. **高分材料（importance≥8）额外产出消化草稿**：按 Finding 格式（结论/论证/证据/口径提醒）写初稿，云端精修入库。
4. **防幻觉硬约束**：summary 里的每个数字必须能在 PDF 提取文本中原文找到；找不到的标 `[未核]`。
5. **可审计**：主会话抽样 5% 双评，分差 ≥2 的批次整批复核。

## 二、打分标准

**完全沿用主项目 `framework/04_reading_scoring_standard.md`（标准 v2）**：
importance 1-9 由七维度定（独占性/可考性/落库密度/时效半衰期/缺口匹配/证据升级潜力/反面价值），
confidence A-C，跨模块杠杆 +1，命中 M14 +1。分数锚点与命名规范以该文档为准，本项目不另立标准。

## 三、分诊分层（Phase 0 已由云端完成初版）

按"单位阅读时间的期望价值"分四层，**从 T1 开始，逐层向下**：

| 层 | 目录 | 份数 | 策略 |
|---|---|---|---|
| **T1 立即精读** | 04/SemiAnalysis合集（242 份）、04/英文机构报告（130 份）、04/半导体与上游（300 份） | ~670 | 逐份精读打分，预期 7-9 分密集区 |
| **T2 抽样后决定** | 04/AI与算力（3,858 份）、05_数据中心设施（251 份）、03_云计算（36 份）、02_制冷与供配电（13 份） | ~4,160 | 每目录抽 10 份定目录基准分，高于 6 才逐份读 |
| **T3 目录级批处理** | 04/中文行业报告集（10,772 份） | ~10,800 | 按机构/年份元数据批量粗筛，2023 前的市场类直接 3-4 分存档，只捞独家渠道数据 |
| **T4 一次性登记** | 01_标准与规范、06_工程图纸、07_方案与模板、08_培训课件 | ~2,140 | 参考资料型：目录级打分（多为 4-5 分），不逐份；爆炸图素材单列给产品线用 |

优先在 T1/T2 中优先命中：**M10（运营/总包/劳动力）、M13（利用率/调度）、M14（中国渠道数据）、
M05（选址）**——这四个模块是当前知识层最薄弱、缺口匹配度维度给分最高的方向。

## 四、阶段计划

- **P0 环境**（半天）：装文本提取（pdftotext/PyMuPDF 均可）；跑通单份"提取→打分→产出"链路。
- **P1 T1 层**（第 1-2 周）：670 份精读打分；每天产出一个批次文件回传 git。
- **P2 T2 抽样 + 高分目录展开**（第 3-4 周）。
- **P3 T3 批量粗筛**（第 5-6 周）：机械规则先筛掉 70%，剩余走模型。
- **P4 T4 登记收尾**（第 7 周）；全库触达率 100%，出终版统计报告。

## 五、与主项目的交接契约（重要）

本地项目**不直接改** LIBRARY_SCORES.csv 与 research/，只产出**批次文件**放入主仓库：

```
docs/inbox/scored_batches/batch_YYYYMMDD_NN.csv   # 与 LIBRARY_SCORES.csv 同列结构
docs/inbox/digest_drafts/{score}{conf}_{主题}_{机构}.md  # importance≥8 的消化草稿
```

云端会话（或主会话）负责：抽样审计 → 合并进 LIBRARY_SCORES.csv → 重建索引
（build_library_index.py）→ 按草稿修订知识层 → commit。**单一写入方原则，避免两边改同一文件冲突。**

重命名/移动文件在本地库直接执行（library 不进 git，无冲突风险），但每个批次 CSV 必须
同时含 old_name 与 new_path，保证可回溯。

## 六、风险与对策

- **本地模型幻觉数字** → 硬约束第 4 条 + 抽样双评；宁可 `[未核]` 也不编。
- **T3 一万份中文报告淹没进度** → 机械规则（年份/机构/标题关键词）先筛，模型只看幸存者。
- **打分漂移**（批次间标准不一致）→ 每批开头先重打 3 份已定标样板（9A/8A/5B 各一）做校准，
  偏差 ≥2 即停下重对标准。
- **重命名破坏本地引用** → 已消化文献的 local_file 路径变更须同批次回传，云端同步改 sources.json。
