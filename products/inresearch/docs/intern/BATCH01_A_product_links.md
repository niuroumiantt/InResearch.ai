# 工单 BATCH01-A：产品官方资料链接补全

你好，欢迎加入。这是你的第一张工单，选它是因为它能让你在两周内把我们研究的
数据中心供应链**从头到尾过一遍**——451 个型号、175 条产品线、从 GPU 到柴油发电机。
做完这单，你对这个行业的产品版图会比大多数从业者都熟。

## 任务

`data/product_docs_plan.csv` 有 801 行采集计划，`source_url` 列目前全部为空。
你的活：**逐行找到官方文档直链，填进去。**

- `doc_type = DS`（451 行）：找该型号的官方 datasheet（PDF 优先）；
- `doc_type = BR`（175 行）：找该产品线的官方 brochure/白皮书；
- `doc_type = WEB`（175 行）：找该产品线的官方产品页 URL。

`referrer_page` 列已给出厂商官网入口，从那里进 support/download/products 页找。

## 规矩（三条，违反任何一条这行就作废）

1. **只填官方域名的链接**——厂商自己的网站或其官方文档中心。第三方转载站、
   数据表聚合站（datasheetspdf 之类）一律不算。
2. **不许猜链接**。拼一个看起来像的 URL 填进去，比留空糟糕十倍。
3. **找不到就留空**，在 `note` 列写明原因，用这几个词之一：
   `需注册`（要厂商账号才能下）/ `无公开文档`（官网确实没有）/ `已下架`（型号停产页面移除）/
   `仅中文`或`仅英文`（语言受限，链接照填，note 说明）。
   写「找不到」不扣分——**编一个链接才是事故**。

## 交付

- 每完成约 100 行交付一次：改好的 CSV 放到 `docs/inbox/submissions/你的名字_日期/`，
  附一行说明（做了哪些行、多少填上、多少留空、留空主因）。
- 顺手记录：哪家厂商的文档中心最难用、哪些型号官网根本查无此物——这些观察本身就有研究价值。

## 参考

- 行数分布：`sheet` 列就是供应链环节，建议按环节整段做（同一厂商的行集中处理，效率高一倍）。
- 你填的链接会被 `pipeline/product_library.py` 自动抓取，抓下来的文件先进暂存区，
  人看过才入库——所以链接错了会被发现，但会浪费一轮抓取，尽量一次填对。

有任何规则不清楚的地方，先问再做，问不扣分。谢谢你，期待你的第一批交付。
